## Состояние проекта

Совместная онлайн-доска (аналог Miro). Сейчас в репозитории только проектные документы, кода приложения ещё нет:

- `REQUIREMENTS.md` — функциональные требования с идентификаторами (ADM-*, ACC-*, BRD-*, SHR-*, CVS-*, MOB-*, COL-*, BAK-* и др.). Поведение продукта берётся отсюда.
- `ARCHITECTURE.md` — целевая архитектура первой версии. Устройство системы берётся отсюда.
- `.cursor/rules/*.mdc` — всегда действующие правила разработки и тестирования (кратко изложены ниже).

Возможности за рамками этих документов не добавляются. В коде указывайте идентификаторы требований, которые он закрывает; архитектура сопоставляет группы требований с серверными модулями.

## Планируемая структура и стек

```text
apps/web          TypeScript, React, Vite — одно SPA, строки интерфейса по-английски прямо в компонентах (без слоя перевода)
apps/api          Python 3.12, FastAPI — один процесс, миграции Alembic (только вперёд)
deploy/compose    Docker Compose (caddy, web, api, postgres), Caddyfile, переменные окружения
```

Серверные модули (код модуля лежит в этом модуле): `identity`, `library`, `sharing`, `realtime`, `history`, `media`, `backup`.

## Правила тестирования (из `.cursor/rules/tests.mdc`)

Модуль не готов, пока тесты не покрывают его наблюдаемое поведение и не проходят. Тесты пишутся в том же изменении, что и код; перед завершением задачи запускаются тесты затронутых модулей.

- Сервер: pytest, один файл на модуль — `apps/api/tests/test_<module>.py` (например, `test_sharing.py`). Один тест: `pytest apps/api/tests/test_sharing.py::test_name`.
- Клиент: Vitest, файлы `*.test.ts` / `*.test.tsx` рядом с модулем.
- Проверяется поведение из требования (например, «старый токен после сброса отвечает 404»), а не факт вызова внутренней функции.

## Ключевые архитектурные решения

- **Содержимое доски — документ Yjs** (клиент `yjs`, сервер `pycrdt`). Верхний уровень: `objects` (Y.Map id → объект сцены, JSON с дискриминатором `type`, координаты дочерних объектов относительно родителя, целое поле `z` для порядка слоёв), `trash`, `comments`, `timer`, `votes`, `notes` (Y.XmlFragment). Метаданные списка (название, папка, обложка, избранное, токены) хранятся в PostgreSQL и в документ не входят.
- **Сервер не интерпретирует жесты**: проверяет право на доску, применяет обновление `sync` к своей копии, дописывает его в `board_updates` и только потом рассылает. Повреждённое обновление закрывает лишь это соединение. Фоновые задачи периодически пишут снимки в `board_snapshots` и отрезают журнал.
- **Присутствие, курсоры, лазерная указка, «смотреть глазами участника»** идут отдельными сообщениями WebSocket `awareness`/`presence` и никогда не попадают в документ, снимки и резервные копии.
- **Один процесс держит все соединения** в памяти; в первой версии нет Redis, шины сообщений и нескольких копий API.
- **Отрисовка**: объекты сцены — DOM-элементы в слое с CSS-преобразованием камеры; редактирование текста — обычные поля ввода браузера. Движка на WebGL/Canvas в первой версии нет.
- **Отмена/повтор**: локальный Yjs UndoManager — только правки этого клиента.
- **Экспорт** (PNG/JPEG/SVG/PDF) собирает браузер; сервер доску не рендерит. **Резервная копия** — ZIP, собираемый сервером (`manifest.json`, `board.yjs`, `media/`); восстановление создаёт новую доску и отклоняет чужую версию формата.
- **HTTP-контракты** — схемы Pydantic, публикуемые как OpenAPI; типы для интерфейса генерируются из схемы. Сообщения WebSocket описаны рядом с серверным кодом и продублированы узким TS-модулем в `apps/web` (общего пакета на два языка нет).

## Модель доступа

- Учётные записи создаёт только администратор (первый создаётся при пустой базе из `ADMIN_EMAIL`/`ADMIN_PASSWORD`). Самостоятельной регистрации нет.
- Участник без учётки входит по ссылке «все, у кого есть ссылка» — `/b/{token}`: токен — 32 случайных байта в URL-безопасной кодировке; участник вводит имя, оно хранится в сессионной cookie этой доски, учётная запись не создаётся. На холсте у участника те же права, что у владельца.
- У доски одна действующая ссылка; сброс сразу отзывает старый токен и его сессии. Отозванная или несуществующая ссылка получает отказ без раскрытия, существует ли доска. Ошибки входа и ссылки сформулированы одинаково скупо.
- Сессия: случайный идентификатор в cookie `HttpOnly`, `SameSite=Lax`; `Secure` — только если `PUBLIC_BASE_URL` начинается с `https://`. Пароли — Argon2id.
- Во фрейме можно открыть только `/b/{token}/embed`; остальные страницы показ во фрейме запрещают.
- Файлы отдаются по `/api/media/{id}` только при сессии этой доски; хранятся в `MEDIA_ROOT/{board_id}/{media_id}`, размер ограничен `MAX_UPLOAD_BYTES`.

## Локальная разработка

- Весь стек запускается в Docker Compose на машине разработчика; Caddy слушает порт 80 на `0.0.0.0`, чтобы доску открывали с телефона в локальной сети.
- `PUBLIC_BASE_URL` — `http://<IP машины в локальной сети>` (например, `http://192.168.1.20`); из него собираются ссылки на доски.
- **Никогда не вписывайте `localhost`** для API и WebSocket в клиенте; адреса строятся из адреса страницы (`/api`, `/api/ws`).
- Обязательные переменные (без них процесс не стартует): `PUBLIC_BASE_URL`, `SECRET_KEY`, `DATABASE_URL`, `MEDIA_ROOT`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `MAX_UPLOAD_BYTES`. `SITE_DOMAIN` — только для публичного профиля с HTTPS.
