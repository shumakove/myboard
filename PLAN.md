# План реализации

План разбивает [REQUIREMENTS.md](REQUIREMENTS.md) на задачи по [ARCHITECTURE.md](ARCHITECTURE.md). Каждая задача состоит из двух частей:

- **Разработка (DEV)** — что реализует агент-разработчик вместе с модульными тестами (`apps/api/tests/test_<module>.py`, `*.test.ts(x)`).
- **Тестирование (QA)** — какие приёмочные сценарии агент-тестировщик независимо проверяет через HTTP, WebSocket и браузер (`acceptance/`).
- **UML (DEV, после приёмки)** — у каждой задачи, без отдельного блока: когда QA принял задачу (`ACCEPTED`), DEV обновляет схемы в `uml/` по принятой реализации и только после этого ставит `DONE`. Какие схемы затрагивает задача — по таблице в [uml/README.md](uml/README.md).

Передача задач между агентами, статусы и шаблоны — в [WORKFLOW.md](WORKFLOW.md).

Статусы: `TODO`, `IN_DEV`, `READY_FOR_QA`, `IN_QA`, `REJECTED`, `BLOCKED`, `ACCEPTED` (принято QA, код в `main`), `DONE` (UML обновлён). Зависимость выполнена, когда задача в `ACCEPTED` или `DONE`.

## Фаза 0. Основа

### T0.1 · Стек Docker Compose

**Разработка**
- `deploy/compose`: сервисы `caddy`, `web`, `api`, `postgres`, тома для PostgreSQL и `MEDIA_ROOT`.
- Caddy слушает `0.0.0.0:80`, отдаёт статику `web`, проксирует `/api` и `/api/ws` в `api`.
- `.env.example` со всеми обязательными переменными; `PUBLIC_BASE_URL=http://<IP в LAN>`.
- Порт Caddy задаётся переменной `HTTP_PORT` (по умолчанию 80), чтобы стеки DEV (`-p myboard-dev`, 8080) и QA (`-p myboard-qa`, 80) работали одновременно.
- Заголовки против показа во фрейме для всех путей, кроме `/b/{token}/embed`.

**Тестирование**
- `docker compose up` на пустых томах поднимает все четыре сервиса; страница открывается по `PUBLIC_BASE_URL` с другого устройства в сети.
- `/api/...` и WebSocket `/api/ws` доходят до API через Caddy.
- Любая страница, кроме `/b/{token}/embed`, отдаёт запрет показа во фрейме.

### T0.2 · Каркас API

**Разработка**
- FastAPI-приложение, модули `identity`, `library`, `sharing`, `realtime`, `history`, `media`, `backup` (пустые роутеры).
- Настройки: процесс не стартует без любой из переменных `PUBLIC_BASE_URL`, `SECRET_KEY`, `DATABASE_URL`, `MEDIA_ROOT`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `MAX_UPLOAD_BYTES`.
- SQLAlchemy + Alembic (миграции только вперёд), схема таблиц из раздела 7 архитектуры по мере надобности.
- Публикация OpenAPI; фикстуры pytest (тестовая БД, клиент).
- `uv` и `pyproject.toml`; `ruff` (lint + format) и `mypy --strict` настроены и зелёные.

**Тестирование**
- Запуск без каждой обязательной переменной по очереди завершается ошибкой с именем переменной.
- Миграции применяются на пустой базе до приёма трафика.
- `/api/openapi.json` доступен.

### T0.3 · Каркас интерфейса

**Разработка**
- Vite + React + TypeScript, маршрутизатор с путями из раздела 4 архитектуры (заглушки страниц).
- Генерация типов из OpenAPI; HTTP-клиент на `/api`, адрес WebSocket собирается из `location` (без `localhost`).
- `pnpm`; Vitest, `tsc --noEmit` в строгом режиме, ESLint и Prettier настроены и зелёные.

**Тестирование**
- Все маршруты из раздела 4 открываются без ошибок в консоли.
- В собранной статике нет строки `localhost` в адресах API и WebSocket.

### Q0.1 · Приёмочный стенд (задача QA)

- `acceptance/api`: pytest + httpx + клиент WebSocket, фикстуры «чистый стек», «админ», «пользователь досок», «доска», «участник по ссылке».
- `acceptance/e2e`: Playwright, профили `desktop` и `mobile` (ширина телефона, `hasTouch`), базовый адрес из `PUBLIC_BASE_URL`.
- Хелпер двух независимых клиентов для проверок совместной работы.
- `docs/qa/traceability.md` со всеми ID из REQUIREMENTS.md в статусе «не проверено», каталог `docs/qa/reports/`.
- Задачу ведёт QA сам: `TODO → IN_QA → DONE`, без передачи DEV.

## Фаза 1. Учётные записи (`identity`)

### T1.1 · Администратор и учётные записи — ADM-01…07

**Разработка**
- Создание первого администратора из `ADMIN_EMAIL`/`ADMIN_PASSWORD` при пустой таблице `admins`.
- Пароли Argon2id, сессия — случайный id в cookie `HttpOnly`, `SameSite=Lax`, `Secure` только при `https://` в `PUBLIC_BASE_URL`.
- API и страницы `/admin/login`, `/admin/users`: список, создание, изменение имени/почты/пароля, отключение, включение.
- Уникальность почты ограничением БД; ограничение частоты попыток входа с одного адреса.

**Тестирование**
- ADM-01: вход администратора; пользователь досок в панель не входит.
- ADM-02…04: созданная и изменённая учётка видна в списке; новый пароль работает, старый — нет.
- ADM-05: отключённый пользователь не входит, его доски остаются (проверяется после T2.1 — вернуться в регрессии).
- ADM-06: после включения вход снова работает.
- ADM-07: вторая учётка с той же почтой (в т.ч. при изменении почты существующей) отклоняется.
- Cookie без `Secure` на `http://`, с `HttpOnly`; `document.cookie` её не видит.

### T1.2 · Вход пользователя досок — ACC-01…03

**Разработка**
- `/login`, выход, бессрочная сессия до выхода.
- Одинаково скупое сообщение для неверной почты, неверного пароля и отключённой учётки.

**Тестирование**
- ACC-01: вход с данными, заданными администратором.
- ACC-02: три случая отказа дают одинаковый ответ (текст и код) — перебор почт невозможен; частые попытки ограничиваются.
- ACC-03: после закрытия и открытия браузера (сохранённое состояние) пользователь остаётся в системе; после выхода — нет.

## Фаза 2. Список досок (`library`)

### T2.1 · Список досок — ACC-04, BRD-01…06

**Разработка**
- Таблица `boards`; создание (с мгновенным переходом на `/boards/{id}`), переименование, удаление (`deleted_at`).
- Главная `/`: недавние (по `updated_at`) и полный список; сортировка, фильтры, поиск по названию на сервере.
- Все запросы ограничены владельцем.

**Тестирование**
- ACC-04: после входа виден список досок именно этого пользователя.
- BRD-01…03: создание открывает доску и добавляет её в список; переименование и удаление отражаются в списке.
- BRD-04: недавние упорядочены по последнему изменению.
- BRD-05, BRD-06: сортировка, фильтр, поиск по части названия.
- Изоляция: пользователь B не видит и не открывает доски пользователя A по id (ни в списке, ни прямым запросом).

### T2.2 · Папки и избранное — BRD-07, BRD-09…11

**Разработка**
- `folders` с вложенностью и `position`, `favorites` для досок и папок.
- Боковой список: свернуть/развернуть, перетаскивание для порядка, вложения и переноса досок.
- Поиск BRD-06 расширяется на папки.

**Тестирование**
- BRD-07: доска и папка добавляются в избранное и убираются.
- BRD-09: папка в папке в папке.
- BRD-10: перетаскиванием меняется порядок, папка вкладывается, доска переносится; порядок сохраняется после перезагрузки.
- BRD-11: сворачивание папок.
- BRD-06: поиск находит папку.
- Запрет циклов: папку нельзя вложить в собственную дочернюю.

## Фаза 3. Ссылка (`sharing`)

### T3.1 · Ссылка на доску и вход по ссылке — SHR-01…03, SHR-05, SHR-06

**Разработка**
- Токен 32 случайных байта (URL-safe), одна действующая ссылка на доску, сброс с отзывом старого токена и его сессий.
- Диалог Share в интерфейсе: показать, скопировать, сбросить ссылку.
- `/b/{token}`: запрос имени → сессионная cookie этой доски, учётка не создаётся.
- Одинаковый отказ для отозванного и несуществующего токена.
- `/b/{token}/embed` разрешает показ во фрейме.

**Тестирование**
- SHR-01: владелец видит и копирует ссылку, адрес собран из `PUBLIC_BASE_URL`.
- SHR-02, SHR-03: браузер без учётки по ссылке запрашивает имя и попадает на доску; учётка не появляется в панели администратора.
- SHR-05: `/boards/{id}` без сессии владельца не открывается; несуществующий и отозванный токены дают неразличимый отказ.
- SHR-06: после сброса старая ссылка и уже выданная по ней cookie доступа не дают (HTTP и WebSocket), новая работает.
- Участник по ссылке не видит список досок `/` и не получает доступ к другим доскам владельца.

## Фаза 4. Совместная работа: ядро (`realtime`, `history`)

### T4.1 · Синхронизация документа — COL-01, канал для SHR-04

**Разработка**
- WebSocket `/api/ws` с проверкой сессии владельца или участника по ссылке.
- Сообщение `sync`: вектор версии, обновления, полный снимок; сервер (pycrdt) применяет обновление к своей копии, пишет в `board_updates`, затем рассылает.
- Повреждённое обновление закрывает только это соединение.
- Обновление `boards.updated_at` при принятой правке.
- Клиент: `yjs`-провайдер, структура документа (`objects`, `trash`, `comments`, `timer`, `votes`, `notes`), переподключение с досылкой локальных правок.
- TS-модуль с типами сообщений WebSocket в `apps/web`.

**Тестирование**
- COL-01: два клиента одновременно меняют один объект и один текст — оба видят объединённый результат, блокировок нет.
- Поздно подключившийся клиент получает текущее состояние.
- Повреждённое обновление: отправитель отключён, у остальных документ не изменился.
- Сессия без права на доску и отозванная ссылка не открывают WebSocket.
- Разрыв сети у клиента: локальные правки доезжают после переподключения.

### T4.2 · Присутствие и курсоры — COL-02, COL-03, COL-04, COL-09

**Разработка**
- Сообщения `awareness` (курсор, имя, выделение, слежение, лазер) и `presence`; в документ не пишутся.
- Интерфейс: курсоры с именами, переключатель скрытия, режим «смотреть глазами участника», список присутствующих.

**Тестирование**
- COL-02, COL-09: второй клиент видит курсор и имя первого и его в списке присутствующих; после отключения — пропадает.
- COL-03: курсоры скрываются и снова показываются.
- COL-04: при слежении камера наблюдателя повторяет перемещения; выключение останавливает.
- Данные присутствия отсутствуют в документе (проверка через снимок после T4.3).

### T4.3 · Журнал, снимки, корзина — основа COL-07, COL-08

**Разработка**
- Фоновая задача: периодический снимок в `board_snapshots`, отрезание журнала.
- При подключении — недостающие обновления или снимок, если журнал сжат.
- Удаление объекта переносит его в `trash`; запись в `board_events`.

**Тестирование**
- После сжатия журнала новый клиент получает полное и корректное состояние.
- Перезапуск контейнера `api` не теряет содержимое доски.
- Удалённый объект оказывается в `trash` (проверка через WebSocket-клиент).

## Фаза 5. Холст

### T5.1 · Камера — CVS-01…05, MOB-02

**Тестирование**
- CVS-01: объект ставится на большом удалении от начала координат.
- CVS-02, CVS-03: все способы масштаба и сдвига; оба режима колеса.
- CVS-04: щелчок по миникарте переносит вид.

- MOB-02: мобильный профиль — сдвиг одним пальцем, щипок.

### T5.2 · Сцена, создание и выделение — CVS-06, CVS-09…14, CVS-21, CVS-23, MOB-03

**Разработка**
- Контракт инструмента; объект с `type`, `z`, координатами относительно родителя.
- Фон и шаг сетки; создание инструментом, перетаскиванием с панели, вставкой из буфера.
- Выделение: щелчок, рамка, лассо; фильтр по типу при смешанном выделении и массовое изменение свойств.
- Перемещение (Shift — по оси, модификатор — без прилипания), автопрокрутка у края, изменение размера и поворот.
- Удаление, контекстное меню объекта и холста; долгое нажатие на телефоне начинает выделение.

**Тестирование**
- По одному сценарию на каждое требование; результат видит второй клиент (объекты — общие).
- CVS-11: смешанное выделение → только стикеры → цвет меняется у всех.
- CVS-12: Shift фиксирует ось; модификатор отключает прилипание.
- MOB-03: короткое движение двигает холст, долгое нажатие выделяет.

### T5.3 · Операции над объектами — CVS-15…20, CVS-22

**Разработка**
- Выравнивание и распределение (включая жест за маркер рамки), направляющие.

- Блокировка и «разблокировать всё»; копирование/дублирование/вырезание/вставка, в том числе между досками пользователя.
- Автор и даты создания и изменения у объекта.

**Тестирование**
- CVS-15, CVS-16: равные промежутки после распределения; направляющие появляются у соседей.
- CVS-17, CVS-18: порядок слоёв внутри группы и у группы.
- CVS-19: заблокированный объект не двигается; «разблокировать всё» снимает блокировку со всех.
- CVS-20: вставка на другую доску того же пользователя сохраняет объекты.
- CVS-22: автор и даты корректны, в том числе для участника по ссылке (имя из сессии).

### T5.4 · Отмена, панель, горячие клавиши — CVS-07, CVS-24, CVS-25

**Разработка**
- Yjs UndoManager только для локальных правок.
- Закреплённые инструменты с порядком, полный список.
- Горячие клавиши основных инструментов и действий.

**Тестирование**
- CVS-07: Undo/Redo откатывает свои правки и не трогает правки второго клиента.
- CVS-24: закрепление и порядок сохраняются.
- CVS-25: каждое действие из требования вызывается клавишей.

### T5.5 · Поиск и ссылка на объект — CVS-08, SHR-07

**Разработка**
- Клиентский поиск по тексту объектов и тегам, переход к результату.
- «Copy link to object»: `/b/{token}?object={id}`; камера переходит к объекту после загрузки.

**Тестирование**
- CVS-08: находится объект по тексту и по тегу; вид переходит к нему.
- SHR-07: ссылка открывает доску на нужном объекте; с отозванным токеном — отказ.

## Фаза 6. Объекты доски

Общее для всех задач фазы: DEV — схема объекта в документе, компонент, панель свойств, модульные тесты схемы и логики; QA — каждое требование проверяется у владельца и у участника по ссылке, изменения видны второму клиенту, объект переживает перезагрузку.

### T6.1 · Текст и документ — TXT-01…08

**Разработка**: текстовый блок с оформлением; совместно редактируемый rich-text (Y.XmlFragment) со списками, заголовками, ссылками, чекбоксами; быстрая разметка (`#`, маркеры, `--` → `—`); меню `/`; запоминание размера и цвета в сессии; документ из блоков со ссылками на объекты; копирование во внешний редактор и вставка с форматированием.

**Тестирование**: каждое свойство TXT-01; чекбокс отмечается без полного режима редактирования (TXT-02); автозамена разметки (TXT-03); меню `/` в тексте и документе (TXT-04); новый блок наследует размер и цвет (TXT-05); ссылка из документа ведёт к объекту (TXT-06); буфер обмена в обе стороны с внешним редактором (TXT-07, TXT-08); два клиента пишут в один текст одновременно (COL-01).

### T6.2 · Стикеры — STK-01…05

**Разработка**: стикер с цветом (выбор до постановки, перетаскивание образца), ручной размер шрифта или автоподгон, теги и автор, Tab создаёт следующий, стопка стикеров.

**Тестирование**: сценарий на каждый STK; автоподгон уменьшает шрифт при длинном тексте; из стопки выходит стикер с её цветом и тегами.

### T6.3 · Фигуры и BPMN — SHP-01…04

**Разработка**: наборы базовых фигур, выносок, блок-схем и BPMN с маркерами; заливка, обводка, скругление, текст с интервалом; недавние цвета отдельно по типам объектов.

**Тестирование**: все наборы доступны; переключение маркеров BPMN; недавние цвета стикера не появляются в палитре линии (SHP-04).

### T6.4 · Соединительные линии — CON-01…07, CVS-26

**Разработка**: прямая, ломаная, кривая; наконечники и их отсутствие; смена направления; несколько подписей с позицией и ориентацией; Shift — произвольный угол; удаление точки двойным щелчком; привязка к точкам объектов и отвязка.

**Тестирование**: линия следует за перемещаемым объектом, пока привязана, и не следует после отвязки; сценарий на каждый CON.

### T6.5 · Рисование — DRW-01…06, MOB-04, MOB-05

**Разработка**: перо и маркер с цветом и толщиной, три пресета, ластик (не стирает заблокированное), прямой штрих с Shift, масштаб штриха; лазер через `awareness` с исчезновением; отсев ладони; режим «стилус сразу рисует».

**Тестирование**: DRW-03 — заблокированный штрих остаётся; DRW-05 — второй клиент видит лазер, через несколько секунд он исчезает, в документе и снимке его нет; MOB-04, MOB-05 — эмуляция касаний и стилуса в Playwright (`pointerType: 'pen'`/`'touch'`).

### T6.6 · Фреймы — FRM-01…05

**Разработка**: фрейм как родитель (координаты детей относительно него), линия к фрейму, оформление, фиксация пропорций, скрытие содержимого, выбор режима блокировки.

**Тестирование**: объект, перенесённый во фрейм, двигается вместе с ним; скрытие работает у заблокированного фрейма; при блокировке появляется выбор и оба варианта ведут себя по-разному.

### T6.7 · Таблицы — TBL-01…07

**Разработка**: таблица со строками/столбцами, размерами, форматированием, заливкой, объединением; навигация стрелками; ячейка как родитель объектов; обмен с внешней электронной таблицей; вставка как набор стикеров по выбору.

**Тестирование**: копирование в внешнюю таблицу и обратно сохраняет сетку данных; TBL-07 — выбор при вставке даёт стикеры.

### T6.8 · Канбан и карточки — KBN-01…03

**Разработка**: канбан со столбцами-родителями, карточки с текстом и тегами, перенос перетаскиванием, переименование/добавление/удаление столбца с выбором судьбы карточек.

**Тестирование**: удаление столбца — оба варианта судьбы карточек; перенос карточки виден второму клиенту.

### T6.9 · Интеллект-карты — MAP-01…04

**Разработка**: корень и дочерние узлы, операции с узлами, перестановка перетаскиванием, сворачивание веток, вопрос о перекраске потомков.

**Тестирование**: сценарий на каждый MAP; оба ответа на вопрос MAP-04.

### T6.10 · Комментарии — CMT-01…04

**Разработка**: ветки в `comments` с привязкой к объекту или точке, ответы, «решено», непрочитанные (локально для участника), цвет, фильтр по участникам.

**Тестирование**: комментарий следует за объектом; непрочитанные отмечаются у второго участника; фильтр по имени участника по ссылке.

### T6.11 · Реакции, флип-карточки, кубик — RCT-01…04, FLP-01…03, DICE-01…03

**Разработка**: реакция-штамп, привязанная к объекту, автор по наведению, рост при удержании, наборы и недавние; флип-карточка со сторонами, картинкой и направлением, переворот одной и группы; кубик с гранями 4–20, бросок, сумма выделенных.

**Тестирование**: реакция едет с объектом; кубик выдаёт значения только в диапазоне граней (много бросков); сумма нескольких кубиков верна; одновременный бросок с двух клиентов даёт согласованное значение у обоих.

### T6.12 · Заметка доски — NTE-01…03

**Разработка**: панель заметки на `notes` с блоками и меню `/` из T6.1, флаг «открывать всем», ссылки на объекты.

**Тестирование**: закреплённая заметка открыта у нового участника при входе; ссылка из заметки переносит вид.

## Фаза 7. Файлы (`media`)

### T7.1 · Модуль media и изображения — IMG-01…07

**Разработка**: загрузка в `MEDIA_ROOT/{board_id}/{media_id}`, проверка типа и `MAX_UPLOAD_BYTES`, выдача `/api/media/{id}` только сессии этой доски; объект изображения: вставка из буфера, обрезка, маска, скругление, обводка, отражение, замена с сохранением обрезки, удаление фона, GIF с воспроизведением по наведению при многих объектах, SVG.

**Тестирование**: файл больше лимита отклонён; `/api/media/{id}` без сессии и с сессией другой доски — отказ; после сброса ссылки старая cookie не получает файл; сценарий на каждый IMG.

### T7.2 · Файлы, PDF, видео, аудио — FIL-01…05

**Разработка**: ярлык файла с переименованием и скачиванием, PDF постранично с извлечением страниц, видеоплеер (mp4, m4v, mov, webm), аудио (mp3, m4a, wav, webm), воспроизведение только у запустившего.

**Тестирование**: каждый формат из списка воспроизводится; FIL-05 — запуск у одного клиента не запускает у второго; извлечённые страницы PDF — отдельные объекты.

### T7.3 · Встраивание и ссылки — EMB-01…04

**Разработка**: iframe-объект по коду с панели и из буфера, карточка ссылки с названием и изображением, ссылка у объекта с переходом к объекту этой доски, страница `/b/{token}/embed` с рабочим холстом.

**Тестирование**: EMB-02 — заблокированная карточка открывает адрес; EMB-04 — внешняя тестовая страница с iframe встраивает доску и правка из фрейма видна второму клиенту; прочие страницы во фрейме не открываются.

### T7.4 · Обложка доски — BRD-08

**Разработка**: загрузка изображения обложки, рендер фрейма в изображение на клиенте и загрузка как `media`, 16:9.

**Тестирование**: обе ветки задания обложки; обложка видна в списке досок.

## Фаза 8. Совместная работа: дополнения

### T8.1 · Таймер и голосование — COL-05, COL-06

**Разработка**: общий таймер в `timer` с памятью последнего запуска; голосование по области и объектам в `votes` с ходом голосов.

**Тестирование**: копирование из снимка не откатывает остальную доску; восстановление к снимку видят все подключённые клиенты; удалённый объект возвращается из ленты; в ленте имя участника по ссылке.

### T9.1 · Шаблоны — BRD-12…15

## Фаза 10. Резервная копия и экспорт

### T10.1 · Резервная копия — BAK-01, BAK-02, BAK-06, KBN-04

**Разработка**: модуль `backup` — ZIP (`manifest.json`, `board.yjs`, `media/`), скачивание владельцем и участником по ссылке; восстановление только пользователем досок в новую доску с новыми id файлов; отказ для чужой версии формата.

**Тестирование**: круговой тест «доска со всеми типами объектов → ZIP → восстановление» сохраняет объекты, теги стикеров и карточек (KBN-04, BAK-02), файлы; участник скачивает ZIP, но не может восстановить; ZIP с другой версией формата отклонён с понятной ошибкой; в ZIP нет данных присутствия.

### T10.2 · Экспорт — BAK-03…05, FRM-06

**Разработка**: клиентский экспорт всей доски или выделения в PNG, JPEG, SVG, PDF; PDF с выделяемым текстом и ссылками; фреймы постранично в порядке презентации; медиа как ссылка или кадр-заглушка.

**Тестирование**: файлы открываются и содержат ожидаемые объекты; в PDF текст находится поиском и ссылки кликабельны (проверка разбором PDF); порядок страниц совпадает с порядком фреймов; участник по ссылке экспортирует так же (BAK-06).
