# Технические решения DEV

Библиотеки и инструменты, не названные в `ARCHITECTURE.md`, и почему они выбраны.

## 2026-09-27 · T0.1 · Образы и конфигурация стека

- **Образы**: `caddy:2.10-alpine` (фронтовой прокси и сервер статики заглушки `web`), `postgres:16-alpine`, `python:3.12-slim` (заглушка `api`). Версии зафиксированы по минорной ветке, чтобы сборка на пустых томах была воспроизводимой. Альтернатива для статики — nginx; не выбран, чтобы в стеке был один веб-сервер с одним синтаксисом конфигурации.
- **Запрет фрейма**: Caddy ставит `X-Frame-Options: DENY` и `Content-Security-Policy: frame-ancestors 'none'` на все ответы, кроме пути `^/b/[^/]+/embed/?$`. Два заголовка — для старых и новых браузеров. Заголовки ставятся на прокси (`defer`), поэтому действуют и для статики, и для API, и ответ upstream их не перезаписывает.
- **Переменные**: обязательные переменные в `compose.yaml` заданы через `${VAR:?...}` — `docker compose` не запускает стек без любой из них. Для PostgreSQL добавлены `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`; `DATABASE_URL` указывается целиком (драйвер `postgresql+psycopg` — предварительно, окончательно выбирается в T0.2).
- **Заглушки** `deploy/compose/stubs/{api,web}` — временные, только для проверки маршрутизации. Заглушка `api` — FastAPI + uvicorn из стека архитектуры (`/api/health`, эхо-WebSocket `/api/ws`). В T0.2 и T0.3 контекст сборки сменится на `apps/api` и `apps/web`, заглушки удаляются.

## 2026-09-27 · T0.2 · Каркас API

- **Зависимости и окружение**: `uv` с `pyproject.toml` и `uv.lock` в `apps/api` (`package = false` — приложение, не библиотека). В образе `uv` копируется из `ghcr.io/astral-sh/uv:0.8.2`, зависимости ставятся `uv sync --frozen --no-dev`. Альтернатива — pip + requirements.txt; не выбрана: нет lock-файла с хэшами.
- **Настройки**: `pydantic-settings`. Ошибка валидации переводится в `SettingsError` с именами переменных в верхнем регистре (`PUBLIC_BASE_URL: is required`); пустое значение приравнивается к отсутствующему. Точка входа `python -m app` печатает ошибку в stderr и завершается с кодом 1 до запуска Uvicorn. Альтернатива — ручной разбор `os.environ`; не выбрана: pydantic уже в стеке FastAPI и даёт типы.
- **База данных**: SQLAlchemy 2 (async) + драйвер `psycopg` 3 (`postgresql+psycopg://`). Один драйвер работает и в async-приложении, и в синхронном Alembic, поэтому `DATABASE_URL` один. Альтернатива — asyncpg; не выбран: Alembic пришлось бы запускать через отдельный sync-драйвер или async-обёртку. `MetaData` с `naming_convention` — стабильные имена ограничений в миграциях.
- **Миграции**: Alembic, каталог `app/migrations`, запуск `upgrade head` в lifespan приложения — Uvicorn открывает порт только после завершения lifespan, значит трафик принимается уже на мигрированной базе. Шаблон ревизии генерирует `downgrade()`, бросающий `NotImplementedError` (только вперёд). Базовая ревизия `0001` пустая; таблицы добавляют задачи модулей. Альтернатива — `alembic upgrade head && uvicorn` в команде контейнера; не выбрана: проверка «миграции до трафика» тогда не покрывается модульным тестом.
- **OpenAPI**: `/api/openapi.json`, Swagger UI — `/api/docs` (ReDoc отключён). Все маршруты под префиксом `/api`, как проксирует Caddy.
- **Тестовая БД**: `testcontainers` (`testcontainers.community.postgres`, образ `postgres:16-alpine`) поднимает PostgreSQL на сессию тестов; каждый тест получает отдельную пустую базу. Если задан `TEST_DATABASE_URL`, используется внешний сервер. Альтернатива — SQLite; не выбрана: схема и миграции должны проверяться на PostgreSQL. Клиент тестов — `fastapi.testclient` с `httpx2` (Starlette 1.x помечает `httpx` в TestClient устаревшим).
- **Проверки**: `ruff` (lint с наборами E, W, F, I, B, UP, N, SIM, RUF, ASYNC, S и format, длина строки 100), `mypy --strict` с плагином `pydantic.mypy`.
- **Заглушка `deploy/compose/stubs/api` удалена**: сервис `api` собирается из `apps/api`. Эхо-WebSocket `/api/ws` больше нет — канал появится в модуле `realtime` (T4.1); до тех пор рукопожатие `/api/ws` получает 403 от API.

## 2026-09-27 · T0.3 · Каркас интерфейса

- **Пакеты и сборка**: `pnpm@10.18.3` (поле `packageManager`, та же версия, что в `acceptance/e2e`), Vite 8 + `@vitejs/plugin-react`, React 19. TypeScript закреплён на `~5.9`: TypeScript 7 не входит в поддерживаемые версии `typescript-eslint` и `openapi-typescript` (peer-зависимости).
- **Маршрутизатор**: `wouter` 3. Альтернативы — `react-router` и `@tanstack/react-router`; не выбраны: в их сборке есть строка `http://localhost` (служебная база для разбора URL), а в статике интерфейса не должно быть адресов `localhost` (ARCHITECTURE.md, раздел 10; регрессия `ARCH-NET-05` QA). `wouter` — небольшой зрелый маршрутизатор с параметрами пути и строкой запроса, этого хватает для таблицы маршрутов раздела 4.
- **Типы из OpenAPI**: `openapi-typescript` генерирует `src/api/schema.d.ts` из снимка схемы `apps/web/openapi.json`; снимок обновляется командой `pnpm api:fetch` (загрузка `$PUBLIC_BASE_URL/api/openapi.json` с запущенного стека), типы — `pnpm api:types`. Снимок в репозитории, чтобы сборка образа `web` не зависела от запущенного `api`. HTTP-клиент — `openapi-fetch` (тот же автор, типизированные пути без генерации кода клиента). Альтернатива — `orval`/`openapi-generator`; не выбраны: генерируют много кода клиента, который здесь не нужен.
- **Адреса**: HTTP-клиент берёт базой `window.location.origin` (пути схемы уже начинаются с `/api`), адрес сокета — `ws:`/`wss:` + `location.host` + `/api/ws`.
- **Тесты**: Vitest 5 + jsdom + Testing Library (`@testing-library/react`, `@testing-library/jest-dom`). Страница тестов открыта по адресу `http://192.168.1.20:8080/`, а не по умолчанию jsdom `localhost`.
- **Проверки**: ESLint 10 (flat config: `@eslint/js`, `typescript-eslint` `strictTypeChecked`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `eslint-config-prettier`), Prettier 3 с настройками по умолчанию; `tsc --noEmit` в строгом режиме (`strict`, `noUncheckedIndexedAccess`, `verbatimModuleSyntax`).
- **Образ `web`**: сборка в `node:24-alpine` (`pnpm install --frozen-lockfile && pnpm build`), раздача `dist` в `caddy:2.10-alpine` с прежним SPA-Caddyfile заглушки (`try_files {path} /index.html`). Заглушка `deploy/compose/stubs/web` удалена.

## 2026-09-27 · T1.1 · Администратор и учётные записи

- **Хэши паролей**: `argon2-cffi` (`PasswordHasher` с параметрами по умолчанию — Argon2id). Хэширование и проверка идут в пуле потоков, чтобы не блокировать цикл событий. Для неизвестной почты проверяется фиктивный хэш — время отказа не выдаёт, есть ли учётка. Альтернатива — `passlib`; не выбран: не развивается, а нужен только Argon2.
- **Сессии**: значение cookie — `secrets.token_urlsafe(32)`, в таблице `sessions` хранится его SHA-256 (утечка таблицы не даёт готовых cookie). Cookie администратора — `myboard_admin` (`HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` только при `https://` в `PUBLIC_BASE_URL`), без `Max-Age`: живёт до закрытия браузера или выхода; в базе `expires_at = NULL`. Сессия пользователя досок (T1.2) получит отдельную cookie, поэтому сессия пользователя в панель не пускает. Столбцы `sessions.board_id` и `display_name` (сессии участника по ссылке) добавит T3.1 своей миграцией.
- **Почта**: хранится обрезанной и в нижнем регистре; уникальность — ограничение `uq_users_email` в базе (ADM-07), конфликт → `409`. Формат проверяется минимально (`что-то@что-то` без пробелов, до 254 символов) — без `email-validator`: он отклоняет служебные домены (`.test`, `.local`), которыми пользуются в LAN-стендах. Пароль — непустой, до 1024 символов; требований к сложности в REQUIREMENTS.md нет.
- **Идентификаторы** `admins.id`, `users.id` — UUID v4 (непоследовательные).
- **Ограничение частоты входа**: в памяти процесса (один процесс API), скользящее окно: 10 неудачных попыток за 60 с с одного адреса → `429` с `Retry-After`, пока окно не освободится (в том числе для верного пароля). Удачный вход счётчик не сбрасывает. Адрес — `request.client.host` (uvicorn берёт его из `X-Forwarded-For`, который Caddy выставляет сам, не доверяя присланному клиентом). Альтернатива — `slowapi`; не выбран: лишняя зависимость ради одного счётчика.
- **`/admin`**: в таблице маршрутов раздела 4 его нет, а раздел 2 говорит «администратор открывает `/admin`». Толкование без изменения поведения: `/admin` — вход в панель, клиент перенаправляет на `/admin/users`; без сессии там показано приглашение войти со ссылкой на `/admin/login` (страница не подменяется формой входа, чтобы маршруты оставались различимыми). Вопрос владельцу не заводился.
- **Состояние входа в интерфейсе**: `GET /api/admin/session` отвечает `200 {authenticated, email}` и без сессии — cookie `HttpOnly` скрипту не видна, а ответ `401` на каждую анонимную загрузку страницы засорял бы консоль.
- **HTTP-клиент** (`apps/web/src/api/client.ts`) берёт `fetch` в момент запроса, а не при создании клиента: так тесты подменяют его через `vi.stubGlobal`. Тесты интерфейса — `@testing-library/user-event` (ввод и клики как у пользователя).

## 2026-09-27 · T1.2 · Вход пользователя досок

- **Маршруты**: `POST /api/login`, `POST /api/logout`, `GET /api/session` (без префикса `/admin`: страница входа — `/login`, раздел 4 архитектуры). `GET /api/session` отвечает `200 {authenticated, name, email}` и без сессии — по той же причине, что и `/api/admin/session` (T1.1). Маршруты модуля разнесены: `admin_router.py` (панель), `account_router.py` (пользователь досок), `router.py` собирает оба; общие части входа (скупой отказ, адрес клиента, лимит) — в `identity/http.py`.
- **Бессрочная сессия (ACC-03)**: cookie `myboard_session` отдельная от `myboard_admin` (сессия одного вида не открывает другой), `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` только при `https://`. Чтобы сессия пережила закрытие браузера, cookie ставится с `Max-Age` 400 дней (предел, который браузеры допускают для cookie) и продлевается при каждом `GET /api/session` с живой сессией; в базе `expires_at = NULL`. Сессия заканчивается только выходом или отключением учётки. Альтернатива — cookie без срока (сессионная); не выбрана: браузер удаляет её при закрытии.
- **Одинаковый отказ (ACC-02)**: неизвестная почта, неверный пароль, отключённая учётка и почта администратора дают `401 {"detail":"Invalid email or password"}` без cookie. Пароль проверяется и у отключённой учётки — время ответа не выдаёт причину. Сессия отключённого пользователя не принимается, даже если бы строка в `sessions` уцелела (проверка `users.disabled` при каждом запросе).
- **Лимит попыток**: тот же `LoginRateLimiter` (10 неудачных попыток за 60 с с адреса → `429` + `Retry-After`), отдельный экземпляр для входа пользователя: исчерпанный лимит панели не закрывает вход пользователям и наоборот.
- **Интерфейс**: `/login` — форма Email/Password; вошедший пользователь перенаправляется на `/`. `/` без сессии перенаправляет на `/login`; до T2.1 на `/` только имя пользователя и кнопка Sign out.

## 2026-09-27 · T1.3 · Отзыв сессий при смене пароля

- **Что считается сменой пароля (ADM-04)**: любой `PATCH /api/admin/users/{id}` с полем `password` отзывает все строки `sessions` этого пользователя (`subject_type = user`), даже если новый пароль совпадает со старым: сервер не сравнивает пароли, а администратор явно задал пароль заново. Имя и почта сессии не трогают; сессия администратора, выполнившего правку, не затрагивается. Новых библиотек нет.
- **Атомарность**: `DELETE` сессий и правка учётки — одна транзакция; при отказе (`409`, почта занята) не меняется ни пароль, ни сессии. `DELETE` выполняется до изменения полей объекта: иначе autoflush SQLAlchemy отправлял `UPDATE` почты раньше `commit`, и нарушение `uq_users_email` давало `500` вместо `409` (это касалось и отключения вместе со сменой почты из T1.1).
- **Открытая вкладка**: сервер отвечает отозванной сессии `authenticated: false`/`401`; страница узнаёт об этом при следующем обращении к API (загрузка или переход), тогда `/` уводит на `/login`. Опроса сессии или push-уведомления нет — в первой версии нет механизма для этого, а требование касается отзыва сессии, а не мгновенной реакции вкладки.

## 2026-09-28 · T1.4 · Выход вкладки при отзыве сессии

- **Как вкладка узнаёт об отзыве (ACC-05)**: опрос `GET /api/session` каждые 2 с, пока вкладка видима (`document.visibilityState`), и сразу при `visibilitychange` → `visible` и `focus`. Скрытая вкладка не опрашивает (браузеры всё равно замедляют её таймеры до раза в минуту), но проверяет сессию сразу при возврате — пользователь видит `/login`, не успев ничего сделать. 2 с — запас на медленную сеть телефона при пределе 5 с; нагрузка — один лёгкий запрос в 2 с на открытую вкладку. Одновременно идёт не больше одной проверки. Альтернатива — push по WebSocket; не выбрана: канал `/api/ws` появится в T4.1 и только на странице доски, а вкладка `/` должна уходить на вход и без него. Новых библиотек нет.
- **Ответ 401**: HTTP-клиент (`apps/web/src/api/client.ts`) через middleware `openapi-fetch` сообщает подписчикам `onUnauthorized` о любом ответе `401`. Вкладка пользователя считает выходом `401` на все пути, кроме `POST /api/login` (неверный пароль) и `/api/admin/*` (это сессия администратора). Сбой сети при повторной проверке вкладку не выбивает; выход окончательный — запоздавший ответ «вошёл» его не отменяет.
- **Где действует**: обёртка `RequireAccount` на маршрутах пользователя досок `/`, `/boards/{id}`, `/templates` — одна проверка на вкладку, состояние входа страницам отдаётся через контекст. `/t/{token}` не обёрнут: реакцию этой страницы на отсутствие сессии (отказ участнику без учётки, BRD-15) определит её задача. `/login` проверяет сессию один раз при открытии, без опроса.

## 2026-09-29 · T2.1 · Список досок

- **Таблица `boards`**: только столбцы, нужные T2.1 (`id` UUID v4, `owner_id` → `users.id`, `title` до 200 символов, `created_at`, `updated_at`, `deleted_at`). Папка, обложка и токены ссылок добавят T2.2, T3.1, T7.4, T9.1 своими миграциями. Новых библиотек нет.
- **Маршруты**: `GET /api/boards` (`q`, `sort`, `modified_since`), `GET /api/boards/recent`, `POST /api/boards`, `GET|PATCH|DELETE /api/boards/{id}`. Все — только с сессией пользователя досок (`401` иначе, в том числе с сессией администратора) и только над своими досками. Чужая, удалённая и несуществующая доска отвечают одинаково: `404 {"detail":"Board not found"}` — ответ не выдаёт, существует ли доска. Неверный формат id — `422` (валидация FastAPI); интерфейс показывает его как «не найдена».
- **Сортировка и фильтр (BRD-05)**: требование не называет конкретных вариантов. Выбрано: сортировка `updated` (по умолчанию, новые сверху), `created` (новые сверху), `title` (по алфавиту без учёта регистра); фильтр — по давности последнего изменения (`modified_since`, в интерфейсе Any time / Last 24 hours / Last 7 days / Last 30 days). Фильтры «избранное» и «папка» появятся с T2.2 (BRD-07, BRD-09). Граница фильтра считается на клиенте и передаётся ISO-временем — сервер не зависит от часового пояса браузера.
- **Поиск (BRD-06)**: `ILIKE '%…%'` по названию на сервере, без учёта регистра; `%`, `_`, `\` в запросе ищутся буквально. Интерфейс отправляет запрос через 300 мс после ввода. Поиск по папкам добавит T2.2.
- **Недавние (BRD-04)**: 8 последних по `updated_at`, отдельный маршрут `/recent`; поиск и фильтр их не сужают. Метку `updated_at` двигает и переименование: это изменение доски, иначе до T4.1 порядок «недавних» совпадал бы с порядком создания. Правки документа начнут двигать метку в T4.1.
- **Удаление (BRD-03)**: только `deleted_at`; окончательного удаления и корзины досок в требованиях нет. Подтверждение — встроенное в строку («Yes, delete»), без `window.confirm`: его нельзя оформить и неудобно проверять.
- **Создание (BRD-01)**: `POST /api/boards` без названия даёт «Untitled board»; кнопка New board сразу переходит на `/boards/{id}`. До холста (T4.1, T5.*) страница доски показывает название и ссылку на список.
- **Типы клиента**: снимок `apps/web/openapi.json` сгенерирован из `create_app(...).openapi()` в той же компактной сериализации, что отдаёт `/api/openapi.json` (совпадает байт в байт с загрузкой `pnpm api:fetch`), затем `pnpm api:types`.

## 2026-09-30 · T2.2 · Папки и избранное

- **Перетаскивание (BRD-10)**: `@dnd-kit/core` 6 — зрелая и распространённая библиотека для React, работает на Pointer Events (мышь, палец, перо одним сенсором). Альтернативы: нативный HTML5 Drag and Drop — не выбран: на телефонах перетаскивание касанием поддерживается неполно, а доска должна работать с телефона; `react-dnd` — тот же HTML5-бэкенд плюс отдельный touch-бэкенд; `@dnd-kit/react` — ещё версия 0.x. Перетаскивают за ручку (`Drag <название>`, `touch-action: none`): прокрутка пальцем по строке не превращается в перетаскивание, клики по ссылкам и кнопкам строки не мешают. Цели измеряются во время перетаскивания заново (`MeasuringStrategy.Always`) — страница прокручивается, пока тянут; автопрокрутка — только по вертикали и только у края (10 % высоты).
- **Куда падает элемент**: строка папки делится на зоны: верхняя и нижняя четверть — встать перед/после папки, середина — вложить. Доска кладётся в папку по всей строке. Свободное место раздела Folders — верхний уровень (и для досок, и для папок). Доски тянут из полного списка All boards и из дерева.
- **API**: `GET /api/folders` (все папки плоским списком, дерево строит клиент; `q` — поиск), `POST /api/folders {title, parent_id?}` (папка встаёт последней), `PUT /api/folders/{id}/position {parent_id, position}` (индекс среди папок нового родителя; соседи перенумеровываются 0…n-1), `PUT /api/boards/{id}/folder {folder_id}`, `PUT|DELETE /api/boards/{id}/favorite`, `PUT|DELETE /api/folders/{id}/favorite` (`204`, повтор безопасен). `BoardOut` получил `folder_id` и `favorite`. Отдельные маршруты вместо расширения `PATCH /api/boards/{id}`: у переименования обязательное поле `title`, а `{}` там — `422` (контракт T2.1).
- **Циклы**: вложить папку в неё саму или в её дочернюю — `409 {"detail":"A folder cannot be moved into itself or its subfolder"}`; интерфейс такой перенос не отправляет и показывает тот же текст. Создание и перенос папок берут блокировку всех папок владельца (`SELECT … FOR UPDATE`) — параллельные переносы не создают цикл и не путают порядок.
- **Перенос доски не двигает `updated_at`**: это раскладка списка, а не правка доски (в отличие от переименования) — порядок «недавних» не меняется.
- **Избранное**: таблица `favorites (user_id, target_type, target_id)` по архитектуре, без внешнего ключа на цель (цель двух типов); владение целью проверяет маршрут. Удалённая доска из избранного пропадает вместе со списком.
- **Боковой список**: раздел Favorites (появляется, когда есть избранное) и дерево Folders: подпапки по `position`, затем доски папки по названию. Доски верхнего уровня в дереве не повторяются — они в All boards. Папка сворачивается нажатием на её название (`aria-expanded`); новая папка свёрнута, родитель новой папки и цель переноса раскрываются. Какие папки развёрнуты — в `localStorage` браузера (BRD-11 не требует хранить это на сервере).
- **Поиск папок (BRD-06)**: то же поле Search boards на сервере (`GET /api/folders?q=`, `ILIKE` с буквальными `%`, `_`, `\`); найденные папки — список Matching folders с путём «Work / Projects / Alpha»; нажатие раскрывает путь в дереве и ставит фокус на папку. Фильтра списка All boards по папке нет: содержимое папки видно в дереве.
- **Не сделано намеренно**: переименование и удаление папок, порядок досок внутри папки — в требованиях их нет (BRD-09 — создание и вложение, BRD-10 — порядок папок и перенос досок).

## 2026-10-01 · T3.1 · Ссылка на доску и вход по ссылке

- **Токен (SHR-01, SHR-06)**: `secrets.token_urlsafe(32)` (32 случайных байта, 43 символа), столбец `boards.share_token` (уникальный, до 64 символов), не связан с id доски. Токен выдаётся при первом запросе `GET /api/boards/{id}/share`, а не при создании доски: старые доски получают ссылку без миграции данных, а доска, которой не делились, не имеет действующей ссылки. Одновременные первые запросы не выдают разных токенов: запись идёт `UPDATE … WHERE share_token IS NULL`, проигравший читает токен победителя. Прежний токен после сброса в базе не хранится (только момент сброса `share_token_revoked_at`), поэтому отозванный и никогда не существовавший токен неразличимы уже на уровне данных. Новых библиотек нет.
- **Адрес ссылки**: `url` в ответе собирает сервер из `PUBLIC_BASE_URL` (`{PUBLIC_BASE_URL}/b/{token}`); клиент его не собирает и `localhost` не вписывает.
- **Отказ (SHR-05)**: любой недействующий токен (отозванный, неизвестный, слишком длинный, доска удалена) — `404 {"detail":"Link is not available"}`; страница `/b/{token}` показывает «Board unavailable / This link is not available.» Маршруты владельца на чужую доску — `404 Board not found`, как в T2.1.
- **Cookie участника — своя на каждую доску (SHR-02, SHR-03)**: имя `myboard_board_{board_id.hex}`, флаги как у остальных сессий (`HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` только при `https://`), без `Max-Age` — живёт до закрытия браузера. Сессия хранится в `sessions` с `subject_type = guest`, случайным `subject_id`, `board_id` и `display_name`; учётная запись не создаётся. Одна cookie на доску, а не одна общая: участник может одновременно быть на нескольких досках под разными именами, а сброс ссылки одной доски не задевает другие. Альтернатива — общая cookie со списком досок в сессии — сложнее отзывать по одной доске. Повторный ввод имени заменяет прежнюю сессию этого браузера на доске.
- **Сброс удаляет сессии (SHR-06)**: `POST /api/boards/{id}/share/reset` в одной транзакции пишет новый токен и удаляет все гостевые сессии доски (`DELETE FROM sessions WHERE subject_type='guest' AND board_id=…`). Удаление, а не пометка «отозвана»: живой считается только существующая строка, проверка сессии остаётся одним запросом. Сессия владельца и гости других досок не затрагиваются. Подтверждение сброса — внутри диалога (Reset / Cancel), без `window.confirm`.
- **Права участника**: гостевая сессия не является сессией пользователя досок — `/api/boards*`, `/api/folders*`, `/` и `/boards/{id}` отвечают ей `401`/уводят на `/login`. Доступ к холсту по гостевой сессии (WebSocket `/api/ws`) проверяет T4.1: канала в T3.1 ещё нет.
- **Копирование ссылки (SHR-01)**: в локальной сети доска открыта по `http://` — это не защищённый контекст, и `navigator.clipboard` недоступен. Поэтому `copyText` сначала пробует Clipboard API (https, `localhost`), а при его отсутствии или отказе выделяет поле со ссылкой и вызывает `document.execCommand("copy")`. API устаревший, но поддерживается всеми браузерами и единственный работает без защищённого контекста; правило ESLint `no-deprecated` отключено одной строкой с пояснением. Если не вышло и это — пользователь видит «Copy failed. Select the link and copy it.», поле со ссылкой остаётся выделенным. Библиотеки (`copy-to-clipboard`) не нужны: они делают то же самое.
- **Фрейм**: заголовки `X-Frame-Options: DENY` и `frame-ancestors 'none'` уже ставит Caddy для всех путей, кроме `/b/{token}/embed` (T0.1); T3.1 их не меняет. Содержимое `/b/{token}/embed` появится в T7.3.

## 2026-10-01 · T4.1 · Синхронизация документа

- **Библиотеки**: сервер — `pycrdt` (назван в архитектуре); клиент — `yjs` (назван) и `lib0` (кодировщик varuint того же автора, зависимость самого `yjs`; объявлен явно, потому что импортируется напрямую). `y-websocket` не выбран: его провайдер закрывает соединение, если 30 с нет входящих сообщений (одинокий клиент переподключался бы каждые 30 с), сам строит адрес из комнаты и тянет протокол awareness до T4.2. `y-protocols` не нужен: из него понадобились бы только три функции sync. `pycrdt-websocket` не выбран: хранилище обновлений в нём — SQLite/файлы, а порядок «применить → записать в `board_updates` → разослать» и закрытие только виновного соединения проще задать явно.
- **Протокол `sync`**: двоичные кадры в кодировке y-protocols (`varuint тип | varuint подтип | varuint длина | байты`), тип `sync = 0`, подтипы `STEP1` (вектор версии), `STEP2` (недостающее / полный снимок на пустой вектор), `UPDATE`. Сервер после подключения сам шлёт `STEP1`; клиент — тоже. Так поздний клиент получает текущее состояние, а клиент после разрыва в ответ на вектор сервера досылает правки, сделанные без связи. Разбор кадра строгий (своя реализация, `pycrdt.Decoder` не проверяет длины): неизвестный тип, лишние байты, текстовый кадр, неразбираемое обновление или вектор — закрытие только этого соединения с кодом `1007`; документ сервера и других клиентов не меняется (обновление сначала применяется к копии сервера, затем пишется в журнал, затем рассылается). Пустое обновление (`00 00`) не пишется и не рассылается.
- **Адрес канала**: `/api/ws?board={id}` — владелец (cookie `myboard_session`), `/api/ws?token={token}` — участник по ссылке (cookie `myboard_board_{id}`); ровно один параметр. Участник входит по токену, а не по id доски: отозванная ссылка не открывает канал даже при живой cookie. Сессия участника по-прежнему привязана к `board_id` (Q-001 без изменений). Отказ — закрытие до `accept`, т. е. HTTP `403` на рукопожатие, причина не раскрывается.
- **Origin**: если браузер прислал `Origin`, его хост должен совпадать с `Host` запроса — чужая страница (в том числе сайт на другом порту той же машины: cookie `SameSite=Lax` для него «свои») не откроет канал с cookie участника. Клиент без `Origin` — не браузер, чужих cookie у него нет.
- **Отзыв доступа во время работы**: сброс ссылки сразу закрывает каналы участников этой доски кодом `4403` (SHR-06). Остальные случаи (выход, смена пароля, отключение учётки, удаление доски) ловит перепроверка доступа каждые 5 с в открытом соединении — без связей `identity`/`library` с `realtime`. Клиент после любого разрыва спрашивает HTTP (`GET /api/boards/{id}` или `GET /api/share/{token}`), есть ли доступ: нет — канал не переподключается, участник видит отказ или форму имени; сбой сети — повтор с паузами 0,5–8 с.
- **Журнал**: таблица `board_updates (board_id, seq, update, created_at)`, PK `(board_id, seq)`, миграция `0006`. Модель — в модуле `realtime`; снимки и сжатие журнала — T4.3. Документ доски живёт в памяти, пока есть соединения, и собирается из журнала при первом подключении. Номер `seq` и порядок применения/записи/рассылки задаёт блокировка комнаты (один процесс). Запись в журнал и `boards.updated_at = now()` — одна транзакция (BRD-04: правка поднимает доску в «недавних»).
- **Клиент**: `BoardConnection` (`apps/web/src/realtime/boardConnection.ts`) — свой провайдер; `createBoardDocument` объявляет корни `objects`, `trash`, `comments`, `timer`, `votes` (Y.Map) и `notes` (Y.XmlFragment). До холста (T5.*) страницы `/boards/{id}` и `/b/{token}` показывают только строку состояния связи (`role="status"`): Connecting… / Live… / Offline… В тестах `WebSocket` глобально заменён двойником без сети (`src/test-setup.ts`).

## 2026-10-02 · T4.2 · Присутствие и курсоры

- **Протокол `awareness`/`presence`** — свой, по тому же каналу `/api/ws`, тип кадра `1` и `2` после `sync = 0`: `varuint тип | varuint длина | JSON в UTF-8`. Новых библиотек нет. Протокол awareness из `y-protocols` не выбран: в нём имя — часть состояния клиента (участник по ссылке мог бы назваться чужим именем), а clientID документа Yjs раскрывается всем. Здесь сервер присваивает каждому соединению случайный id (`secrets.token_hex(8)`, не связан с сессией и учёткой) и сам подставляет имя: владельцу — имя учётки, участнику — имя из его сессии. Состояние клиента сервер не интерпретирует (только JSON-объект не больше 4 КБ, без `NaN`/`Infinity`; иначе `1007`), хранит последнее в памяти соединения для поздних участников и пересылает остальным. В документ, журнал `board_updates` и снимки присутствие не попадает и пропадает вместе с соединением (ARCHITECTURE.md, раздел 6).
- **`presence`** — полный список «кто на доске» по одному элементу на соединение (две вкладки одного человека — две строки, у каждой свой курсор), с id получателя (`self`). Рассылается всем при каждом входе и выходе, а также сразу, когда сервер сам закрывает соединения (сброс ссылки, отзыв доступа) — не дожидаясь ответа клиента на закрытие.
- **Состояние клиента**: `cursor` (точка в координатах доски или `null`), `camera` (центр вида в координатах доски и масштаб — не зависит от размера экрана наблюдателя), `following` (id соединения, за которым следит камера). Выделение (T5.2) и лазер (T6.5) добавятся полями того же состояния без изменений сервера. Клиент шлёт своё состояние сразу и затем не чаще раза в 50 мс (`AWARENESS_INTERVAL_MS`); после переподключения — заново.
- **Камера**: для курсоров и слежения нужна камера, а она — T5.1. Сделана минимальная: модуль `canvas/camera.ts` (центр + масштаб, пересчёт экран ↔ доска, сдвиг, масштаб вокруг точки) и область холста `BoardCanvas` — перетаскивание сдвигает вид, колесо масштабирует, точечный фон показывает движение. Миникарта, клавиши, настройка колеса, `localStorage` и щипок — в T5.1.
- **Слежение (COL-04)**: вид наблюдателя повторяет камеру выбранного участника, пока наблюдатель не нажмёт Stop following, не сдвинет/не масштабирует вид сам или участник не уйдёт с доски. Своё перемещение считается выключением наблюдения — иначе вид рывком возвращался бы к чужому.
- **Скрытие курсоров (COL-03)** — локальная настройка вкладки (состояние страницы), на сервер не уходит.
- **BUG-001**: ручка перетаскивания списка досок — не меньше 44×44 px во всех профилях (не только на `pointer: coarse`): размер не зависит от того, как браузер или эмуляция сообщают тип указателя.
- **BUG-002**: `RequireAccount` монтирует страницу только после ответа `/api/session` «вошёл»; до этого — «Loading…». Без сессии страница не успевает запросить доски и папки.

## 2026-10-02 · T4.3 · Журнал, снимки, корзина

- **Библиотек нет**: снимки — `pycrdt` (`Doc.get_update()` — полное состояние), фоновая задача — `asyncio.create_task` в lifespan процесса. Планировщики (APScheduler, Celery) не нужны: один процесс, одна периодическая задача.
- **Таблицы** (миграция `0007`, модели в модуле `history`): `board_snapshots (id, board_id, state, created_at)` и `board_events (id, board_id, actor_name, event_type, payload jsonb, created_at)` — как в разделе 7 архитектуры, плюс индексы `(board_id, created_at)`. Номер последнего вошедшего в снимок обновления не хранится: снимок и отрезание журнала (`DELETE … WHERE seq <= N`) — одна транзакция, поэтому всё, что осталось в `board_updates`, — после последнего снимка. Состояние доски при загрузке = последний снимок + оставшийся журнал, оба читаются в одной транзакции `REPEATABLE READ` (параллельное сжатие их не разорвёт). После полного отрезания нумерация `seq` у заново открытой доски начинается с 1 — коллизий нет, строк с прежними номерами уже нет.
- **Когда пишется снимок**: (1) раз в `SNAPSHOT_INTERVAL_SECONDS` (необязательная переменная, по умолчанию 300 с) для каждой открытой доски, где с прошлого снимка были правки; (2) при выгрузке доски — когда уходит последнее соединение; (3) при остановке процесса (lifespan). Доска без новых правок снимков не плодит. Пункты 2–3 — чтобы журнал неактивной доски не оставался несжатым и перезапуск не начинал с длинного журнала; снимки остаются как точки истории (COL-07, T8.2). Ошибка БД при сжатии только логируется: журнал не тронут. Выход соединения из комнаты экранирован от отмены (`anyio.CancelScope(shield=True)`), иначе отменённая задача соединения оставляла бы доску в памяти несжатой.
- **Подключение**: клиент по-прежнему присылает вектор версии (`sync STEP1`), сервер отвечает `STEP2` из своей копии документа — это и «недостающие обновления», и полный снимок, если клиент пуст или журнал сжат. Протокол WebSocket не менялся.
- **Корзина (основа COL-08)**: удаление — клиентская функция `moveToTrash` (`apps/web/src/realtime/boardDocument.ts`): одной транзакцией Yjs `objects[id]` → `trash[id] = Y.Map { object, deletedAt (ISO 8601), deletedBy }`. Общий тип Yjs переносить нельзя, поэтому в корзину кладётся `clone()` объекта. Сервер жестов не разбирает: комната подписана на ключи корня `trash` своей копии и для принятого обновления, добавившего ключи (`add`/`update`), пишет одну запись `board_events` (`event_type = "objects_deleted"`, `payload = {"object_ids": [...]}`) в той же транзакции, что и обновление журнала. `actor_name` — имя из сессии соединения (как в присутствии), а не поле `deletedBy` документа. Загрузка доски из снимка и журнала записей не порождает (подписка ставится после загрузки). Восстановление из корзины и экран ленты — T8.2. Интерфейса удаления пока нет (объекты появятся в T5.2/T5.3).
- **Присутствие вне снимков**: снимок — состояние документа Yjs, а awareness живёт только в памяти соединений; тест `test_presence_stays_out_of_snapshots` проверяет, что в байтах снимка нет ни курсора, ни имён.

## 2026-10-06 · T5.1 · Камера

- **Библиотек нет**: камера, щипок, колесо и миникарта — свои небольшие функции (`apps/web/src/canvas/`). Библиотеки жестов (`@use-gesture/react`, `hammerjs`) и готовые «бесконечные холсты» не взяты: Pointer Events покрывают мышь, касание и перо одним API, а нужны только сдвиг, щипок и колесо.

- **Закреплённые инструменты (CVS-24)**: набор и порядок — `localStorage["myboard.pinnedTools"]` (массив id), общий для всех досок этого браузера, как режим колеса (T5.1); у участника по ссылке учётной записи нет, поэтому хранение на сервере не выбрано. По умолчанию закреплены все инструменты в прежнем порядке — панель выглядит как до T5.4. Полный список — кнопка All tools, модальный диалог: выбрать любой инструмент, переключатель Pinned (`Switch`, первое применение на экране), кнопки Move up/down. Закреплённый заново инструмент встаёт в конец панели. Испорченная запись — набор по умолчанию.
- **Горячие клавиши (CVS-25)**: инструменты — V (Select), L (Lasso), N (Sticky note), S (Shape), T (Text), без модификаторов; отмена — Ctrl/⌘+Z, повтор — Ctrl/⌘+Shift+Z и Ctrl+Y. Сопоставление по `KeyboardEvent.code`, а не символу: клавиши работают в любой раскладке. Остальные клавиши — прежние: копирование, вырезание, вставка, дубликат — Ctrl/⌘+C, X, V, D (T5.3); удаление — Delete/Backspace (T5.2); масштаб — «+»/«−» (T5.1); перемещение вида — стрелки (T5.1); Escape — снять выделение. Клавиша показана в подсказке кнопки и в `aria-keyshortcuts`. Пока открыт модальный диалог, клавиши сцены не срабатывают.

Иначе нажатие терялось: в браузере между обработчиками одного события выполняются микрозадачи, другой обработчик Escape (снятие выделения) перерисовывал страницу, и диалог переподписывался посреди события.

## 2026-10-09 · T5.5 · Поиск и ссылка на объект

- **Библиотек нет**: поиск — подстрока без учёта регистра по уже загруженному документу (`scene/search.ts`, ARCHITECTURE.md, раздел 4). Полнотекстовые и нечёткие библиотеки (`fuse.js`, `minisearch`, `flexsearch`) не взяты: на доске сотни объектов, индекс не нужен, а нечёткое совпадение давало бы неожиданные результаты.
- **Теги (CVS-08)**: формат задан здесь, интерфейс тегов добавят T6.2 (STK-03) и T6.8 (KBN-02). Поле объекта `tags` — `Y.Array<string>` (одновременные добавления разных тегов сливаются); читается и запись JSON-массивом. Тег хранится без «#», пустые и повторы при чтении отбрасываются. Запрос с «#» в начале ищет только по тегам, без «#» — по тексту и тегам.
- **Поиск в интерфейсе**: кнопка Search в группе Board actions панели Tools открывает плавающую панель справа сверху над холстом (`role="search"`). Результаты обновляются при вводе и при правках документа, в порядке чтения доски (сверху вниз, слева направо): тип, отрывок текста вокруг совпадения (до 80 символов), совпавшие теги. Щелчок по результату или Enter (следующий результат по кругу) переводит вид к объекту и выделяет его; панель остаётся открытой. Escape в поле или Close закрывают её. Горячей клавиши нет: Ctrl/⌘+F остаётся поиском браузера.
- **Переход к объекту** (`canvas/camera.ts`, `focusOn`): центр вида — середина объекта, масштаб 100 %; если объект с полями 48 px не помещается — меньше. Один и тот же переход у поиска и ссылки.
- **Ссылка на объект (SHR-07)**: `/b/{token}?object={id}` (ARCHITECTURE.md, раздел 5). Пункт Copy link to object — в меню объекта (правый щелчок, кнопка More), только при одном выделенном объекте. Он открывает диалог Link to object с полем и кнопкой Copy link: без защищённого контекста (http в LAN) копируется выделение поля, как в Share (T3.1), а запрос ссылки владельца асинхронный и не даёт копировать прямо из пункта меню. Владелец получает ссылку на доску из `GET /api/boards/{id}/share` (как диалог Share), участник — из адреса страницы и своего токена.
- **Когда двигать вид**: после первой сверки документа с сервером (статус `online`), один раз на объект из ссылки; повторное подключение вид не трогает. Объекта нет (удалён, в корзине, чужой id) — вид остаётся прежним, внизу холста сообщение «The linked object is not on this board.» с кнопкой Dismiss. Параметр `object` остаётся в адресе: перезагрузка снова ведёт к объекту.
