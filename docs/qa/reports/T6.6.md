# T6.6 · QA-отчёт

Требования: FRM-01…FRM-05; попутно — CVS-19 (блокировка), CON-01 / CVS-26 (линия к фрейму), COL-01 (правки видны второму клиенту), CVS-07 (отмена); регрессия всего `acceptance/`
Коммит сценариев: c9a04ef (в `main` до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (FRM-01…05, CVS-19, CON-01, CVS-26, COL-01, CVS-07), `ARCHITECTURE.md` (раздел 6: объект сцены — JSON с `type`, «координаты дочернего объекта задаются относительно родителя. Родитель — фрейм, группа, ячейка таблицы или столбец канбана», порядок слоёв — целое `z`; сервер применяет `sync` и рассылает) и блоку «Тестирование» T6.6 в `PLAN.md`. До чтения handoff, `docs/decisions.md` ветки DEV и кода.

Роли: **пользователь досок** (владелец, `/boards/{id}`), **участник по ссылке** (`/b/{token}`, те же права на холсте: создаёт фрейм, оформляет, скрывает содержимое, блокирует; блокировку другого не обходит), **посторонний** (без сессии документ не получает — регрессия `realtime`), **администратор** — не затрагивается. Совместная работа — минимум два независимых клиента.

Границы толкования (фиксирую до чтения handoff):

- **FRM-01** «создавать фрейм, внутрь которого попадают объекты, и позволять провести к фрейму соединительную линию»: инструмент «фрейм» ставит фрейм на холст. Объект, перенесённый внутрь фрейма (перетаскиванием) или созданный внутри, становится его содержимым: при перемещении фрейма объект двигается вместе с ним (сохраняя положение относительно фрейма), у второго клиента и после перезагрузки тоже. Негативный: объект вне фрейма при перемещении фрейма остаётся на месте; объект, вынесенный из фрейма, перестаёт двигаться с ним. Граничный: объект, лишь частично перекрывающий фрейм, — наблюдение (правило «внутри» требованием не задано: центр или целиком); ни при каком правиле объект целиком внутри не должен остаться вне фрейма. По архитектуре у дочернего объекта в `objects` есть ссылка на родителя и координаты относительно него (проверка независимым WebSocket-клиентом). Линия: соединитель проводится от объекта к фрейму и привязывается к нему — при перемещении фрейма конец линии следует за ним (у второго клиента тоже). Участник по ссылке делает то же самое.
- **FRM-02** «оформление: заливка, только граница или рамка без фона, в том числе пользовательским цветом»: три вида оформления выбираются у фрейма; заливка — фон фрейма заданным цветом; цвет из палитры и пользовательский (поле выбора цвета) применяется к выбранному виду; видно второму клиенту и после перезагрузки. **Неясность**: «только граница» и «рамка без фона» буквально совпадают — открыт вопрос Q-004 (без ответа владельца). По WORKFLOW.md раздел 5 QA не выбирает удобное толкование: различие видов «только граница» / «рамка без фона» оценивается после ответа владельца; не зависящие от толкования проверки (три вида есть, заливка цветом, пользовательский цвет, синхронизация, сохранение) прогоняются сейчас — их провал даёт FAIL независимо от ответа.
- **FRM-03** «фиксировать пропорции фрейма»: у фрейма есть переключатель фиксации пропорций; при включённой фиксации изменение размера маркером сохраняет отношение ширины к высоте (в т. ч. при протяжке только по одной оси, через боковой маркер — либо пропорция сохраняется, либо боковой маркер недоступен); при выключенной — размер меняется свободно; состояние фиксации — свойство фрейма, переживает перезагрузку и видно второму клиенту (изменение размера вторым клиентом тоже сохраняет пропорцию). Граничный: сильное уменьшение не нарушает отношение сверх округления (≤ 2 %). Прочтение «выбрать готовую пропорцию (A4, 16:9)» требованием прямо не названо — наличие пресетов наблюдение, не FAIL; их отсутствие при работающей фиксации — не FAIL.
- **FRM-04** «скрывать и снова показывать содержимое фрейма, в том числе у заблокированного фрейма»: команда скрытия делает содержимое фрейма невидимым (рамка остаётся видимой), показ возвращает содержимое на прежние места без потерь; объекты вне фрейма не скрываются. Работает у фрейма, заблокированного обоими способами FRM-05 (только рамка; рамка с содержимым). Скрытие — состояние документа или локальное — требованием не задано: наблюдение (фиксирую, видно ли второму клиенту). Скрытое содержимое не удаляется из документа (после показа объекты те же, `id` те же). Граничный: пустой фрейм — команда не ломает ничего; содержимое, добавленное в скрытый фрейм, — наблюдение.
- **FRM-05** «при блокировке фрейма спрашивать, блокировать только рамку или рамку вместе с содержимым»: команда блокировки фрейма показывает выбор из двух вариантов (диалог/меню в интерфейсе приложения, не браузерный `confirm`); отказ/закрытие выбора не блокирует ничего. «Только рамка»: фрейм не двигается (CVS-19), содержимое можно двигать и править. «Вместе с содержимым»: не двигается ни фрейм, ни объекты внутри, рисунок внутри не стирается ластиком (CVS-19). Варианты наблюдаемо различаются. Снятие блокировки (и «разблокировать всё») возвращает подвижность. Блокировка видна второму клиенту и действует для участника по ссылке. Блокировка обычного объекта (не фрейма) выбора не показывает — наблюдение (требование о нём молчит; регрессия CVS-19 — блокировка объекта работает).
- **Архитектура**: фрейм — объект `objects` с `type` (наблюдаемо `frame`), у содержимого — родитель и координаты относительно фрейма; правки фреймов идут через WebSocket `sync`, без HTTP-запросов к `/api`; нет `localhost` в клиенте (регрессия `web.spec.ts`); посторонний без сессии документ не получает (регрессия `realtime`).
