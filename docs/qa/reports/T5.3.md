# T5.3 · QA-отчёт

Требования: CVS-15, CVS-16, CVS-17, CVS-18, CVS-19, CVS-20, CVS-22; регрессия CVS-12 (прилипание после добавления направляющих) и всего `acceptance/`; наблюдение T5.2: удаление/вырезание переносит объект в `trash`
Коммит сценариев: 0c3fb94 (в `main` до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (CVS-15…20, CVS-22, контекст — CVS-12, CVS-21, SHR-04, COL-01), `ARCHITECTURE.md` (раздел 6: объект сцены — JSON с `type`, целое поле `z` — порядок слоёв, координаты дочернего объекта относительно родителя, родитель — в т. ч. группа; удаление переносит объект в `trash` `{object, deletedAt, deletedBy}`; метаданные доски в документ не входят) и блоку «Тестирование» T5.3 в `PLAN.md`, до чтения handoff и кода. `docs/questions.md` по T5.3 вопросов не содержит.

Способ наблюдения (только публичные интерфейсы): документ доски — независимый WS-клиент (`pycrdt`) и второй контекст браузера; холст — DOM-элементы объектов, их экранные прямоугольники и порядок наложения (`elementFromPoint` в зоне перекрытия); направляющие — видимые элементы на холсте во время перетаскивания.

Роли: **владелец**; **участник по ссылке** — на холсте те же действия (SHR-04), у CVS-22 — автор с именем из сессии; **второй клиент** — видит результат; **второй пользователь** (другая учётка) — для CVS-20 «между досками пользователя»; **посторонний** — регрессия.

Границы толкования (фиксирую до чтения handoff):

- **CVS-15** выравнивание: при выделении ≥ 2 объектов есть команды выравнивания (по левому/правому краю, центру по горизонтали, верху/низу, центру по вертикали — минимум левый край и верх); после «по левому краю» у всех `x` (левый край в мире) равен минимальному левому краю выделения, вертикальные координаты не меняются. Распределение: ≥ 3 объекта разной ширины — после распределения по горизонтали промежутки между соседними (край к краю) равны (± 1), крайние объекты на месте; по вертикали — аналогично. Жест за маркер рамки выделения: у рамки выделения нескольких объектов есть маркер(ы), протяжка которого меняет промежутки между объектами (равные после жеста), а не размер объектов; что именно — узнаю из handoff, но жест должен существовать. Негатив: при одном выделенном объекте распределение недоступно/ничего не меняет; при двух — распределение не меняет положения (или недоступно). Граничный: объекты внутри группы/повёрнутые — наблюдение. Второй клиент видит новые координаты.
- **CVS-16**: при перетаскивании объекта, когда его край/центр совпадает (в пределах порога) с краем/центром соседнего, на холсте появляются направляющие линии; объект прилипает к выравниванию; после отпускания направляющие исчезают. Негатив: далеко от соседей направляющих нет; с модификатором отключения прилипания (CVS-12) объект не прилипает (направляющие — наблюдение). Регрессия CVS-12: без соседей прилипание к сетке как прежде; Shift — одна ось; Alt — точный сдвиг.
- **CVS-17**: команда «сгруппировать» на ≥ 2 выделенных создаёт группу: щелчок по члену выделяет группу целиком, перетаскивание двигает всех вместе (взаимное положение сохраняется); «разгруппировать» возвращает отдельные объекты на те же мировые места. В документе — объект группы, у детей ссылка на родителя и координаты относительно родителя (ARCH) — мировые положения детей при этом не меняются. Порядок слоёв внутри группы: элемент группы можно поднять/опустить относительно других членов группы — меняется его `z` относительно соседей по группе, видно по наложению; группа целиком — поднять/опустить относительно объектов вне группы (все её члены оказываются над/под внешним объектом). Негатив: группировка одного объекта недоступна/ничего не делает; разгруппировка не-группы ничего не ломает. Граничный: группа с ≥ 3 членами; вложенная группа — наблюдение. Второй клиент видит группу и порядок.
- **CVS-18**: 4 команды — вперёд на один, назад на один, на передний план, на задний план. Для 3+ перекрывающихся объектов A<B<C: «вперёд» у A ставит его между B и C (ровно на один слой), «на передний» — выше всех, «назад»/«на задний» — симметрично. Видно по наложению (`elementFromPoint` в общей зоне) и по `z` в документе (целые). Граничный: «вперёд» у самого верхнего и «назад» у самого нижнего — порядок не меняется, ошибок нет; «на один слой» учитывает только перекрывающихся/соседей по порядку — наблюдение. Второй и поздний клиент видят тот же порядок.
- **CVS-19**: заблокировать выделенный объект; заблокированный не двигается перетаскиванием (документ не меняется, ни одного `sync` с новыми координатами), не меняет размер; стрелки/выравнивание — наблюдение. Снять блокировку с объекта — снова двигается. Команда «разблокировать всё» на доске снимает блокировку со всех заблокированных (≥ 3 объекта, в т. ч. невыделенные). Блокировка — свойство объекта в документе: второй клиент тоже не может сдвинуть. Ластик — инструмента рисования ещё нет (DRW, T6.5): часть «не стирается ластиком» переносится в T6.5, здесь — наблюдение. Удаление заблокированного (Delete) — требование не задаёт, наблюдение. Участник по ссылке блокирует/снимает так же.
- **CVS-20**: копировать (Ctrl/Cmd+C) + вставить (Ctrl/Cmd+V) на этой доске создаёт новые объекты (новые id) с теми же свойствами, со смещением или у курсора; дублировать — одна команда (Ctrl/Cmd+D или меню) создаёт копию; вырезать (Ctrl/Cmd+X) убирает объекты из `objects` (по ARCH — в `trash`, как удаление) и вставка возвращает их как новые; несколько объектов сохраняют взаимное положение; копия группы — группа с детьми. Между досками пользователя: копирование на доске A и вставка на доске B того же пользователя (в одном браузере, обе доски открыты по очереди/в двух вкладках) создаёт на B объекты с теми же свойствами (тип, текст, цвет, размеры, взаимное положение). Негатив: вставка в поле ввода объекты не создаёт; повторная вставка — ещё одна копия (не сдвигает прежнюю). Граничный: копия на другую доску не меняет доску-источник; новые `z` поверх существующих на B. Участник по ссылке — копирует и вставляет в пределах доски; «между досками пользователя» — у участника досок нет (наблюдение).
- **CVS-22**: по объекту (панель свойств/меню/подсказка) видны: автор, дата создания, автор и дата последнего изменения. Создал владелец — автор = имя владельца; изменил участник по ссылке — «изменил» = имя участника из сессии, «создал» прежний; даты — реальные (в пределах минуты от действия), изменение не раньше создания, и после правки дата изменения растёт. Негатив: выделение/щелчок без правки не меняют «последнее изменение». Граничный: объект, созданный участником, — автор = имя участника; копия объекта — автор копии = кто вставил (наблюдение); данные видны второму клиенту и после перезагрузки (хранятся в документе).
- Доступ: все действия выполняет и участник по ссылке; посторонний холст не получает (регрессия).
