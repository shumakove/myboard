# T3.1 · QA-отчёт

Требования: SHR-01, SHR-02, SHR-03, SHR-05, SHR-06; регрессия ACC-*, ADM-*, BRD-*
Коммит сценариев: b1535ae (в `main` до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (раздел 2 «Участник сессии», раздел 5 «Участник сессии по ссылке этот список не видит», раздел 6 SHR-01…03, 05, 06), `ARCHITECTURE.md` (раздел 4 — маршруты `/b/{token}`, `/b/{token}/embed`; раздел 5 «Ссылка» — токен 32 случайных байта в URL-безопасной кодировке, одна действующая ссылка, сброс помечает прежний токен отозванным, имя в сессионной cookie этой доски, учётка не создаётся; раздел 7 — `sessions.board_id`, `display_name`, `boards.share_token`, `share_token_revoked_at`; раздел 12 — токен не последовательный и не содержит id доски, сброс сразу лишает старый адрес и старую cookie доступа, cookie не читаются скриптом, фрейм только для `/b/{token}/embed`, ошибки ссылки одинаково скупые) и блоку «Тестирование» T3.1 в `PLAN.md`, до чтения handoff и кода.

Роли:

- **владелец (пользователь досок A)** — получает, копирует и сбрасывает ссылку своей доски;
- **пользователь досок B** — не получает и не сбрасывает ссылку доски A (`404`/`403`); по действующей ссылке A входит как участник (SHR-02 «любого»), но не получает доступа к списку и другим доскам A;
- **участник по ссылке** — без учётки: вводит имя, получает cookie этой доски, не видит `/` и другие доски владельца, не может получить/сбросить ссылку;
- **администратор** — сессия панели не даёт ссылки и не сбрасывает её; участник по ссылке не появляется в списке учётных записей;
- **посторонний** — без сессии и без токена: эндпоинты ссылки `401`, `/boards/{id}` не открывается, случайный/отозванный токен — неразличимый отказ.

Границы толкования (фиксирую до чтения handoff):

- SHR-01 «скопировать»: в диалоге Share есть кнопка копирования; после клика в буфере обмена — полная ссылка `PUBLIC_BASE_URL/b/{token}` (проверка через `navigator.clipboard.readText` с разрешением в Playwright или вручную). Адрес собран из `PUBLIC_BASE_URL`, не из `localhost`. Ссылка стабильна: повторный запрос без сброса даёт тот же токен.
- Токен: не короче 43 символов base64url (32 байта), алфавит `[A-Za-z0-9_-]`, у разных досок разный, не содержит id доски, не последовательный.
- SHR-02 «без учётной записи»: браузер без каких-либо cookie по ссылке попадает на доску (на этой задаче — страница доски/её заглушка после ввода имени; холста ещё нет). Количество учёток в панели до и после входа участника одинаково.
- SHR-03: до ввода имени страница доски не показывается и HTTP доступа к доске нет; пустое имя / только пробелы отклоняются; очень длинное имя — `4xx` или обрезка, не `5xx`; кириллица и разметка — отображаются текстом; повторное открытие той же ссылки в той же сессии имя повторно не требует (фиксация). Имя хранится в cookie этой доски (сессионной: без `Max-Age`/`Expires` — фиксация), cookie `HttpOnly`, `SameSite=Lax`, без `Secure` на `http://`.
- SHR-05: несуществующий токен, отозванный токен, токен с изменённым одним символом, пустой/короткий токен — одинаковый код и тело ответа (и одинаковая страница в браузере), без признаков существования доски. `/boards/{id}` без сессии владельца не открывается (ни посторонним, ни участником по ссылке, ни пользователем B). Cookie участника доски X не открывает доску Y.
- SHR-06: сброс доступен только владельцу; новый токен отличается от прежнего; прежний токен отвечает как несуществующий; выданная по прежней ссылке cookie участника перестаёт давать доступ (HTTP; WebSocket — если канал доски уже есть); новая ссылка работает; повторный сброс отзывает и вторую ссылку.
- Embed: `/b/{token}/embed` разрешает показ во фрейме, `/b/{token}` — нет (регрессия ARCH-FRAME).
