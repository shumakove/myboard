Требования: FIL-01…FIL-05; попутно — модуль `media` (ARCHITECTURE.md разделы 5, 8, 12), IMG-06 (GIF), SHR-04/SHR-06 (доступ участника по ссылке к файлам), CVS-20 (копирование объекта с файлом), COL-01 (два клиента), MOB-01 (профиль телефона); регрессия всего `acceptance/`

Сценарии составлены только по `REQUIREMENTS.md` (FIL-*, IMG-06, CVS-20, SHR-04…06), `ARCHITECTURE.md` (раздел 4 — маршруты; раздел 5 — модуль `media`; раздел 6 — объект сцены в `objects` с `type`; раздел 8 — хранение, `/api/media/{id}` только при сессии этой доски, проверка объявленного типа, лимит `MAX_UPLOAD_BYTES`, «Проигрывание идёт с этого URL в браузере участника, который нажал play. Сервер поток по сеансам не синхронизирует (FIL-05)»; раздел 12 — живая сессия конкретной доски) и блоку «Тестирование» T7.2 в `PLAN.md` («каждый формат из списка воспроизводится; FIL-05 — запуск у одного клиента не запускает у второго; извлечённые страницы PDF — отдельные объекты»). До чтения handoff, ветки DEV и кода.

Роли: **пользователь досок** (владелец, `/boards/{id}`), **участник по ссылке** (`/b/{token}`), **посторонний** (без сессии; с сессией другой доски; со старой cookie после сброса; другой пользователь досок), **администратор** (сессия панели — не сессия доски).

Границы толкования (фиксирую до чтения handoff):

- **FIL-01** «загружать файл на доску, показывать его ярлыком, переименовывать и скачивать»: «файл» — произвольный файл, не только изображение (минимум txt, docx, zip, без расширения); на холсте — объект-ярлык с именем файла; новое имя видно второму клиенту и после перезагрузки; скачивание отдаёт те же байты; имя скачиваемого файла — текущее имя ярлыка (ожидание; если отдаётся исходное — разбираю отдельно). Участник по ссылке может всё то же.
- **FIL-02** «открывать PDF на доске постранично и извлекать выбранные страницы отдельными объектами»: листание страниц на холсте вперёд и назад, границы первой и последней страницы; выбор одной и нескольких страниц; число новых записей `objects` равно числу выбранных страниц, каждая показывает свою страницу, живёт без исходного PDF, видна второму клиенту и после перезагрузки. Тип извлечённого объекта требование не задаёт.
- **FIL-03** «воспроизводить видео на доске: пауза, перемотка, громкость, скорость и полный экран. Форматы: mp4, m4v, mov, webm»: каждый формат действительно воспроизводится (`currentTime` растёт, размер кадра ненулевой) в браузере с H.264; каждое из пяти управлений доступно участнику и меняет наблюдаемое состояние элемента. Кодек H.264 в `mp4/m4v/mov`, VP8/VP9 в `webm`.
- **FIL-04** то же для аудио: mp3, m4a, wav, webm (Opus/Vorbis); пауза и перемотка.
- **FIL-05** «воспроизводить видео, аудио и GIF только у того участника, который запустил ролик»: запуск, пауза, перемотка, громкость, скорость у клиента A ничего не меняют у клиента B и не порождают записей в документе (независимый WS-клиент). Для **GIF**: фиксирую как возможную неоднозначность сочетание с IMG-06 («показывать GIF; при большом числе объектов воспроизведение начинается по наведению»): (а) при малом числе объектов GIF анимируется у всех без запуска, а FIL-05 относится к запуску по наведению; (б) GIF ни у кого не анимируется, пока участник сам его не запустил. Наведение у A при большом числе объектов не должно запускать GIF у B при любом толковании. Если поведение реализации различает (а) и (б), выбор делает владелец.
