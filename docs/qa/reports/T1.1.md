# T1.1 · QA-отчёт

Требования: ADM-01, ADM-02, ADM-03, ADM-04, ADM-05, ADM-06, ADM-07
Коммит сценариев: см. коммит «T1.1: Зафиксировать сценарии приёмки до чтения handoff» в `main` (до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (раздел 3), `ARCHITECTURE.md` (разделы 2, 4, 5, 7, 12) и блоку «Тестирование» T1.1 в `PLAN.md`, до чтения handoff и кода. Дополнительные проверки архитектуры: `ARCH-ADM-*`.

Роли:

- **администратор** — учётка из `ADMIN_EMAIL`/`ADMIN_PASSWORD`, созданная при пустой базе;
- **пользователь досок** — учётка, созданная администратором в панели;
- **посторонний** — клиент без cookie или с поддельной cookie;
- **участник по ссылке** — ссылок на доски в T1.1 ещё нет (T3.1); роль проверяется в регрессии после T3.1 (сессия участника не открывает панель).

Способ проверки «пользователь входит / не входит» (ADM-04, ADM-05, ADM-06) — через публичный вход пользователя досок, если он есть в ветке (`/login` или API входа). Если входа пользователя досок в T1.1 нет, эти части проверяются тем же способом, который указан в handoff как наблюдаемый снаружи, а при его отсутствии фиксируются как непроверяемые до T1.2 (вопрос владельцу не нужен: блок «Тестирование» T1.1 прямо требует «новый пароль работает, старый — нет»).
