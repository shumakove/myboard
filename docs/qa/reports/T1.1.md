# T1.1 · QA-отчёт

Требования: ADM-01, ADM-02, ADM-03, ADM-04, ADM-05, ADM-06, ADM-07
Коммит сценариев: см. коммит «T1.1: Зафиксировать сценарии приёмки до чтения handoff» в `main` (до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (раздел 3), `ARCHITECTURE.md` (разделы 2, 4, 5, 7, 12) и блоку «Тестирование» T1.1 в `PLAN.md`, до чтения handoff и кода. Дополнительные проверки архитектуры: `ARCH-ADM-*`.

Роли:

- **администратор** — учётка из `ADMIN_EMAIL`/`ADMIN_PASSWORD`, созданная при пустой базе;
- **пользователь досок** — учётка, созданная администратором в панели;
- **посторонний** — клиент без cookie или с поддельной cookie;
- **участник по ссылке** — ссылок на доски в T1.1 ещё нет (T3.1); роль проверяется в регрессии после T3.1 (сессия участника не открывает панель).

Способ проверки «пользователь входит / не входит» (ADM-04, ADM-05, ADM-06) — через публичный вход пользователя досок, если он есть в ветке (`/login` или API входа). Если входа пользователя досок в T1.1 нет, эти части проверяются тем же способом, который указан в handoff как наблюдаемый снаружи, а при его отсутствии фиксируются как непроверяемые до T1.2 (вопрос владельцу не нужен: блок «Тестирование» T1.1 прямо требует «новый пароль работает, старый — нет»).

## Сценарии

| Требование | Роль | Сценарий | Тип (авто / ручной) |
| --- | --- | --- | --- |
| ADM-01 | администратор | Позитивный: на пустой базе вход в панель с `ADMIN_EMAIL`/`ADMIN_PASSWORD` успешен, выдаётся cookie сессии; с ней доступен список учётных записей | авто (api) |
| ADM-01 | администратор | Позитивный (UI): `/admin/login` — форма почты и пароля; после входа открывается `/admin/users` со списком | авто (e2e, desktop + mobile) |
| ADM-01 | посторонний | Негативный: неверный пароль администратора, неизвестная почта — отказ; ответ одинаковый (код и текст) для обоих случаев, cookie сессии не выдаётся | авто (api) |
| ADM-01 | посторонний | Негативный: без cookie и с поддельной cookie API панели (список, создание, изменение) отвечает отказом (401/403), данных учёток не раскрывает | авто (api) |
| ADM-01 | посторонний | Негативный (UI): `/admin/users` без сессии не показывает список (переход на `/admin/login` или отказ) | авто (e2e) |
| ADM-01 | пользователь досок | Негативный: почта и пароль пользователя досок на входе в панель — отказ; сессия пользователя досок (если есть вход пользователя) не открывает API панели | авто (api) |
| ADM-01 | администратор | Граничный: почта администратора в другом регистре / с пробелами по краям — поведение фиксируется; пустые поля — отказ 4xx, не 500 | авто (api) |
| ADM-01 | администратор | Граничный: выход из панели (если есть) — после выхода старая cookie не даёт доступа | авто (api) |
| ADM-01 | администратор | Граничный: повторный старт стека на непустой базе не создаёт второго администратора и не меняет пароль (смена `ADMIN_PASSWORD` в env не действует после первого старта) | ручной (перезапуск api с другим `ADMIN_PASSWORD`) |
| ADM-02 | администратор | Позитивный: пустой список на новой базе; после создания N учёток список содержит все N с именем и почтой (и признаком отключения) | авто (api + e2e) |
| ADM-02 | администратор | Негативный: список не содержит паролей и хэшей паролей; администратор в списке пользователей досок не появляется | авто (api) |
| ADM-02 | посторонний, пользователь досок | Негативный: список недоступен | авто (api) |
| ADM-03 | администратор | Позитивный: создание с именем, почтой, паролем → учётка появляется в списке с этими именем и почтой (API и UI) | авто (api + e2e) |
| ADM-03 | администратор | Позитивный: созданный пользователь входит с заданными почтой и паролем (вход пользователя досок) | авто (api), если вход есть |
| ADM-03 | администратор | Негативный: без имени, без почты, без пароля, с некорректной почтой — отказ 4xx (422/400), учётка не создана | авто (api) |
| ADM-03 | посторонний | Негативный: создание без сессии администратора — отказ, учётка не появляется | авто (api) |
| ADM-03 | администратор | Граничный: имя и пароль с Unicode (кириллица), длинное имя, пароль с пробелами — сохраняются как введены, вход с тем же паролем работает | авто (api) |
| ADM-04 | администратор | Позитивный: изменение имени → новое имя в списке | авто (api + e2e) |
| ADM-04 | администратор | Позитивный: изменение почты → новая почта в списке; вход по новой почте работает, по старой — нет | авто (api) |
| ADM-04 | администратор | Позитивный: изменение пароля → новый пароль работает, старый — нет | авто (api) |
| ADM-04 | администратор | Негативный: изменение несуществующей учётки — 404; некорректная почта / пустое имя — 4xx, данные не изменились | авто (api) |
| ADM-04 | посторонний | Негативный: изменение без сессии администратора — отказ, данные не изменились | авто (api) |
| ADM-04 | администратор | Граничный: изменение только одного поля не трогает остальные (смена имени не меняет пароль и почту) | авто (api) |
| ADM-05 | администратор | Позитивный: отключение → в списке учётка помечена отключённой; вход пользователя с верным паролем отклоняется | авто (api + e2e) |
| ADM-05 | пользователь досок | Негативный: уже выданная сессия отключённого пользователя не даёт доступа (если вход пользователя есть) | авто (api) |
| ADM-05 | пользователь досок | Позитивный: доски отключённого пользователя сохраняются — проверяется после T2.1 (регрессия), в T1.1 досок нет; в T1.1 проверяется, что отключение не удаляет учётку (она остаётся в списке) | авто (api) |
| ADM-05 | посторонний | Негативный: отключение без сессии администратора — отказ | авто (api) |
| ADM-05 | администратор | Граничный: повторное отключение уже отключённой — без ошибки 500, состояние «отключена» | авто (api) |
| ADM-06 | администратор | Позитивный: включение отключённой → в списке активна, вход пользователя снова работает с прежним паролем | авто (api + e2e) |
| ADM-06 | посторонний | Негативный: включение без сессии администратора — отказ | авто (api) |
| ADM-06 | администратор | Граничный: включение уже активной — без 500, состояние «активна» | авто (api) |
| ADM-07 | администратор | Негативный: создание второй учётки с той же почтой — отказ 4xx (409/400/422), в списке одна учётка | авто (api) |
| ADM-07 | администратор | Негативный: та же почта в другом регистре (`User@x` vs `user@x`) — отклоняется либо различается; поведение фиксируется, при расхождении с «тем же адресом» — вопрос владельцу | авто (api) |
| ADM-07 | администратор | Негативный: изменение почты существующей учётки на почту другой — отказ, обе учётки без изменений | авто (api) |
| ADM-07 | администратор | Граничный: изменение почты учётки на её же почту — не отказ; после смены почты старая почта свободна для новой учётки | авто (api) |
| ADM-07 | администратор | Граничный: параллельное создание двух учёток с одной почтой — создаётся ровно одна, вторая 4xx (не 500) | авто (api) |
| ADM-07 | администратор | UI: при дубликате почты форма показывает ошибку, список не меняется | авто (e2e) |
| ARCH-ADM-01 | администратор | Cookie сессии администратора: `HttpOnly`, `SameSite=Lax`, без `Secure` при `http://` в `PUBLIC_BASE_URL`; `document.cookie` её не видит | авто (api + e2e) |
| ARCH-ADM-02 | администратор | Идентификатор сессии случайный: две сессии подряд дают разные значения достаточной длины (≥ 16 байт энтропии по длине), не содержат почту или id | авто (api) |
| ARCH-ADM-03 | посторонний | Частые попытки входа в панель с одного адреса ограничиваются (после серии неверных попыток — 429 или отказ даже с верным паролем); ограничение не ломает первый верный вход | авто (api) |
| ARCH-ADM-04 | посторонний | Маршруты `/admin/login`, `/admin/users` отдают SPA и запрещают показ во фрейме (регрессия ARCH-FRAME) | авто (регрессия) |
| ARCH-ADM-05 | посторонний | Клиент обращается к API по адресу страницы (`/api/...`), в собранной статике нет `localhost` (регрессия ARCH-WEBNET с HTTP-клиентом) | авто (регрессия + e2e перехват сети) |
| ARCH-ADM-06 | посторонний | Строки интерфейса панели — по-английски (нет кириллицы в видимом тексте, кроме введённых данных) | авто (e2e) |
| ARCH-ADM-07 | посторонний | Контракты панели опубликованы в `/api/openapi.json` | авто (api) |
