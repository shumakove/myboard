# T5.5 · QA-отчёт

Требования: CVS-08, SHR-07; попутно — UI-01…UI-04 для новых элементов (панель поиска, пункт/диалог «Copy link to object»); регрессия всего `acceptance/`
Коммит сценариев: (см. коммит «T5.5: Зафиксировать сценарии приёмки» в `main`, до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (CVS-08, SHR-05, SHR-06, SHR-07, UI-01…UI-04), `ARCHITECTURE.md` (раздел 4: маршрут `/b/{token}?object={id}`, «Поиск по доске идёт по тексту уже загруженного документа на клиенте (CVS-08)»; раздел 5 «Ссылка»: «Ссылка на объект — тот же токен плюс идентификатор объекта. Клиент после загрузки документа двигает камеру к нему (SHR-07)», «отозванный и несуществующий токен неразличимы») и блоку «Тестирование» T5.5 в `PLAN.md`. Из постановки запуска учтено: интерфейса тегов ещё нет (T6.2/T6.8), формат тегов — поле `tags` объекта (массив строк без «#»), документ для поиска по тегам наполняется через Yjs. До чтения handoff и кода. В `docs/questions.md` вопросов по T5.5 нет.

Роли: **пользователь досок** (владелец, `/boards/{id}`), **участник по ссылке** (`/b/{token}`, на холсте те же права — поиск и копирование ссылки на объект есть и у него), **посторонний** (без сессии, с отозванным или выдуманным токеном), **администратор** — не затрагивается. Ссылка на объект проверяется в двух независимых клиентах: кто копирует и кто открывает.

Границы толкования (фиксирую до чтения handoff):

- **CVS-08** «искать по тексту объектов на доске, включая теги, и переходить к найденному»: поиск находит объект по подстроке его текста без учёта регистра; по тегу (значение тега, с «#» и без); показывает все совпадения (список или счётчик с переходом «следующий/предыдущий»); выбор результата двигает камеру так, что объект оказывается в видимой области (центр объекта внутри окна холста), желательно с выделением/подсветкой. Поиск клиентский: при вводе нет запросов к `/api` по тексту поиска (наблюдаемое решение архитектуры). Негативный: строка без совпадений — понятное «ничего не найдено», камера не двигается; объекты в корзине (`trash`) в результатах не показываются. Граничные: пустая строка — нет результатов/список закрыт, ничего не ломается; спецсимволы регулярных выражений (`.*(`) ищутся как текст; кириллица и регистр; объект далеко за пределами вида (например, x = 20000) — камера переходит к нему; объект, добавленный другим клиентом после открытия доски, находится без перезагрузки; объект, удалённый другим клиентом, пропадает из результатов. Вложенный объект (координаты относительно родителя) — если на доске уже есть родительские объекты; иначе наблюдение. Открытие поиска клавишей (Ctrl/Cmd+F) — наблюдение, не FAIL. Ввод в поле поиска не переключает инструменты и не удаляет объекты (CVS-25 регрессия).
- **SHR-07** «скопировать ссылку на конкретный объект доски. Человек с действующей ссылкой на доску переходит по ней к этому объекту»: у выделенного объекта (контекстное меню/панель выделения) есть действие «Copy link to object»; скопированная ссылка имеет вид `{PUBLIC_BASE_URL}/b/{token}?object={id}` — с действующим токеном доски, адрес из `PUBLIC_BASE_URL`, без `localhost`; у владельца, у которого ссылка ещё не создана, — ссылка создаётся или показывается понятное объяснение (наблюдение; без токена ссылка на объект невозможна). Открытие ссылки в новом клиенте: запрос имени (SHR-03), затем холст, и камера переходит к объекту (центр в видимой области) даже если сохранённое место камеры (CVS-05) в этом браузере другое; объект выделен/подсвечен — наблюдение. Тот же переход — у участника, у которого уже есть сессия доски (имя не спрашивается повторно). Негативные: после сброса ссылки (SHR-06) старая ссылка на объект даёт тот же отказ, что и любая отозванная ссылка (SHR-05), без раскрытия существования доски и объекта; выдуманный токен с `?object=` — тот же отказ; посторонний без сессии не видит холст. Граничные: `?object=` с несуществующим id или id удалённого (в корзине) объекта — доска открывается, показывается сообщение, что объект не найден, камера не прыгает в «никуда»; пустой `?object=` — доска открывается обычно; id со спецсимволами (`<script>`, `%00`) — без ошибок и без исполнения; объект далеко от начала координат — переход есть. Владелец, открывший ссылку `/b/{token}?object=` в своей сессии, — попадает к объекту (наблюдение по тому, как владелец входит по ссылке; минимум — открывает свою доску `/boards/{id}` с тем же переходом, если такая форма есть). Скопированная ссылка после сброса ссылки доски (новый токен) — новая копия содержит новый токен.
- **Архитектура**: маршрут `/b/{token}?object={id}` (раздел 4); страница `/b/{token}?object=` запрещает показ во фрейме, как и `/b/{token}`; в клиентском бандле нет `localhost`; поиск не ходит на сервер.
- **UI-01…UI-04** для новых элементов: поле поиска и список результатов — в плавающей панели в общем стиле (белый фон, скругление, тень); текст и рамки — строго серые R = G = B или акцент; кнопки и поле — общие компоненты с состояниями наведения, фокуса с клавиатуры; на телефоне поиск доступен, цели ≥ 44×44, панель не выходит за ширину экрана; сообщение «объект не найден» — в общем стиле (тост/баннер), закрывается. Диалоги/панели закрываются Escape.
- **Регрессия**: весь `acceptance/` (api + e2e desktop + mobile) без ослабления.
