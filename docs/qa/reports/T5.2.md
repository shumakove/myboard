Способ наблюдения (только публичные интерфейсы):

- **Документ доски** — независимый WebSocket-клиент (`pycrdt`, как в T4.x/T5.1) и/или второй контекст браузера: после действия в первом клиенте объект появляется/меняется/исчезает в `objects` у второго; поздний клиент получает то же состояние (сохранено сервером).
- **Холст** — DOM-элементы объектов в слое камеры, их экранные прямоугольники; зонд «экран → мир» по кадрам `awareness` (T5.1, `acceptance/e2e/camera.ts`) — для пересчёта экранных сдвигов в мировые.
- **Выделение** — видимый признак выделения в интерфейсе и/или `awareness` (что именно — узнаю из handoff); выделение не пишет в документ.

Роли: **владелец (пользователь досок)**; **участник по ссылке** — на холсте те же действия, что у владельца (SHR-04): создание, выделение, перемещение, размер/поворот, удаление, меню; **второй клиент** (второй контекст браузера или WS-клиент) — видит результат каждого действия (объекты общие); **посторонний** — холст чужой доски не получает (регрессия). Администратор досок не ведёт — отдельной роли нет.

Границы толкования (фиксирую до чтения handoff):

- **CVS-06** «сменить фон доски и шаг сетки»: в интерфейсе доски есть выбор фона (минимум два варианта, например цвет/узор или «без сетки») и шага сетки (минимум два значения). Смена видна сразу (вычисленный стиль фона холста / шаг узора меняется), сохраняется после перезагрузки и видна второму клиенту — это свойство доски, а не браузера (формулировка «фон доски»). Шаг сетки виден на экране с учётом масштаба (при приближении шаг на экране растёт). Негатив: недопустимое значение шага (0, отрицательное, нечисло — если поле свободного ввода) не применяется и не ломает холст. Участник по ссылке видит фон и сетку владельца; может ли участник их менять — SHR-04 перечисляет действия с объектами, фон в списке нет: фиксирую как наблюдение, не вердикт. Смена фона не меняет объекты.
- **CVS-09** создание тремя способами: (1) инструмент с панели — выбрать инструмент, щелчок (или протяжка) по холсту создаёт объект в этой точке мира (с учётом камеры: проверяю при масштабе ≠ 100 % и сдвиге); (2) перетаскивание кнопки инструмента с панели на холст — объект появляется в точке отпускания; (3) вставка из буфера (Ctrl/Cmd+V) — содержимое системного буфера (как минимум текст) становится объектом на холсте (в видимой области, обычно у курсора или в центре). Каждый созданный объект — в `objects` с `type`, целым `z`, координатами; новый объект выше существующих по `z`. Негатив: перетаскивание, отпущенное вне холста (обратно на панель), объект не создаёт; Ctrl+V при фокусе в поле ввода объект не создаёт; пустой буфер — ничего не создаёт и ошибок нет. Граничный: создание далеко от начала координат (после ухода камеры на 10⁶) и при сильном отдалении — координаты конечны и соответствуют точке на экране. Второй клиент видит созданный объект. Участник по ссылке создаёт так же.
- **CVS-10**: щелчок по объекту выделяет его (и снимает выделение с прежнего); щелчок по пустому месту снимает выделение. Рамка (протяжка по пустому холсту в режиме выделения) выделяет объекты внутри рамки и не выделяет объекты вне её. Лассо — отдельный режим/инструмент: произвольный контур выделяет объекты внутри контура и **не** выделяет объект, который лежит внутри описанного прямоугольника контура, но вне самого контура (L-образное или треугольное лассо) — так лассо отличается от рамки. Граничный: объект, частично пересекающий рамку, — правило (полное вхождение или пересечение) любое, но последовательное; фиксирую как наблюдение. Протяжка по пустому холсту в режиме выделения не двигает камеру (иначе — двигает камеру, а рамка включается инструментом/модификатором: устройство узнаю из handoff, требование лишь требует, чтобы рамка была). Выделение не порождает кадров `sync` (не пишется в документ).
- **CVS-11**: при выделении объектов разных типов (например, стикеры + фигура) интерфейс даёт оставить в выделении только объекты одного типа (по выбору типа); после фильтра выделены ровно объекты этого типа. Изменение свойства (цвет) при выделении нескольких объектов применяется ко всем выделенным разом (одно действие) и не меняет невыделенные; второй клиент видит новый цвет у всех. Граничный: 3+ объекта одного типа + 2 другого; после фильтра изменение не задевает отфильтрованные. Негатив: при однотипном выделении изменение тоже применяется ко всем (массовое изменение — не только после фильтра).
- **CVS-12**: перетаскивание выделенного объекта двигает его на величину жеста в мировых единицах (экранный сдвиг / масштаб); перетаскивание нескольких выделенных двигает все вместе с сохранением взаимного положения. С Shift объект идёт только по одной оси (доминирующей): у второй координаты приращение 0. Прилипание: без модификатора конечное положение прилипает (к сетке с шагом из CVS-06 или к соседним объектам/направляющим — что именно, узнаю из handoff); с отдельной клавишей-модификатором (не Shift) при том же жесте конечное положение равно точному сдвигу жеста (без округления к сетке). Если прилипания нет вообще, вторая часть требования не выполняется — FAIL. Граничный: Shift при жесте почти по диагонали — всё равно одна ось; Shift + модификатор вместе — ось и без прилипания. Второй клиент видит новое положение; поздний клиент — тоже.
- **CVS-13**: если тянуть объект к краю видимой области холста и держать у края, вид сдвигается в сторону края (зонд камеры), а объект продолжает двигаться в мире вместе с указателем (его мировая координата уходит за пределы исходного вида). Негатив: перетаскивание объекта в середине холста камеру не двигает; у края без перетаскивания объекта (просто курсор у края) камера не двигается. Граничный: у каждой из четырёх сторон — в свою сторону; после отпускания автопрокрутка прекращается.
- **CVS-14**: у выделенного объекта есть маркеры размера; протяжка маркера меняет ширину/высоту в документе на величину жеста (с учётом масштаба). Поворот: у типов, для которых поворот предусмотрен (по типам T5.2 — узнаю из handoff), есть маркер поворота; протяжка меняет угол в документе; у типов без поворота маркера нет. Граничный: уменьшение до нуля и через ноль не даёт нулевой/отрицательной ширины (минимальный размер или отражение — без NaN/отрицательных значений); поворот на ≥ 360° не ломает значения. Второй клиент видит размер и угол.
- **CVS-21**: клавиша Delete (и/или Backspace) удаляет все выделенные объекты — они исчезают из `objects` у второго клиента и с холста, невыделенные остаются; удаление из контекстного меню объекта — то же. Негатив: Delete/Backspace при фокусе в поле ввода объекты не удаляет; при пустом выделении ничего не удаляется. Граничный: удаление нескольких объектов одним действием. По `ARCHITECTURE.md` удалённый объект переносится в `trash` — фиксирую наблюдение (`trash` у WS-клиента); вердикт по переносу в корзину — в задаче T5.3/T8.2 (COL-08), по указанию владельца.
- **CVS-23**: правый щелчок по объекту открывает меню объекта (с действиями над объектом, минимум «удалить»); правый щелчок по пустому месту открывает меню холста — другое по составу (без действий над объектом; например, вставка, выделить всё, фон). Действие из меню выполняется (удаление из меню объекта удаляет объект). Меню закрывается по Escape и щелчку мимо. Системное меню браузера на холсте не показывается. Граничный: правый щелчок по невыделенному объекту при выделенном другом — меню относится к объекту под указателем (его выделение); меню у края экрана целиком в окне. На телефоне — наблюдение, как открыть меню (требование способ не задаёт).
- **MOB-03** (профиль mobile, `hasTouch`): короткое движение одним пальцем (касание и сразу сдвиг) — по пустому месту и по объекту — двигает вид (зонд камеры) и не выделяет/не двигает объект (документ не меняется). Долгое нажатие (≥ ~0,5 с без движения) начинает выделение: по объекту — объект выделен; по пустому месту — после долгого нажатия протяжка рисует рамку/выделяет объекты, а вид не двигается. Граничный: движение раньше порога долгого нажатия — сдвиг вида; простое касание без удержания не двигает вид. После выделения долгим нажатием палец двигает выделенный объект (наблюдение).
- **Совместная правка (COL-01, замечание владельца)**: два клиента одновременно меняют разные свойства одного объекта (один двигает, другой меняет цвет/размер) — у обоих итог содержит обе правки. Если у объектов T5.2 есть текст, одновременный ввод в один текст двумя клиентами сливается (оба фрагмента сохраняются, Y.Text), а не «последний победил». Если текста у объектов в T5.2 нет — проверка переносится в T6.1 (фиксирую в отчёте).
- Доступ: все действия выполняет и участник по ссылке; посторонний не получает холст (регрессия).
