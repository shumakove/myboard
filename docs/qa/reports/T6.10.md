# T6.10 · QA-отчёт

Требования: CMT-01…CMT-04; попутно — MOB-01 (комментарии на ширине телефона), COL-01/realtime (комментарии видны второму клиенту), SHR-04 (участник по ссылке комментирует); регрессия всего `acceptance/`
Коммит сценариев: <заполняется после коммита>

Сценарии составлены только по `REQUIREMENTS.md` (CMT-01…04, MOB-01, SHR-03/04), `ARCHITECTURE.md` (раздел 5: участник по ссылке комментирует; раздел 6: `comments` — Y.Map `id -> ветка комментария`, комментарий хранит привязку к объекту или к точке холста, сообщения, цвет и признак «решён»; присутствие в документ не входит) и блоку «Тестирование» T6.10 в `PLAN.md` («комментарий следует за объектом; непрочитанные отмечаются у второго участника; фильтр по имени участника по ссылке»; в «Разработке» — «непрочитанные (локально для участника)»). До чтения handoff, `docs/decisions.md` ветки DEV и кода.

Роли: **пользователь досок** (владелец, `/boards/{id}`), **участник по ссылке** (`/b/{token}`, имя из SHR-03 — автор комментариев и ответов), **посторонний** (без сессии документ, а значит и комментарии, не получает — регрессия `realtime`), **администратор** — не затрагивается. Совместная работа — минимум два независимых клиента.

Границы толкования (фиксирую до чтения handoff):

- **CMT-01** «прикреплять комментарий к объекту и к точке холста»: комментарий к объекту (стикер/фигура) — метка у объекта; при перемещении объекта метка едет вместе с ним (у себя, у второго клиента, после перезагрузки). Комментарий к точке пустого холста остаётся в этой точке холста (при сдвиге/масштабе камеры — вместе с холстом, а не с экраном). Оба вида видны второму клиенту и после перезагрузки. Негативный: пустой комментарий не создаётся; браузерных диалогов нет. Граничный: удаление объекта с комментарием — наблюдение (комментарий скрыт/удалён/остаётся в точке — главное, интерфейс не ломается); восстановление объекта Ctrl+Z — наблюдение; комментарий к объекту внутри фрейма едет с фреймом (наблюдение).
- **CMT-02** «вести в комментарии переписку, отмечать его решённым и показывать непрочитанные»: в ветку добавляются ответы; каждое сообщение показывает автора (имя пользователя досок / имя участника по ссылке) и порядок; ответы видны второму клиенту и после перезагрузки. «Решён»: отметка видна второму клиенту и после перезагрузки; решённая ветка визуально отличается или скрывается из обычного списка, её можно снова открыть (reopen) — наблюдение, но отметка обязана сниматься или ветка должна оставаться доступной. Непрочитанные: новый комментарий/ответ одного участника отмечается у второго участника как непрочитанный (метка/счётчик); после открытия ветки вторым участником отметка снимается; собственные сообщения автору непрочитанными не показываются. Граничный: отметка «прочитано» у одного участника не снимает непрочитанное у другого (локальность для участника, по PLAN); после перезагрузки прочитанное остаётся прочитанным (наблюдение — допустимо хранение на клиенте). Пустой ответ не отправляется.
- **CMT-03** «задавать цвет комментария»: у ветки выбирается цвет из набора; цвет метки меняется у себя, второго клиента и после перезагрузки; разные комментарии могут иметь разные цвета. Граничный: цвет по умолчанию у нового комментария есть.
- **CMT-04** «фильтровать комментарии по участникам обсуждения»: фильтр показывает список участников обсуждений (включая участника по ссылке по его имени); выбор участника оставляет только ветки, где он писал (автор или ответ), остальные скрыты; снятие фильтра возвращает все. Граничный: ветка, где участник только ответил, попадает в фильтр по нему (наблюдение, «участники обсуждения»); фильтр по двум участникам — наблюдение.
- **Попутно**: MOB-01 — на ширине телефона панель комментариев помещается в экран (без горизонтальной прокрутки), комментарий ставится касанием; SHR-04 — участник по ссылке создаёт, отвечает, решает и красит комментарии.
- **Архитектура**: комментарии — записи `comments` в документе Yjs (видно независимым WS-клиентом), в `objects` не попадают; запись хранит привязку (объект или точка), сообщения, цвет и «решён»; правки комментариев идут через WS `sync`, без изменяющих HTTP-запросов к `/api`; имя автора участника по ссылке совпадает с именем сессии; нет `localhost` в клиенте (регрессия `web.spec.ts`); посторонний без сессии документ не получает (регрессия `realtime`).

| CMT-01 | пользователь досок + 2-й клиент | Комментарий к стикеру: метка у объекта; перемещение стикера двигает метку у себя, второго клиента и после перезагрузки | авто (e2e, 2 клиента) |
| CMT-01 | пользователь досок + 2-й клиент | Комментарий к точке пустого холста: остаётся в той же точке холста после сдвига и масштаба камеры; виден второму клиенту и после перезагрузки | авто (e2e, 2 клиента) |
| CMT-01 | участник по ссылке + владелец | Участник прикрепляет комментарий к объекту владельца — владелец видит его у объекта | авто (e2e, 2 клиента) |
| CMT-01 | пользователь досок | Негативные/граничные: пустой комментарий не создаётся; нет браузерных диалогов; удаление объекта с комментарием и Ctrl+Z — наблюдение | авто (e2e) |
| CMT-02 | владелец + участник по ссылке | Переписка: ответы обоих в одной ветке с именами авторов и в порядке — у обоих и после перезагрузки; пустой ответ не отправляется | авто (e2e, 2 клиента) |
| CMT-02 | владелец + участник по ссылке | «Решён»: отметка видна второму клиенту и после перезагрузки; ветку можно открыть снова | авто (e2e, 2 клиента) |
| CMT-02 | владелец + участник по ссылке | Непрочитанные: новый комментарий и новый ответ одного отмечены у второго; открытие ветки снимает отметку; свои сообщения не отмечены; прочтение одним не снимает отметку у другого | авто (e2e, 2–3 клиента) |
| CMT-03 | пользователь досок + 2-й клиент | Цвет ветки: выбор из набора меняет цвет метки у себя, второго клиента и после перезагрузки; у нового комментария есть цвет по умолчанию; разные ветки — разные цвета | авто (e2e, 2 клиента) |
| CMT-03 | участник по ссылке | Участник меняет цвет комментария — владелец видит | авто (e2e, 2 клиента) |
| CMT-04 | владелец + участник по ссылке | Фильтр по имени участника по ссылке оставляет только ветки, где он писал (автор и ответ), снятие фильтра возвращает все; фильтр по владельцу | авто (e2e, 2 клиента) |
| MOB-01 (попутно) | пользователь досок на телефоне | Комментарий ставится касанием; панель ветки в пределах ширины экрана, ответ отправляется | авто (e2e, mobile) |
| ARCH | пользователь досок | Комментарии — записи `comments` (привязка, сообщения, цвет, «решён»), не в `objects` (независимый WS-клиент); правки без изменяющих HTTP к `/api`; автор участника — имя сессии | авто (e2e + WS) |
| ARCH | посторонний | Без сессии документ доски не отдаётся (регрессия realtime); нет `localhost` (регрессия web) | авто (регрессия) |
