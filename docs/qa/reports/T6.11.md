# T6.11 · QA-отчёт

Требования: RCT-01…RCT-04, FLP-01…FLP-03, DICE-01…DICE-03; попутно — COL-01/realtime (два клиента), SHR-04 (участник по ссылке), MOB-01 (ширина телефона); регрессия всего `acceptance/`
Коммит сценариев: (см. коммит «T6.11: Зафиксировать сценарии приёмки» в `main`, до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (RCT-*, FLP-*, DICE-*), `ARCHITECTURE.md` (раздел 6: реакция, флип-карточка и кубик — объекты сцены в `objects`, JSON с `type`; раздел 6 «Файлы»: файлы хранятся в `MEDIA_ROOT/{board_id}/{media_id}`, отдаются по `/api/media/{id}`, лимит `MAX_UPLOAD_BYTES`; раздел 9: ZIP — `board.yjs` + `media/` с файлами, на которые ссылается документ) и блоку «Тестирование» T6.11 в `PLAN.md` («реакция едет с объектом; кубик выдаёт значения только в диапазоне граней (много бросков); сумма нескольких кубиков верна; одновременный бросок с двух клиентов даёт согласованное значение у обоих»). До чтения handoff, `docs/decisions.md` ветки DEV и кода. Вопрос Q-006 (DEV) прочитан в `docs/questions.md` — он в `main`.

Роли: **пользователь досок** (владелец, `/boards/{id}`), **участник по ссылке** (`/b/{token}`, имя из SHR-03 — автор реакции для RCT-02), **посторонний** (без сессии документ не получает — регрессия `realtime`), **администратор** — не затрагивается. Совместная работа — минимум два независимых клиента.

Границы толкования (фиксирую до чтения handoff):

- **RCT-01** «ставить реакцию-штамп на объект; реакция держится на объекте при его перемещении»: реакция ставится на объект (стикер/фигуру); при перемещении объекта реакция едет вместе с ним, сохраняя положение относительно объекта (у себя, у второго клиента, после перезагрузки). Негативный: удаление объекта — реакция не остаётся висеть в пустоте (наблюдение). Граничный: несколько реакций на одном объекте; реакция на объекте внутри фрейма едет при перемещении фрейма (наблюдение). Постановка реакции на пустой холст требование не описывает — допустимо как запрет, так и разрешение (наблюдение, не FAIL).
- **RCT-02** «по наведению на реакцию показывать, кто её поставил»: наведение показывает имя автора — имя пользователя досок / имя участника по ссылке из сессии; второй клиент, наводя на чужую реакцию, видит имя автора, а не своё.
- **RCT-03** «увеличивать реакцию, пока удерживается кнопка мыши или палец»: при удержании (мышь, на телефоне — касание) размер реакции растёт со временем; отпускание прекращает рост; итоговый размер больше начального и сохраняется (у второго клиента, после перезагрузки). Граничный: короткий щелчок ставит реакцию обычного размера; рост ограничен сверху (наблюдение).
- **RCT-04** «наборы изображений для реакций и недавние использованные»: в выборе реакции — больше одного набора изображений (переключение наборов); использованная реакция появляется в «недавних» первой; повтор не дублирует; список недавних ограничен (наблюдение).
- **FLP-01** «флип-карточка с лицевой и оборотной стороной, картинкой на стороне и направлением переворота»: создаётся карточка; лицевая и оборотная стороны имеют разный текст; на сторону ставится картинка (видна на этой стороне, не на другой); задаётся направление переворота (минимум по горизонтали и по вертикали) — переворот визуально идёт в выбранном направлении. Всё видно второму клиенту и после перезагрузки. Архитектура: картинка — это файл изображения; по разделу 6 «Файлы» файлы лежат в `MEDIA_ROOT`, отдаются по `/api/media/{id}` только сессии этой доски и ограничены `MAX_UPLOAD_BYTES`. Если картинка стороны хранится иначе — фиксирую как расхождение с наблюдаемым решением архитектуры (связано с Q-006).
- **FLP-02** «переворачивать одну карточку и все выделенные карточки разом»: переворот одной карточки показывает другую сторону; при выделении нескольких карточек одна команда переворачивает все; переворот виден второму клиенту и после перезагрузки. Граничный: в выделении есть не-карточки — они не меняются; выделены карточки в разных состояниях (лицо/оборот) — наблюдение (каждая переворачивается или все приводятся к одной стороне).
- **FLP-03** «задавать на стороне карточки размер и форматирование текста»: на каждой стороне задаётся размер шрифта и форматирование (минимум жирный/курсив); настройки стороны независимы (лицо и оборот разные); видно второму клиенту и после перезагрузки.
- **DICE-01** «кубик с числом граней 4, 6, 8, 10, 12 или 20 и цветом»: создаётся кубик; доступны ровно эти шесть вариантов граней; цвет меняется; видно второму клиенту и после перезагрузки. Негативный: других чисел граней интерфейс не предлагает.
- **DICE-02** «бросать кубик и показывать выпавшее значение»: бросок показывает значение; при многих бросках (≥ 100 для d4/d6, ≥ 200 для d20) все значения в диапазоне 1…N, встречаются и 1, и N (минимум и максимум достижимы — наблюдение для d20). Значение одинаковое у бросившего, второго клиента и после перезагрузки. Одновременный бросок с двух клиентов — у обоих в итоге одно и то же значение.
- **DICE-03** «для нескольких выделенных кубиков показывать сумму последних значений»: при выделении ≥ 2 кубиков видна сумма последних значений; после повторного броска одного сумма пересчитывается; сумма верна (сверка со значениями на кубиках). Граничный: один выделенный кубик — сумма не обязательна (наблюдение); в выделении есть не-кубики — сумма только по кубикам.
- **Попутно**: SHR-04 — участник по ссылке ставит реакцию, переворачивает карточку, бросает кубик; MOB-01 — реакции, переворот и бросок доступны касанием на ширине телефона, рост реакции при удержании пальца (RCT-03).
- **Архитектура**: реакция, флип-карточка, кубик — записи `objects` с `type` (видно независимым WS-клиентом); изменения идут через WS `sync`, без изменяющих HTTP-запросов к `/api`; файл картинки стороны — `media` (см. выше); нет `localhost` в клиенте (регрессия `web.spec.ts`); посторонний без сессии документ не получает (регрессия `realtime`).
