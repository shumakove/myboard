Роли:

- **владелец (пользователь досок A)** — открывает доску, его курсор и имя видят остальные;
- **участник по ссылке** — вошёл по `/b/{token}` с введённым именем; видит владельца и других, его видят под введённым именем (SHR-04: те же права на холсте);
- **второй участник по ссылке** — третий клиент для проверки «многих» и одинаковых имён;
- **пользователь досок B / администратор / посторонний** — канала доски нет, поэтому ни их присутствия, ни чужих курсоров они не получают;
- **участник с отозванной cookie** — после сброса ссылки пропадает из присутствия у остальных (SHR-06 + COL-09).

Границы толкования (фиксирую до чтения handoff):

- COL-02 «курсоры и имена **других** участников»: у наблюдателя на холсте появляется курсор другого клиента с подписью-именем; позиция курсора следует за перемещением мыши/пальца другого клиента (в координатах доски — при одинаковой камере курсор оказывается в той же точке холста). Свой курсор как «чужой» не дублируется. Имя владельца — имя его учётной записи (как в панели), имя участника — введённое при входе по ссылке.
- Подмена имени: имя, которое видят другие в списке присутствующих, не должно произвольно задаваться клиентом в обход сессии (участник не может появиться под именем владельца, просто отправив другое имя в `awareness`). Требование прямо этого не называет — при подмене завожу баг безопасности по модели доступа (имя хранится в сессионной cookie доски), серьёзность решаю по факту; если подмена возможна только в подписи курсора, а не в списке — замечание.
- Пропадание «вместе с соединением»: закрытие вкладки/сокета — курсор и строка в списке исчезают у остальных за ≤ 5 с; обрыв без закрытия (сокет убит) — за разумный срок таймаута (≤ 60 с, фиксирую фактическое значение).
- COL-03: переключатель скрывает все чужие курсоры только у этого клиента; повторное нажатие показывает снова; курсоры, появившиеся, пока скрыто, тоже скрыты; другие клиенты продолжают видеть курсоры; список присутствующих (COL-09) от скрытия курсоров не зависит.
- COL-04: наблюдатель выбирает участника (из списка присутствующих) и его вид (сдвиг и масштаб камеры) повторяет перемещения ведомого; после выключения перемещения ведомого вид наблюдателя больше не двигают. Если ведомый ушёл — слежение прекращается без ошибки. Себя выбрать для слежения нельзя (или выбор ничего не делает). Работает в обе стороны (участник следит за владельцем и наоборот) и в профиле mobile. Камера в T4.2 — минимальная (перемещение/масштаб), полная — T5.1; собственное перемещение вида наблюдателем выключает слежение — это один из способов «выключить наблюдение», не противоречит требованию.
- COL-09: список присутствующих показывает всех подключённых к доске (как минимум других; себя — отмечаю фактическое поведение), обновляется при входе и уходе без перезагрузки; одинаковые имена двух участников — две записи; изоляция досок — присутствие доски X не видно на доске Y.
- Протокол (ARCH-T42-01): на том же `/api/ws` идут кадры `awareness` и `presence`; `presence` — от сервера; кадр `presence`/мусорный `awareness` от клиента не меняет список присутствующих у других и не ломает их соединения; `awareness` доски X не приходит клиентам доски Y; кадр `awareness` больше не закрывает соединение как незнакомый (было в T4.1).
- ARCH-T42-02 «не в документе»: после обмена `awareness` состояние документа (`sync` позднего клиента) не содержит курсоров, имён, присутствия; кадры `awareness` не меняют `boards.updated_at` («недавние»). Проверка через снимок `board_snapshots` и ZIP — отложена до T4.3/T10.1.
- Доступ: посторонний/пользователь B/администратор не получают `awareness`/`presence` доски (канал не открывается — регрессия ARCH-T41-01); после сброса ссылки участник по старой ссылке исчезает из присутствия у владельца.
