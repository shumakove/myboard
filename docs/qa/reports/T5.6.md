Сценарии составлены только по `REQUIREMENTS.md` (раздел 11, UI-01…04; контекст — MOB-03, CVS-20), `ARCHITECTURE.md` (раздел 4: маршруты интерфейса, строки по-английски; раздел 12: фрейм только для `/b/{token}/embed`), блоку «Тестирование» T5.6 в `PLAN.md`, файлам BUG-007/BUG-008 и решению владельца, переданному при запуске: стиль светлый «как в Miro» без чужих логотипов, палитра + базовые компоненты, тёмной темы нет; BUG-007, BUG-008 и синтаксис Mermaid чинятся в T5.6. До чтения handoff и кода. `docs/questions.md` по T5.6 вопросов не содержит.

Способ наблюдения (только публичные интерфейсы): вычисленные стили (`getComputedStyle`) видимых элементов в браузере, скриншоты экранов, эмуляция `prefers-color-scheme: dark`, клавиатура (Tab) для фокуса, `hover`/нажатие мышью, hit-test (`elementFromPoint`) для области нажатия на телефоне; документ доски — независимый WS-клиент/второй контекст (BUG-008); схемы `uml/` — `mermaid.parse` в браузере.

Экраны (UI-02): `/login`, `/admin/login`, `/admin/users`, `/` (список досок и папки), `/b/{token}` (запрос имени), отказ по неверной ссылке, `/boards/{id}` (холст владельца), `/b/{token}` (холст участника), `/b/{token}/embed`.

Роли: **администратор** (админка), **пользователь досок** (вход, список, холст), **участник по ссылке** (запрос имени, холст, встроенная доска), **посторонний** (страница входа, отказ по неверной/отозванной ссылке — тоже экран в общем стиле). Требования раздела 11 не про доступ; роли нужны, чтобы увидеть все экраны.

Границы толкования (фиксирую до чтения handoff):

- **UI-01** «светлый фон»: фон `body`/страницы и фон холста — светлые (относительная яркость ≥ 0,85). «Белые плавающие панели со скруглёнными углами и мягкой тенью поверх холста»: каждая панель на холсте (инструменты, камера/масштаб, миникарта, панель выделения, присутствие, шапка доски, если она плавает) — фон `rgb(255,255,255)`, `border-radius` > 0, `box-shadow` не `none`; на прочих экранах — карточки/формы белые со скруглением. «Один акцентный цвет для основных и активных действий»: фон основных кнопок на всех экранах и выделение активного инструмента/активной вкладки — один и тот же цвет (точное совпадение RGB; оттенки наведения/нажатия — допустимы); других насыщенных цветов (насыщенность HSL > 0,25) в фоне/рамке кнопок, кроме акцента и цвета «опасного действия», нет. «Нейтральная серая шкала для текста и границ»: цвет текста и рамок элементов интерфейса (не объектов доски) — серые (|R−G|, |G−B|, |R−B| ≤ 16) или акцент/опасный. «Тёмной темы нет»: при эмуляции `prefers-color-scheme: dark` вычисленные цвета ключевых элементов и скриншот совпадают со светлым режимом; `color-scheme` страницы не `dark`. Логотипы: нет изображений/SVG/текста с названиями чужих продуктов (Miro и т. п.) — ручной осмотр скриншотов + поиск по DOM.
- **UI-02**: на всех экранах один `font-family` (у `body`, кнопок, полей ввода); один цвет фона страницы и основного текста; шкалы — множество различных значений по всем экранам ограничено: размеры шрифта элементов интерфейса ≤ 7 значений, `border-radius` (кроме кругов 50 %/≥ 999px и 0) ≤ 5, `box-shadow` (кроме `none`) ≤ 4, отступы `padding` — значения из одной шкалы (≤ 10 различных значений по всем элементам интерфейса). Объекты сцены (пользовательский контент) не учитываются. Встроенная доска выглядит так же, как доска.
- **UI-03**: кнопки одного вида (основная, второстепенная, опасная, кнопка-значок) на разных экранах имеют одинаковые вычисленные стили (фон, цвет, рамка, скругление, шрифт, высота, тень); поля ввода на всех экранах одинаковы; выпадающее меню (например, меню карточки доски в списке) и контекстное меню холста — одинаковый фон/скругление/тень/пункты; диалоги (переименование, подтверждения в интерфейсе, не браузерные `confirm`) одинаковы; плавающие панели инструментов на холсте одинаковы. Состояния: наведение меняет вид (фон/рамку/тень), нажатие (`:active`) меняет вид, фокус с клавиатуры (Tab) даёт видимое кольцо/обводку (`outline` или `box-shadow`, отличные от покоя), недоступность — отличный вид (прозрачность/цвет) и `cursor` не `pointer`, щелчок не срабатывает. Элементы, которых на экранах нет (если переключатели, подсказки, вкладки не используются), — сравнивать нечего; это фиксируется наблюдением, не FAIL. Нативные `title`-подсказки — наблюдение.
- **UI-04**: в профиле mobile на каждом экране каждый видимый элемент управления (`button`, `a[href]`, `input`, `select`, `textarea`, `[role=button|menuitem|tab|switch|checkbox]`, маркеры выделения) имеет область нажатия ≥ 44×44 px: hit-test в точках на расстоянии 21 px от центра по обеим осям (углы квадрата 44×44, обрезанного видимой областью экрана) попадает в сам элемент или его потомка, а не в соседа или холст. Визуальный размер может быть меньше (маркеры), но область нажатия — нет; соседний элемент, перекрывающий чужую область, — нарушение. Стиль на телефоне тот же: шрифт, акцент, фон панелей, скругление совпадают с desktop.
- **BUG-007** (MOB-03): на телефоне при выделенном объекте панель выделения не закрывает верх холста: долгое нажатие на пустом месте у верхнего края видимого холста (ниже шапки/панелей, не на самой панели) начинает выделение области. Исходный шаг бага — начало жеста у верхнего края холста, а не под панелью.
- **BUG-008** (CVS-20): копии объектов, записанных сторонним клиентом обычными JSON-значениями с `z`, при вставке получают `z` больше максимального на доске и ложатся поверх.
- **Mermaid**: каждый блок ` ```mermaid ` во всех файлах `uml/**/*.md` разбирается `mermaid.parse` без ошибок.
- **Регрессия**: все приёмочные тесты прежних задач (api, e2e desktop + mobile) проходят без ослабления. Тест, затрагивающий раскладку (позиции панелей), меняется только если он сам опирался на прежнюю раскладку, а не на требование — причина пишется в отчёте.
