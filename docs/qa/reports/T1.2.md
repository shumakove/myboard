# T1.2 · QA-отчёт

Требования: ACC-01, ACC-02, ACC-03; регрессия из T1.1: ADM-01, ADM-04, ADM-05, ADM-06
Коммит сценариев: 7422c67 (в `main` до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (разделы 2–4), `ARCHITECTURE.md` (разделы 4, 5, 7, 12), блоку «Тестирование» T1.2 в `PLAN.md` и списку переноса из `docs/qa/reports/T1.1.md`, до чтения handoff и кода. Дополнительные проверки архитектуры: `ARCH-ACC-*`.

Роли:

- **пользователь досок** — учётка, созданная администратором через API панели;
- **администратор** — учётка из `ADMIN_EMAIL`/`ADMIN_PASSWORD`;
- **посторонний** — клиент без cookie, с поддельной или отозванной cookie;
- **участник по ссылке** — ссылок ещё нет (T3.1); «сессия участника не открывает вход/список пользователя» — регрессия T3.1.

«Пользователь в системе» наблюдается снаружи как: API текущей сессии пользователя (эндпоинт из handoff) отвечает успехом, а страница `/login` / `/` в браузере показывает состояние вошедшего (переход с `/login` или доступ к `/`). Экран списка досок (ACC-04) — задача T2.1, здесь проверяется только, что вошедший попадает на `/`, а невошедший — на `/login`.
