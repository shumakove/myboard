# T1.2 · QA-отчёт

Требования: ACC-01, ACC-02, ACC-03; регрессия из T1.1: ADM-01, ADM-04, ADM-05, ADM-06
Коммит сценариев: см. коммит «T1.2: Зафиксировать сценарии приёмки до чтения handoff» в `main` (до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (разделы 2–4), `ARCHITECTURE.md` (разделы 4, 5, 7, 12), блоку «Тестирование» T1.2 в `PLAN.md` и списку переноса из `docs/qa/reports/T1.1.md`, до чтения handoff и кода. Дополнительные проверки архитектуры: `ARCH-ACC-*`.

Роли:

- **пользователь досок** — учётка, созданная администратором через API панели;
- **администратор** — учётка из `ADMIN_EMAIL`/`ADMIN_PASSWORD`;
- **посторонний** — клиент без cookie, с поддельной или отозванной cookie;
- **участник по ссылке** — ссылок ещё нет (T3.1); «сессия участника не открывает вход/список пользователя» — регрессия T3.1.

«Пользователь в системе» наблюдается снаружи как: API текущей сессии пользователя (эндпоинт из handoff) отвечает успехом, а страница `/login` / `/` в браузере показывает состояние вошедшего (переход с `/login` или доступ к `/`). Экран списка досок (ACC-04) — задача T2.1, здесь проверяется только, что вошедший попадает на `/`, а невошедший — на `/login`.

## Сценарии

| Требование | Роль | Сценарий | Тип (авто / ручной) |
| --- | --- | --- | --- |
| ACC-01 | пользователь досок | Позитивный: учётка создана администратором → вход по почте и паролю успешен, выдаётся cookie сессии; с ней API текущей сессии возвращает этого пользователя (имя/почта), без пароля и хэша | авто (api) |
| ACC-01 | пользователь досок | Позитивный (UI): `/login` — форма почты и пароля; после входа открывается `/` (не `/login`), видно состояние вошедшего | авто (e2e, desktop + mobile) + ручной (Claude in Chrome) |
| ACC-01 | пользователь досок | Граничный: почта в другом регистре и с пробелами по краям — вход проходит (почта — тот же адрес, ADM-07 считает их одинаковыми); пароль с кириллицей и пробелами — вход с тем же паролем проходит, с обрезанными пробелами — нет | авто (api) |
| ACC-01 | пользователь досок | Граничный: две учётки — каждая входит своими данными и получает свою сессию; сессия A не показывает данные B | авто (api) |
| ACC-01 | пользователь досок | Граничный: пустые поля, отсутствующие поля, не-JSON — отказ 4xx, не 500, cookie не выдаётся | авто (api) |
| ACC-01 | администратор | Негативный: почта и пароль администратора на входе пользователя досок — тот же отказ, что для неверных данных (администратор — отдельная учётка, ADM-01) | авто (api) |
| ACC-01 | пользователь досок | Негативный (регрессия ADM-01): сессия пользователя досок не открывает API панели (`/api/admin/*` — 401/403); сессия администратора не является сессией пользователя досок | авто (api) |
| ACC-02 | посторонний | Негативный: неизвестная почта, верная почта + неверный пароль, отключённая учётка с верным паролем — три ответа одинаковы: код, тело (текст) и отсутствие cookie сессии | авто (api) |
| ACC-02 | посторонний | Негативный (UI): на `/login` три случая показывают один и тот же текст ошибки, пользователь остаётся на `/login` | авто (e2e) |
| ACC-02 | посторонний | Граничный: частые попытки входа с одного адреса ограничиваются (серия неверных → 429 или отказ даже с верным паролем); первый верный вход и обычный повторный вход не ограничиваются; после окна вход снова работает | авто (api) |
| ACC-02 | посторонний | Граничный: лимит входа пользователя не должен давать различимого ответа для существующих и несуществующих почт (ограничение одинаково) | авто (api) |
| ACC-02 | пользователь досок | Негативный (регрессия ADM-05): после отключения уже выданная сессия пользователя не действует (API текущей сессии — 401), страница `/` уводит на `/login` | авто (api + e2e) |
| ACC-02 | пользователь досок | Позитивный (регрессия ADM-06): после включения вход с прежним паролем снова работает | авто (api + e2e) |
| ACC-02 | пользователь досок | Регрессия ADM-04: после смены пароля администратором вход с новым паролем проходит, со старым — отказ (тот же, что ACC-02); после смены почты вход по новой почте проходит, по старой — отказ | авто (api) |
| ACC-02 | пользователь досок | Граничный (регрессия ADM-04): сессия, выданная до смены пароля/почты, — поведение фиксируется в отчёте (требование её не отзывает) | авто (api, фиксация) |
| ACC-03 | пользователь досок | Позитивный: после входа закрыть браузер и открыть снова с сохранённым состоянием (новый контекст Playwright из `storageState`) — пользователь в системе, `/` открывается без входа | авто (e2e) |
| ACC-03 | пользователь досок | Позитивный: cookie сессии постоянная — у неё задан срок (`Expires`/`Max-Age`) далеко в будущем (≥ года) либо эквивалент, переживающий закрытие браузера; не сессионная cookie браузера | авто (api + e2e) |
| ACC-03 | пользователь досок | Позитивный: повторные визиты (много запросов одной cookie, перезапуск контейнера `api`) не выбивают из системы | авто (api) + перезапуск api |
| ACC-03 | пользователь досок | Негативный: после выхода та же cookie (в т.ч. скопированная заранее в другой клиент) не действует; после закрытия/открытия браузера пользователь не в системе | авто (api + e2e) |
| ACC-03 | пользователь досок | Граничный: выход в одной из двух сессий (два браузера) не выбивает вторую; повторный выход и выход без сессии — без 500 | авто (api) |
| ACC-03 | посторонний | Негативный: без cookie и с поддельной cookie API текущей сессии — 401; `/` в браузере ведёт на `/login` | авто (api + e2e) |
| ARCH-ACC-01 | пользователь досок | Cookie сессии пользователя: `HttpOnly`, `SameSite=Lax`, без `Secure` на `http://`; `document.cookie` её не видит | авто (api + e2e) |
| ARCH-ACC-02 | пользователь досок | Идентификатор сессии случайный: разные значения при двух входах, достаточной длины, без почты и id | авто (api) |
| ARCH-ACC-03 | посторонний | `/login` отдаёт SPA и запрещает показ во фрейме (регрессия ARCH-FRAME) | авто (api) |
| ARCH-ACC-04 | посторонний | Запросы страницы входа идут на адрес страницы (`/api/...`), без `localhost` | авто (e2e перехват сети) |
| ARCH-ACC-05 | посторонний | Строки интерфейса `/login` — по-английски | авто (e2e) |
| ARCH-ACC-06 | посторонний | Контракты входа, выхода и текущей сессии опубликованы в `/api/openapi.json` | авто (api) |
| ARCH-ACC-07 | пользователь досок | Mobile: `/login` без горизонтальной прокрутки, вход работает касаниями | авто (e2e mobile) |
