Границы толкования (фиксирую до чтения handoff):

- **IMG-01** «загружать изображение на доску и вставлять его из буфера»: загрузка файла с устройства (PNG, JPEG, GIF, WebP — минимум PNG и JPEG) создаёт объект изображения на холсте; вставка изображения из буфера обмена (Ctrl+V с картинкой) создаёт объект изображения. Файл уходит на сервер (`media`), в документе — ссылка на файл, а не данные файла. Изображение видно второму клиенту и после перезагрузки. Негативный: файл больше `MAX_UPLOAD_BYTES` отклонён (HTTP 413 или 4xx), на диске и в списке файлов не остаётся; файл не-изображения не превращается в изображение; подмена объявленного типа (`Content-Type: image/png` при содержимом HTML/скрипта, или `text/html`) не даёт отдать файл как исполняемую страницу. Граничный: файл ровно `MAX_UPLOAD_BYTES` принят, на 1 байт больше — отклонён; пустой файл (0 байт) — отказ или корректный объект (наблюдение).
- **IMG-02** «обрезать изображение, применять маску формы и скруглять углы»: обрезка — видимая область меньше исходной, сохраняется у второго клиента и после перезагрузки; маска формы (минимум круг и ещё одна форма) меняет видимый контур; скругление углов с регулируемым радиусом. Граничный: обрезка не может дать пустую область (наблюдение); маска и скругление сочетаются с обрезкой.
- **IMG-03** «задавать обводку изображения и отражать по горизонтали и вертикали»: обводка — цвет и толщина видны; отражение по горизонтали и по вертикали независимы, повторное отражение возвращает исходное; видно второму клиенту и после перезагрузки.
- **IMG-04** «заменять изображение другим с сохранением обрезки»: команда замены выбирает новый файл; объект остаётся тем же (id, позиция, размер), источник меняется на новый файл; параметры обрезки (и маска/скругление/обводка — наблюдение) сохраняются. Граничный: замена на файл больше лимита — отказ, старое изображение остаётся.
- **IMG-05** «убирать фон изображения по команде из меню выделения»: в меню выделения изображения есть команда удаления фона; после неё фон (однотонный фон тестовой картинки) становится прозрачным (альфа = 0 в углах), предмет сохраняется. Результат виден второму клиенту и после перезагрузки (значит, сохранён в `media` или в параметрах объекта). Отмена возвращает исходное (наблюдение).
- **IMG-06** «показывать GIF; при большом числе объектов на экране воспроизведение начинается по наведению»: GIF загружается и показывается анимированным при малом числе объектов; при большом числе объектов на экране GIF показан статичным кадром, наведение запускает воспроизведение, уход курсора — останавливает (наблюдение). Порог «большого числа» требование не задаёт — принимаю любой разумный порог реализации, но поведение должно наблюдаться (например, при ≥ 50/100 объектах).
- **IMG-07** «загружать SVG как изображение на доску»: SVG загружается и показывается как объект изображения (с обрезкой, обводкой и т. п. как у картинки). Безопасность: SVG со `<script>` и обработчиками событий, открытый напрямую по `/api/media/{id}` (вкладкой, во фрейме, через `<img>`), не исполняет скрипт; ответ отдаётся с CSP, запрещающей скрипты, и/или `Content-Disposition`/`nosniff`.
- **Модуль `media` — доступ** (ARCHITECTURE.md 8, 12; PLAN «Тестирование»):
  - загрузка — владелец и участник по ссылке своей доски; без сессии — отказ; с сессией другой доски — отказ; посторонний пользователь досок (не владелец) в чужую доску не загружает; администратор (сессия панели) не загружает;
  - `/api/media/{id}`: владелец и участник по ссылке этой доски получают файл; без сессии — отказ; участник по ссылке другой доски — отказ; другой пользователь досок — отказ; администратор — отказ; после сброса ссылки старая cookie участника — отказ, а новая ссылка — доступ;
  - отказы для «чужой файл», «несуществующий id», «некорректный id» неразличимы (одинаковый статус и тело), по ответу нельзя понять, существует ли файл или доска;
  - после удаления доски в корзину / окончательного удаления — наблюдение (не входит в T7.1).
- **CVS-20 × изображения**: изображение, скопированное на другую доску пользователя (копировать/вставить между досками), видно на целевой доске и владельцу, и участнику по ссылке целевой доски; после сброса ссылки или удаления исходной доски — не пропадает (по модели «файл только сессии этой доски» значит, что файл должен оказаться в `media` целевой доски, как при создании из шаблона в разделе 7).
- **Архитектура**: изображение — запись `objects` с `type` и ссылкой на id файла (видно независимым WS-клиентом), документ не содержит data URL; маршрут файла — `/api/media/{id}`; клиент не обращается к `localhost`; заголовки: HTML-страницы (`/`, `/boards/{id}`, `/b/{token}`, `/login`, `/admin/*`), JSON API и `/api/media/{id}` запрещают показ во фрейме (`X-Frame-Options: DENY`/`SAMEORIGIN` или CSP `frame-ancestors 'none'`/`'self'`), а `/b/{token}/embed` — разрешает; cookie сессии `HttpOnly`, `SameSite=Lax`, без `Secure` на `http://`.
