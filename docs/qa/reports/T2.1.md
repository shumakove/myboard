# T2.1 · QA-отчёт

Требования: ACC-04, BRD-01…06; регрессия ADM-05 (сохранность досок отключённого пользователя), ACC-01…05, ADM-01…07
Коммит сценариев: см. коммит «T2.1: Зафиксировать сценарии приёмки» в `main` (до чтения handoff)

Сценарии составлены только по `REQUIREMENTS.md` (ACC-04, BRD-01…06, ADM-05, раздел 5 «Раздел доступен пользователю досок»), `ARCHITECTURE.md` (раздел 4 — маршруты `/`, `/boards/{id}`, «поиск списка досок выполняет сервер»; раздел 7 — `deleted_at`, «недавние» по `updated_at`, «чужие строки эти запросы не возвращают»; раздел 12 — список закрыт) и блоку «Тестирование» T2.1 в `PLAN.md`, до чтения handoff и кода.

Роли:

- **пользователь досок A** — владелец досок;
- **пользователь досок B** — другая учётка, не должен видеть, открывать, менять и удалять доски A ни в списке, ни прямым запросом по id;
- **администратор** — сессия панели не даёт доступа к доскам пользователей; отключает/включает A (ADM-05);
- **посторонний** — без сессии: API досок отвечает `401`, страницы `/` и `/boards/{id}` ведут на `/login`;
- **участник по ссылке** — ссылок ещё нет (T3.1); по REQUIREMENTS раздел 5 список досок ему недоступен — проверяется в T3.1.

Границы толкования (фиксирую до чтения handoff):

- BRD-04 «недавние» — по ARCHITECTURE раздел 7 порядок по `boards.updated_at` (последнее изменение). Правок документа до T4.1 нет, поэтому «изменением» в T2.1 считается создание; влияние переименования на порядок недавних — фиксация, не FAIL.
- BRD-05 — требование не называет конкретные критерии сортировки и фильтра. Проверяется, что каждый предложенный интерфейсом вариант сортировки даёт верный порядок, а каждый фильтр — верное подмножество досок; должна быть хотя бы одна сортировка (по названию или дате, в обе стороны) и хотя бы один фильтр. Фильтры по папкам и избранному — T2.2.
- BRD-06 — в T2.1 только доски; поиск папок — T2.2.
