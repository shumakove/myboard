# BUG-034 · Cookie встроенной доски принимается с Origin другой схемы

Задача: T7.3   Требование: EMB-04, Q-008 (защита от подделки), ARCHITECTURE.md раздел 5   Серьёзность: major
Коммит: 41d13ba (`dev/T7.3`)   Окружение: `acceptance/api`, стенд QA с TLS (`acceptance/tls/Caddyfile`, `PUBLIC_BASE_URL=https://192.168.0.26:8443`)

Шаги:
1. Получить cookie `myboard_embed_{id}` входом со встроенной доски.
2. Отправить запрос с этой cookie, без `Sec-Fetch-Site`, с `Origin: http://192.168.0.26:8443` (та же запись хоста и порта, другая схема).
3. То же без cookie для `POST /api/share/{token}/join {"embed": true}`.

Ожидалось (цитата): «сервер принимает её только с запросов со страницы своего сайта: по `Sec-Fetch-Site: same-origin`, а без этого заголовка — по совпадению `Origin` с `PUBLIC_BASE_URL`» (ARCHITECTURE.md, раздел 5, `dev/T7.3`). `http://…` с `https://…` не совпадает.
Фактически: сравниваются только хост и порт. Запрос принят: участник виден в `GET /api/share/{token}`, файл отдаётся, загрузка проходит, канал `/api/ws` открывается (101), поддельный вход отвечает 200 и выдаёт cookie (ожидался тот же 404, что у неверной ссылки). С другими чужими `Origin`, `null`, `Sec-Fetch-Site: cross-site`, `same-site`, `none` и без признаков отказ верный.
Условия: браузер без `Sec-Fetch-Site` и страница той же записи хоста по `http://`, то есть подмена на пути. Случай узкий, но это единственная защита от подделки, которую потребовал владелец в Q-008.
Доказательство: `acceptance/api/test_embed.py::test_emb04_q008_https_foreign_request_gets_no_session`, `…_foreign_websocket_is_closed`, `…_forged_join_is_refused_like_bad_link`, параметр «Origin http той же записи».
