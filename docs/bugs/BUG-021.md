# BUG-021 · Телефон: при сотнях учётных записей касание «Edit» в списке администратора попадает в другую строку

Задача: — (обнаружено в регрессии T6.3; код администратора T6.3 не меняет)   Требование: ADM-04, ADM-05 (UI-04)   Серьёзность: minor
Коммит: main 0d599d5   Окружение: mobile профиль Playwright (Pixel 7, touch), стек `myboard-qa` после `acceptance/api` (~830–920 учётных записей)

Шаги:
1. Создать в базе ~800+ учётных записей (например, прогнать `acceptance/api` на стеке).
2. На телефоне войти администратором, открыть `/admin/users`, прокрутить к одной из последних строк.
3. Нажать `Edit` в этой строке.

Ожидалось (ADM-04): открывается правка выбранной учётной записи.
Фактически: касание попадает в ячейку другой строки (`<td>QA User …</td>` из чужого `<tr>` перекрывает кнопку); `document.elementFromPoint` в центре кнопки возвращает чужую строку. Высота страницы ~170 000 px (адреса переносятся по 3–4 символа, строка ~430 px). На desktop и на свежем стеке ошибки нет. Не исключено, что это предел отрисовки/попадания Chromium на очень длинной странице, а не логика приложения; требования постраничного списка в REQUIREMENTS.md нет.
Доказательство: `acceptance/e2e/admin.spec.ts` «ADM-04 edit …», «ADM-05 ADM-06 …», «ADM-01 sign out …», `session-revoke.spec.ts` «ADM-04 new password …», `session-watch.spec.ts` «ACC-05 …» [mobile] — падают при ~920 учётных записях, зелёные на свежем стеке (отчёт `docs/qa/reports/T6.3.md`, проверка 2).
