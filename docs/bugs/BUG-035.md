# BUG-035 · Во фрейме чужого сайта при HTTPS файл не скачивается

Задача: T7.3   Требование: EMB-04, FIL-01, SHR-04   Серьёзность: major
Коммит: 41d13ba (`dev/T7.3`)   Окружение: desktop профиль Playwright, установленный Chrome, стенд QA с TLS (`acceptance/tls/Caddyfile`), страница другого сайта `https://172.29.144.1:9443`

Шаги:
1. Открыть внешнюю страницу с iframe `/b/{token}/embed`, ввести имя.
2. Загрузить файл `n.txt`: он появляется ярлыком и выделен.
3. Нажать `Download` на панели выделения.

Ожидалось (цитата): «встроить эту доску на внешнюю страницу через iframe так, чтобы на встроенной доске можно было работать» (EMB-04); «загружать файл на доску, показывать его ярлыком, переименовывать и скачивать» (FIL-01); те же действия у участника (SHR-04).
Фактически: скачивание отменяется (`download.failure()` = `canceled`). В журнале API тот же адрес `GET /api/media/{id}?download=n.txt` — `404`. `fetch` того же адреса из той же страницы фрейма — `200`, содержимое верное. Значит, сервер не получил или не принял cookie на запросе скачивания; что именно из двух, снаружи не видно: этот запрос браузер не показывает Playwright. Воспроизведено в двух разовых проверках и в тесте. Показ изображения, воспроизведение видео и страницы PDF в том же фрейме работают.
Доказательство: `acceptance/e2e/embed-https.spec.ts` — `EMB-04 FIL-01 FIL-02 FIL-03 IMG-01 Q-008 https: inside a frame of another site files upload, show, play and download`.
