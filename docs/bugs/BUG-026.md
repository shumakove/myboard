# BUG-026 · Комментарий участника-тёзки владельца не отмечается непрочитанным и сливается с владельцем в фильтре

Задача: T6.10   Требование: CMT-02, CMT-04   Серьёзность: minor
Коммит: 7b088df (`dev/T6.10`, код — 4bf5359)   Окружение: desktop профиль Playwright

Шаги:
1. Пользователь досок (имя учётки, например, `QA User abc`) открывает доску `/boards/{id}`.
2. Участник по ссылке входит по `/b/{token}` и вводит то же имя `QA User abc` (SHR-03 не требует уникальности имени).
3. Участник оставляет комментарий к объекту.
4. Владелец смотрит на метку ветки и в панели `Comments` — на группу `Filter by people`.

Ожидалось (цитата требования): «Система должна вести в комментарии переписку, отмечать его решённым и показывать непрочитанные» (CMT-02); «Система должна фильтровать комментарии по участникам обсуждения» (CMT-04). Комментарий другого человека — непрочитанный для владельца; фильтр различает участников обсуждения.
Фактически: у владельца метка без `data-unread`, у кнопки `Comments` нет счётчика — чужое сообщение считается своим. В `Filter by people` одна кнопка на двоих: владелец и участник неразличимы, фильтр по «владельцу» показывает и ветки участника. Причина видна снаружи: автор сообщения в `comments` — только отображаемое имя, а «своё/чужое» и фильтр определяются по нему (в handoff — известное ограничение «Участники с одинаковым именем считаются одним автором»). В обычном случае (разные имена) непрочитанные и фильтр работают.
Доказательство: `acceptance/e2e/comments.spec.ts` — «CMT-02 CMT-04 observation: a participant by link who enters the same name as the owner» (вывод: «у владельца data-unread=null; кнопок в Filter by people: 1»).
