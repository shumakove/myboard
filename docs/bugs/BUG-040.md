# BUG-040 · Враждебные страницы одного участника задерживают карточки ссылок на всех досках

Задача: T7.3   Требование: EMB-02   Серьёзность: minor
Коммит: 583ac5d (`dev/T7.3`, проверка 2)   Окружение: `acceptance/api`, стек `myboard-qa`, сайт-образец `acceptance/api/link_site.py`

Шаги:
1. Участник по ссылке, без учётной записи, отправляет 30 параллельных `POST /api/boards/{id}/link-preview` с адресом страницы из 1 МиБ символов `<` (в пределах лимита размера).
2. Через секунду другой участник запрашивает карточку обычной страницы (`/page`).

Ожидалось (цитата требования): «Система должна показывать карточку ссылки с названием и изображением страницы и открывать адрес» (EMB-02). Один участник не мешает остальным (BUG-036).
Фактически: процесс отвечает (`/api/health` не дольше 0,28 с) — остановка сервера из BUG-036 устранена. Но разбор страниц идёт по одной на весь процесс, и обычная карточка второго участника ждёт очередь: ответ через 35,4 с, все 30 страниц разобраны за 36,5 с. Одна враждебная страница — около 1,3 с очереди, ограничения частоты нет, так что один участник любой доски может держать очередь занятой сколько угодно.
Серьёзность minor: сервер, каналы и остальные функции работают, карточка в итоге появляется; задерживается только чтение страниц для карточек, и только при намеренной нагрузке. Ограничения частоты требование не задаёт — решение за владельцем (очередь на доску или участника, предел частоты, оставить как есть).
Доказательство: `acceptance/api/test_embed.py::test_emb02_bug036_thirty_hostile_pages_keep_server_responsive` (вывод `-s`: «30 страниц за 36.5 с, /api/health до 0.28 с, карточка другого участника 35.39»).
