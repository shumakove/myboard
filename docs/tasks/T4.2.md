Подготовка данных (как в T4.1):
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}`.
2. Владелец: `POST /api/login` → cookie `myboard_session`; доска `POST /api/boards {"title"}`.
3. Ссылка: `GET /api/boards/{id}/share` → `token`; участник: `POST /api/share/{token}/join {"name"}` → cookie `myboard_board_{id без дефисов}`.
4. Канал: владелец — `ws://<host>/api/ws?board={id}`, участник — `ws://<host>/api/ws?token={token}`.
5. Браузер: владелец открывает `/boards/{id}`, участник (другой браузер/контекст) — `/b/{token}` и вводит имя.

Протокол (`apps/api/app/realtime/protocol.py`, копия — `apps/web/src/realtime/messages.ts`) — к `sync = 0` из T4.1 добавлены двоичные кадры `varuint тип | varuint длина | JSON в UTF-8`:

- `awareness = 1`, клиент → сервер: состояние соединения целиком, JSON-объект `{"cursor": {x, y} | null, "camera": {x, y, zoom} | null, "following": "<peer>" | null}` (координаты доски; `camera` — центр вида и масштаб). Не объект, не JSON, `NaN`/`Infinity`, больше 4096 байт, лишние байты → закрытие `1007`.
- `awareness = 1`, сервер → остальные соединения доски (не отправителю): `{"peer": "<id>", "name": "<имя из сессии>", "state": {…}}`. Имя подставляет сервер (владелец — имя учётки, участник — имя, введённое при входе), поле `name` в состоянии клиента на него не влияет. Новое соединение сразу получает последние состояния остальных.
- `presence = 2`, сервер → все соединения доски при каждом входе/выходе: `{"self": "<id получателя>", "peers": [{"peer", "name"}, …]}` — по элементу на соединение, включая получателя. Клиентский кадр `presence` → `1007`.
- Порядок после подключения: `sync STEP1` → `awareness` уже присутствующих → `presence`.
- Присутствие не пишется в документ и `board_updates`, пропадает с соединением; при сбросе ссылки (`4403`) и отзыве доступа участник исчезает из `presence` у остальных сразу.
