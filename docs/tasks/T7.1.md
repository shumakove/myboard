## Handoff (DEV)

Коммит: см. последний коммит ветки `dev/T7.1` (код — 6ade8d6, aa31e72; карточка — следующим коммитом)
Запуск (из корня репозитория):

```sh
docker compose --project-directory deploy/compose -p <проект> down -v
docker compose --project-directory deploy/compose -p <проект> up --build
```

Переменные — из `deploy/compose/.env.example`, новых нет (`MEDIA_ROOT`, `MAX_UPLOAD_BYTES` уже обязательны). Новая миграция `0008_media` (таблица `media`) применяется при старте. Новых зависимостей нет. Изменён `deploy/compose/Caddyfile`: `Content-Security-Policy "frame-ancestors 'none'"` теперь ставится, только если у ответа нет своей политики (`?Content-Security-Policy`) — иначе Caddy затирал политику файлов media; у файлов в ней тоже есть `frame-ancestors 'none'`, `X-Frame-Options: DENY` — как раньше.

Подготовка данных (как в T6.x):
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}`.
2. Владелец: `POST /api/login` (или форма `/login`), доска — `POST /api/boards {"title"}`; открыть `/boards/{id}`.
3. Участник: `GET /api/boards/{id}/share` → `token`; открыть `/b/{token}` и ввести имя (`POST /api/share/{token}/join`).

HTTP (модуль `media`, `apps/api/app/media/`):
- `POST /api/boards/{board_id}/media?name=<имя файла>` — тело запроса — сам файл, `Content-Type` — объявленный тип (`image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/svg+xml`). Владелец и участник по ссылке этой доски. Ответ 201 `{id, name, mime, size, url: "/api/media/{id}"}`; 404 — нет сессии этой доски (так же, как несуществующая доска); 413 — больше `MAX_UPLOAD_BYTES` (файл не сохраняется); 415 — тип не из списка. Файл — `MEDIA_ROOT/{board_id}/{media_id}`, строка — в `media` (`storage_key`, `original_name`, `mime`, `byte_size`).
- `GET /api/media/{media_id}` — файл только при сессии его доски: владелец (cookie `myboard_session`) неудалённой доски или участник с cookie `myboard_board_<id>`. Без сессии, с сессией другой доски, после сброса ссылки (старая cookie), у удалённой доски — 404 с тем же телом, что у несуществующего файла. Заголовки: `Content-Type` — записанный тип, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-cache`, `Content-Disposition: inline`.
- Сообщения WebSocket не менялись: изображение — объект документа Yjs (`objects`, `type: "image"`, поля `media`, `mime`, `crop {x,y,width,height}` в долях исходника, `mask`, `flipX`, `flipY`, оформление `stroke`, `strokeWidth`, `radius`).

Известные ограничения:
- IMG-05: фон отделяется по цвету края — работает для однотонного или почти однотонного фона; сложный фотографический фон без модели сегментации не отделяется (`docs/decisions.md`, T7.1). GIF после удаления фона — PNG первого кадра.
- Изменение размера изображения за угол — как у остальных объектов (без фиксации пропорций).
- Изображение, скопированное на другую доску, показывает файл исходной доски только тем, у кого есть сессия той доски (владелец обеих досок — да, участник — нет); копирование файлов между досками — задачи шаблонов и резервной копии (T9.1, T10.1).
- Файлы удаляются с окончательным удалением доски — этой операции пока нет.
- Картинка стороны флип-карточки по-прежнему data URL в документе — перевод на `media` — отдельная задача T7.5.
