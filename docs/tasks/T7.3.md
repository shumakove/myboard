Запуск (из корня репозитория):

```sh
docker compose --project-directory deploy/compose -p <проект> down -v
docker compose --project-directory deploy/compose -p <проект> up --build
```

Миграций нет. Новая необязательная переменная `LINK_PREVIEW_ALLOWED_HOSTS` (`deploy/compose/.env.example`): хосты через запятую, чьи страницы сервер читает, хотя они во внутренней сети. Без неё страница в LAN даёт карточку без названия и картинки. Для проверки EMB-02 на своём сайте-образце укажите его хост. Зависимость `httpx2` перенесена из тестовых в зависимости процесса.

Подготовка данных (как в T7.1):
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}`.
2. Владелец: `POST /api/login` (или форма `/login`), доска — `POST /api/boards {"title"}`; открыть `/boards/{id}`.
3. Участник: `GET /api/boards/{id}/share` → `token`; открыть `/b/{token}` и ввести имя.

HTTP: `POST /api/share/{token}/join {"name","embed"}` — `embed` необязателен, по умолчанию `false`, новое поле схемы. `POST /api/boards/{board_id}/link-preview {"url"}` → `{"url","title","image"}`; `image` — `MediaOut` или `null`. Без права на доску — 404, не http(s) — 422, страница недоступна или во внутренней сети — 200 с `null`. Сообщения WebSocket не менялись. Поля документа Yjs: тип `iframe` — `src`; тип `linkcard` — `url`, `media`, название в `text`; у любого объекта — `link` или `linkObject`.

При HTTPS вход отдаёт cookie `myboard_embed_{id}`: `HttpOnly; Path=/; SameSite=None; Secure; Partitioned`; холст работает во фрейме страницы другого сайта. Эта cookie принимается только с `Sec-Fetch-Site: same-origin` или, без этого заголовка, с `Origin` из `PUBLIC_BASE_URL`; иначе запрос идёт как без cookie, а вход со встроенной доски отвечает 404. На `http://` как раньше: с того же хоста работает, на другом — `This browser does not keep your session in an embedded board.` и ссылка на доску |

### Что проверено на HTTPS, а что нет

Проверено на временном проекте `myboard-dev-https` (порт 8443, сертификат `tls internal`, `PUBLIC_BASE_URL=https://192.168.0.26:8443`, заголовки как в `deploy/compose/Caddyfile`; после проверки удалён с томами и образами). Установленный Chrome 156 headless через Playwright с `ignoreHTTPSErrors`, внешняя страница — `http://127.0.0.1:9191`, то есть другой сайт:

- `join` отдаёт cookie со всеми атрибутами; браузер сохранил её с `partitionKey: http://127.0.0.1`; обычной cookie участника нет;
- рабочий холст во фрейме, правка из фрейма видна владельцу на втором клиенте, канал `/api/ws` открыт;
- `fetch` со страницы чужого сайта не читает доску (CORS), поддельный `join` не заменил сессию;
- cookie владельца остаётся `SameSite=Lax; Secure`, `/b/{token}` отдаёт `X-Frame-Options: DENY`.

Загрузка и показ файлов (изображение, видео, PDF) внутри фрейма чужого сайта на HTTPS в браузере не проверялись: только модульным тестом с `Sec-Fetch-Site: same-origin`.

Отказы сервера при поддельных запросах (`Sec-Fetch-Site`, `Origin`, загрузка файла, чтение файла, `/api/ws`, другая доска, сброс ссылки) проверены модульными тестами, а не в браузере.

**Нельзя полностью проверить без HTTPS-профиля (T11.2)**:

- настоящий домен и доверенный сертификат: здесь сертификат внутренний, браузер запущен с отключённой проверкой;
- внешняя страница на настоящем публичном сайте по `https://`: здесь страница на `127.0.0.1` по `http://`. Запрет обращения публичной страницы к устройству локальной сети (Q-008) на настоящем сайте не проверялся;
- `deploy/compose/Caddyfile` — только профиль LAN без TLS. Публичного Caddyfile с `SITE_DOMAIN` ещё нет, поэтому заголовки фрейма и `X-Forwarded-*` этого профиля не проверялись;
- Firefox, Safari и браузеры телефонов, режим с запретом сторонних cookie: проверен только Chrome. Браузер, не принявший такую cookie, должен показать объяснение и ссылку; на HTTPS это не воспроизводилось.

Известные ограничения:
- EMB-04 на другом сайте — только при HTTPS (Q-008, вариант б). По `http://` чужой сайт доску не встроит: другого флага браузер не примет.
- Адрес файла `/api/media/{id}`, открытый из фрейма в новой вкладке, должен прийти без этой cookie и получить 404: она разделена по странице верхнего уровня. Это вывод из устройства cookie, в браузере не проверялось.
- Сайт может сам запретить показ во фрейме: объект будет пустым или с ошибкой браузера. Кнопка `Open` открывает адрес в новой вкладке. На настоящем внешнем сайте встраивание и чтение карточки не проверялись: только сайт-образец в LAN.
- Не проверено на телефоне и в мобильном профиле (MOB-06, UI-04): кнопки встроенной страницы масштабируются вместе с доской, на малом масштабе становятся меньше 44 px. Значок ссылки размером от масштаба не зависит.
- Значок ссылки лежит внутри объекта в левом верхнем углу и на очень маленьком объекте закрывает его. Значок объекта внизу слоёв могут закрыть объекты над ним.
- Частота запросов `link-preview` не ограничена.
- Приёмочные тесты с `/b/{token}/embed` писались, пока там была заглушка: см. падения выше.
- `dev/T7.3` не содержит исправление BUG-032 из `dev/T7.2`: оно ещё не в `main`. Обе ветки меняют `SelectionBar.tsx`, `BoardScene.tsx`, `scene.css` и `docs/decisions.md`, при слиянии возможны простые конфликты.
