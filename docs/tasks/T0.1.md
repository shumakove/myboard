## Handoff (DEV)

Коммит: 433ae3c (код стека); карточка и решения — следующий коммит ветки.

Запуск:

```sh
cd deploy/compose
cp .env.example .env   # заполнить: PUBLIC_BASE_URL=http://<IP в LAN>[:порт], HTTP_PORT, пароли, SECRET_KEY
docker compose -p myboard-qa down -v && docker compose -p myboard-qa up --build -d
```

IP машины на macOS: `ipconfig getifaddr en0`. При `HTTP_PORT` не 80 порт указывается и в `PUBLIC_BASE_URL`. Межсетевой экран машины должен разрешать входящие на `HTTP_PORT` из LAN.

Подготовка данных: не требуется (пользователей и досок ещё нет).

| Пункт задачи | Статус | Где смотреть |
| --- | --- | --- |
| Сервисы `caddy`, `web`, `api`, `postgres`; тома `pgdata`, `media` (+ `caddy_data`, `caddy_config`) | реализовано | `deploy/compose/compose.yaml`; том `media` смонтирован в `MEDIA_ROOT` контейнера `api` |
| Caddy на `0.0.0.0`, статика `web`, прокси `/api` и `/api/ws` в `api` | реализовано | `deploy/compose/Caddyfile`; `GET /api/health` → `{"status":"ok","service":"api-stub"}`; WS `/api/ws` — эхо текстовых сообщений |
| `.env.example` со всеми обязательными переменными | реализовано | `deploy/compose/.env.example`; без любой обязательной переменной `docker compose` отказывается запускаться с её именем в ошибке |
| Порт через `HTTP_PORT` (по умолчанию 80) | реализовано | публикация `0.0.0.0:${HTTP_PORT:-80}:80` |
| Запрет фрейма везде, кроме `/b/{token}/embed` | реализовано | `X-Frame-Options: DENY` и `Content-Security-Policy: frame-ancestors 'none'` на всех ответах (статика и API); на `/b/{token}/embed` и `/b/{token}/embed/` их нет |

Маршруты: пока любой путь, кроме `/api/*`, отдаёт `index.html` заглушки (SPA-fallback). Новые эндпоинты заглушки: `GET /api/health`, WebSocket `/api/ws` (эхо). Сообщения `sync`/`awareness`/`presence` ещё не реализованы.

Проверки (стек `myboard-dev`, `HTTP_PORT=8080`, `PUBLIC_BASE_URL=http://192.168.0.32:8080`, пустые тома):

- `docker compose -p myboard-dev config --quiet` — OK; без переменных — ошибка `required variable ADMIN_EMAIL is missing a value` и т. п.
- `caddy validate` для `Caddyfile` и `stubs/web/Caddyfile` — `Valid configuration`.
- `docker compose -p myboard-dev down -v && ... up --build -d` — все четыре сервиса запущены, `api` и `postgres` healthy.
- `curl` по LAN-IP: `/`, `/login`, `/admin/users`, `/b/abc123`, `/b/abc/embed/extra`, `/api/health`, `/api/nope` (404 JSON от api) — `X-Frame-Options: DENY` и `frame-ancestors 'none'`; `/b/abc123/embed`, `/b/abc123/embed/`, `/b/abc123/embed?x=1` — без этих заголовков.
- WebSocket: `curl` с Upgrade → `101 Switching Protocols`; клиент `websockets` на `ws://192.168.0.32:8080/api/ws` получил эхо `hello`.

Модульные тесты: неприменимо — в задаче нет кода модулей `apps/`, только конфигурация и временные заглушки.
Линтеры: ruff/mypy/tsc/ESLint/Prettier неприменимы, пока нет `apps/api` и `apps/web` (настраиваются в T0.2/T0.3).

Известные ограничения:

- `web` и `api` — временные заглушки в `deploy/compose/stubs/` (статическая страница с проверкой `/api/health` и WS; FastAPI с `/api/health` и эхо `/api/ws`). Каркасы — T0.2 и T0.3; заглушка `api` не проверяет обязательные переменные сама и не ходит в PostgreSQL (проверка переменных сейчас только на уровне `docker compose`).
- Smoke-проверка интерфейса через Claude in Chrome не выполнена: браузерное расширение заблокировало адрес `http://192.168.0.32:8080` настройками доступа к сайтам. Проверено `curl` и WebSocket-клиентом. Открытие с другого физического устройства в LAN не проверялось — публикация на `0.0.0.0` и ответы по LAN-IP подтверждены с этой машины.
- Публичный профиль HTTPS (`SITE_DOMAIN`, порт 443) — задача T11.2.
