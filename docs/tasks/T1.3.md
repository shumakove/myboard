# T1.3 · Отзыв сессий при смене пароля

Требования: ADM-04 (дополнение: «После смены пароля все действующие сессии этой учётной записи отзываются»)
Ветки: dev/T1.3, qa/T1.3

## Handoff (DEV)

Коммит: 011b964 (код); карточка — следующий коммит ветки

Запуск:

```sh
cd deploy/compose
cp .env.example .env   # заполнить, как в T0.1
docker compose -p myboard-qa down -v && docker compose -p myboard-qa up --build -d
```

Новых миграций, маршрутов и сообщений WebSocket нет; изменено поведение существующего `PATCH /api/admin/users/{user_id}`.

Подготовка данных:

- Администратор: `POST /api/admin/login {"email","password"}` → `204` + cookie `myboard_admin`.
- Пользователь досок: `POST /api/admin/users {"name","email","password"}` → `201`.
- Сессии пользователя: `POST /api/login {"email","password"}` → `204` + cookie `myboard_session` (несколько входов — несколько независимых сессий); проверка — `GET /api/session`.
- Смена пароля / имени / почты: `PATCH /api/admin/users/{id}` с `password` / `name` / `email`; в интерфейсе — Edit на `/admin/users`.

| Требование | Статус | Где смотреть (маршрут, эндпоинт) |
| --- | --- | --- |
| ADM-04: смена пароля отзывает все действующие сессии учётки | реализовано | `PATCH /api/admin/users/{id}` с полем `password` → `200`; все ранее выданные cookie `myboard_session` этого пользователя: `GET /api/session` → `200 {"authenticated":false,…}`, маршруты с `require_user` → `401`; открытая вкладка `/` при следующей загрузке уходит на `/login`. Вход с новым паролем → `204`, новая сессия действует; со старым → `401`. Любое присутствие `password` в `PATCH` считается сменой, даже при том же значении |
| ADM-04: смена только имени или почты сессии не отзывает | реализовано | `PATCH` с `name` и/или `email` (без `password`) → `200`, выданные сессии продолжают действовать (`/api/session` показывает новые имя/почту) |
| Границы | реализовано | Сессии других пользователей и сессия администратора, выполнившего правку, не затрагиваются. `PATCH` с `password` и занятой почтой → `409`: не меняются ни пароль, ни сессии |

Smoke (стек `myboard-dev`, `PUBLIC_BASE_URL=http://192.168.0.32:8080`, пустые тома):

- `curl`: две сессии Alice; `PATCH` имени, затем почты → обе сессии `authenticated:true` с новыми данными; `PATCH` пароля → обе `authenticated:false`, сессия администратора жива; старый пароль → `401`, новый → `204`, новая сессия действует; `PATCH {email: занятая, password}` → `409`, текущая сессия жива.

Ввод пароля в браузере DEV не выполнял (адрес — LAN, не локальный хост); переход отозванной вкладки на `/login` — существующее поведение `BoardsPage` при `authenticated:false` (Vitest `BoardsPage.test.tsx`, T1.2).

Решения: `docs/decisions.md`, раздел «T1.3» (что считается сменой пароля, одна транзакция, порядок DELETE до правки полей, реакция открытой вкладки).

Известные ограничения:

- Открытая вкладка узнаёт об отзыве при следующем обращении к API (загрузка, переход); опроса сессии нет. На `/` до T2.1 других запросов, кроме `GET /api/session` при загрузке, нет.
- Попутно исправлено: `PATCH` с занятой почтой вместе с `disabled: true` раньше давал `500` вместо `409` (autoflush при `DELETE` сессий, T1.1); теперь `409`.
