# T1.2 · Вход пользователя досок

Требования: ACC-01, ACC-02, ACC-03 (и перенесённые из T1.1 проверки ADM-01, ADM-04, ADM-05, ADM-06 через вход пользователя)

## Handoff (DEV)

Коммит: a063058 (код); карточка — следующий коммит ветки

Запуск:

```sh
cd deploy/compose
cp .env.example .env   # заполнить, как в T0.1
docker compose -p myboard-qa down -v && docker compose -p myboard-qa up --build -d
```

Новых миграций нет (таблицы `users` и `sessions` — из T1.1).

Подготовка данных:

- Вход администратора: `POST /api/admin/login {"email","password"}` → `204` + cookie `myboard_admin`.
- Пользователь досок: `POST /api/admin/users {"name","email","password"}` с cookie администратора → `201`.
- Вход пользователя: `POST /api/login {"email","password"}` → `204` + cookie `myboard_session`; в интерфейсе — `/login`.
- Смена пароля/почты, отключение, включение — `PATCH /api/admin/users/{id}` (`password`, `email`, `disabled`).

| Требование | Статус | Где смотреть (маршрут, эндпоинт) |
| --- | --- | --- |
| ACC-01 | реализовано | `/login` (форма Email/Password, кнопка Sign in) → после входа `/`; `POST /api/login` → `204` + cookie `myboard_session`; `GET /api/session` → `200 {"authenticated":true,"name","email"}`. Почта без учёта регистра и пробелов по краям |
| ACC-02 | реализовано | Неизвестная почта, неверный пароль, отключённая учётка, почта/пароль администратора → одинаковый `401 {"detail":"Invalid email or password"}` без cookie; в интерфейсе — «Invalid email or password.». 10 неудачных попыток за 60 с с одного адреса → `429 {"detail":"Too many sign-in attempts, try again later"}` + `Retry-After`, в том числе с верным паролем; счётчик отдельный от входа в панель |
| ACC-03 | реализовано | Cookie `myboard_session` с `Max-Age=34560000` (400 дней), продлевается каждым `GET /api/session`; в базе сессия бессрочна. `/login` у вошедшего сразу ведёт на `/`; `/` без сессии ведёт на `/login`. Выход: кнопка Sign out на `/`, `POST /api/logout` → `204`, cookie стёрта, скопированная старая cookie больше не действует |
| ADM-04 (регрессия T1.1) | реализовано | После `PATCH` пароля и почты вход с новыми данными — `204`, со старым паролем или старой почтой — `401` |
| ADM-05 (регрессия T1.1) | реализовано | Отключённый пользователь получает тот же `401`; уже выданная сессия: `GET /api/session` → `authenticated:false` |
| ADM-06 (регрессия T1.1) | реализовано | После `{"disabled":false}` вход с прежним паролем — `204` |
| ADM-01 (регрессия T1.1) | реализовано | Сессия пользователя досок не открывает `/api/admin/*` (`401`, `/api/admin/session` → `authenticated:false`); cookie администратора не принимается как сессия пользователя |
| Cookie | реализовано | `myboard_session=…; HttpOnly; Max-Age=34560000; Path=/; SameSite=lax`, без `Secure` при `http://`, с `Secure` при `https://`; значение — 32 случайных байта (base64url), в базе — SHA-256 |

Smoke (стек `myboard-dev`, `PUBLIC_BASE_URL=http://192.168.0.32:8080`, пустые тома):

- `curl`: вход пользователя → `204` и cookie с флагами выше; `GET /api/session` → Alice; неверный пароль и неизвестная почта → одинаковый `401`; после отключения — тот же `401`, старая сессия → `authenticated:false`; после включения со сменой пароля старый пароль → `401`, новый → `204`; cookie пользователя на `/api/admin/users` → `401`; выход → cookie стёрта, `authenticated:false`; серия неверных попыток → `429` с `Retry-After`.
- `/api/openapi.json` стека совпадает с `apps/web/openapi.json` байт в байт; `src/api/schema.d.ts` сгенерирован из него. В статике `web` нет `localhost`, `127.0.0.1`, LAN-адреса.
- Браузер (Claude in Chrome): `/` без сессии → `/login` с формой Email/Password, запросы только `GET /api/session` на адрес страницы (`200`), консоль без ошибок. Вход с паролем в браузере DEV не выполнял (адрес — LAN, не локальный хост); поток входа, перенаправлений и выхода в интерфейсе покрыт Vitest, серверная часть — `curl` и pytest.

Решения: `docs/decisions.md`, раздел «T1.2» (маршруты `/api/login|logout|session`, cookie `myboard_session` с `Max-Age` 400 дней и продлением, одинаковый отказ, отдельный лимит, перенаправления `/` ↔ `/login`).

Известные ограничения:

- Список досок на `/` — T2.1 (ACC-04); сейчас на `/` имя пользователя и Sign out.
- Остальные страницы пользователя досок (`/boards/{id}`, `/templates`, `/t/{token}`) пока заглушки без проверки входа — их содержимое и доступ появляются в T2.1 и T9.1.
- Лимит попыток — как в T1.1: на Docker Desktop (macOS) все клиенты из LAN видны с адреса шлюза VM, поэтому лимит общий для стенда; окно — 60 с.
- Браузеры ограничивают срок cookie 400 днями: пользователь, не открывавший сайт дольше, войдёт заново (каждый визит продлевает срок).
