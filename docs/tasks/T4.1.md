
Переменные — из `deploy/compose/.env.example`. Новая миграция `0006` (таблица `board_updates`) применяется при старте API. Новые зависимости: `pycrdt` (api), `yjs`, `lib0` (web).

Подготовка данных:
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}` — пользователи A и B.
2. Владелец: `POST /api/login` → cookie `myboard_session`; доска `POST /api/boards {"title"}`.
3. Ссылка: `GET /api/boards/{id}/share` → `token`; участник: `POST /api/share/{token}/join {"name"}` → cookie `myboard_board_{id без дефисов}`.
4. Канал: владелец — `ws://<host>/api/ws?board={id}` с cookie `myboard_session`; участник — `ws://<host>/api/ws?token={token}` с cookie своей доски. Клиент WebSocket: любой y-protocols-совместимый (в Python — `pycrdt` + `websockets`, см. протокол ниже).

Протокол (`apps/api/app/realtime/protocol.py`, копия — `apps/web/src/realtime/messages.ts`): двоичные кадры y-protocols, `varuint тип | varuint подтип | varuint длина | байты`; тип `sync = 0`; подтипы `0 STEP1` (вектор версии), `1 STEP2` (недостающие обновления; на пустой вектор `00` — полный снимок), `2 UPDATE`. После подключения сервер первым шлёт `STEP1`; на `STEP1` клиента отвечает `STEP2`; `STEP2` и `UPDATE` клиента применяет к своей копии (`pycrdt`), пишет в `board_updates`, двигает `boards.updated_at` и только затем рассылает остальным соединениям доски как `UPDATE` (отправителю — нет). Коды закрытия: `1007` — повреждённый кадр/обновление; `4403` — доступ отозван во время работы; отказ в подключении — HTTP `403` на рукопожатие.

Smoke (стек `myboard-dev` с нуля, `http://192.168.0.32:8080`):
- WebSocket-клиенты (`pycrdt` + `websockets` через Caddy): отказ `403` без сессии, для чужого пользователя, участнику без имени, неизвестному токену, с чужим `Origin`; владелец и участник одновременно правят один объект и текст — у обоих `{'color': 'red', 'x': 5, 'text': 'Hi Hello world'}`; мусорное обновление закрывает отправителя кодом `1007`, владелец продолжает, поздний клиент получает то же состояние; сброс ссылки закрывает открытый канал участника кодом `4403`, старый токен и старая cookie на новом — `403`; `updated_at` доски сдвинулся; после `docker compose restart api` в `board_updates` 3 записи, ошибок в логах нет.
- Браузер (Claude in Chrome): владелец на `http://localhost:8080/boards/{id}` — «Live: …»; участник в другом origin `http://192.168.0.32:8080/b/{token}` вводит имя — «You joined as Guest Dana.» и «Live: …»; владелец сбрасывает ссылку — вкладка участника сама показывает «Board unavailable / This link is not available.»; остановка `api` — у владельца «Offline. …», после запуска — снова «Live: …» без перезагрузки. Ошибок консоли нет. В собранной статике нет строки `localhost`.

Решения: `docs/decisions.md`, раздел «2026-10-01 · T4.1 · Синхронизация документа» (pycrdt/yjs/lib0 вместо y-websocket, двоичный протокол y-protocols, параметры `board`/`token`, проверка Origin, закрытие при сбросе и перепроверка доступа каждые 5 с, журнал `board_updates`).

Известные ограничения:
- Холста нет (T5.*): в интерфейсе видно только состояние связи; правки документа в браузере проверяются модульными тестами провайдера, совместная правка снаружи — WebSocket-клиентами.
- Снимки, сжатие журнала и выгрузка недостающих обновлений по журналу — T4.3: сейчас при первом подключении к доске документ собирается из всего журнала.
- `awareness`/`presence` (T4.2) пока не принимаются: такой кадр закрывает соединение как незнакомый (`1007`).
- Выход, смена пароля, отключение учётки и удаление доски закрывают уже открытый канал не мгновенно, а при ближайшей перепроверке (до 5 с); сброс ссылки — сразу.
- Q-001 (сессия участника привязана к `board_id`) не менялся.
