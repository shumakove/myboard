# T1.4 · Выход вкладки при отзыве сессии

Требования: ACC-05
Ветки: dev/T1.4, qa/T1.4

## Handoff (DEV)

Коммит: см. последний коммит ветки `dev/T1.4` (код и карточка — один коммит)

Запуск:

```sh
cd deploy/compose
cp .env.example .env   # заполнить, как в T0.1
docker compose -p myboard-qa down -v && docker compose -p myboard-qa up --build -d
```

Новых миграций, эндпоинтов и сообщений WebSocket нет; сервер не менялся. Изменён только клиент `apps/web`.

Подготовка данных (как в T1.3):

- Администратор: `POST /api/admin/login {"email","password"}` → `204` + cookie `myboard_admin`.
- Пользователь досок: `POST /api/admin/users {"name","email","password"}` → `201`; вход на `/login` (или `POST /api/login`).
- Отзыв: `PATCH /api/admin/users/{id}` с `password` или `{"disabled": true}`; только `name`/`email` — не отзыв. В интерфейсе — Edit на `/admin/users`.

| Требование | Статус | Где смотреть (маршрут, эндпоинт) |
| --- | --- | --- |
| ACC-05: отзыв сессии (смена пароля, отключение) → вкладка на `/login` ≤ 5 с без действий | реализовано | Открытые `/`, `/boards/{id}`, `/templates`: пока вкладка видима, `GET /api/session` каждые 2 с; при `authenticated:false` — `replace` на `/login` (форма Sign in). Скрытая вкладка не опрашивает, при возврате на вкладку (`visibilitychange`, `focus`) проверяет сразу |
| ACC-05: ответ `401` на любой запрос API пользователя → сразу `/login` | реализовано | Любой `401`, кроме `POST /api/login` и `/api/admin/*`. Сейчас маршрутов с `require_user`, кроме уже существующих, нет — поведение закреплено модульными тестами и сработает для запросов досок (T2.1) |
| ACC-05: смена только имени или почты не выбивает | реализовано | Вкладка остаётся на месте, при следующей проверке показывает новое имя |
| Границы | реализовано | Сбой сети при проверке не выбивает; на `/login` опроса нет; после ухода на `/login` опрос прекращается. `/t/{token}` не охвачен (см. `docs/decisions.md`, T1.4) |

Smoke (стек `myboard-dev`, `PUBLIC_BASE_URL=http://192.168.0.32:8080`, пустые тома):

- `curl`: пользователь Alice; `PATCH` имени → сессия `authenticated:true` с новым именем; `PATCH` пароля → `authenticated:false`; вход с новым паролем → `204`; `PATCH {"disabled":true}` → `authenticated:false`. В собранном бандле есть обработчик `visibilitychange`.
- Браузер (Claude in Chrome, LAN-адрес): `/boards/42` без сессии → `/login`; на `/login` за 5 с нет повторных запросов `/api/session`; ошибок в консоли нет. Вход с паролем в браузере DEV не выполнял (на LAN-адресе пароль не вводится, а к `localhost` расширение не подключилось), поэтому переход открытой вкладки после отзыва в браузере проверен только модульными тестами.

Решения: `docs/decisions.md`, раздел «T1.4» (опрос 2 с при видимой вкладке, реакция на `401`, какие маршруты охвачены).

Известные ограничения:

- Скрытая (фоновая) вкладка не опрашивает сервер: уходит на `/login` сразу при возврате на неё.
- `/t/{token}` не охвачен — страница-заглушка, поведение без сессии определит её задача.
