Подготовка данных (как в T7.1):
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}`.
2. Владелец: `POST /api/login` (или форма `/login`), доска — `POST /api/boards {"title"}`; открыть `/boards/{id}`.
3. Участник: `GET /api/boards/{id}/share` → `token`; открыть `/b/{token}` и ввести имя (`POST /api/share/{token}/join`).

HTTP (модуль `media`, `apps/api/app/media/`; права и ответы 404/413 — как в T7.1):
- `POST /api/boards/{board_id}/media?name=<имя>` — к типам изображений добавлены `application/pdf`; `video/mp4`, `video/x-m4v`, `video/quicktime`, `video/webm`; `audio/mpeg`, `audio/mp3`, `audio/mp4`, `audio/m4a`, `audio/x-m4a`, `audio/wav`, `audio/x-wav`, `audio/wave`, `audio/vnd.wave`, `audio/webm`.
- `POST /api/boards/{board_id}/media?name=<имя>&kind=file` — файл любого содержимого для ярлыка, только с `Content-Type: application/octet-stream`; другой тип — 415. Без `kind=file` тип `application/octet-stream` — 415, как раньше.
- `GET /api/media/{media_id}` — отвечает на `Range` (206, `Accept-Ranges: bytes`).
- `GET /api/media/{media_id}?download=<имя>` — `Content-Disposition: attachment` с этим именем.
- Сообщения WebSocket не менялись. Объекты документа Yjs: `type` — `file`, `pdf`, `video`, `audio`; поля `media`, `mime`, `name`, `size`; у PDF `pages`; у извлечённой страницы `page` (с 1).

Интерфейс: `All tools` → `File` (клавиша Y; закрепляется на панели, CVS-24) открывает выбор файла (`input` «Upload file», можно несколько). Новый объект — в центре вида, выделен. Селекторы объектов: `[data-object-id][data-type="file|pdf|video|audio"]`.

Известные ограничения:
- Какие кодеки играют, решает браузер. Bundled Chromium из Playwright не содержит H.264 и AAC: mp4, m4v, mov, m4a в нём покажут «Video/Audio can't be played». Smoke выполнен в установленном Chrome (`channel: 'chrome'`). То же относится к `.mov` с HEVC.
- Playwright + Chrome headless: выбор файла иногда не приходит событием `filechooser` (замер: клавиша Y 2 из 20, Image по клавише G 7 из 20), хотя обработчик сработал, `input.click()` вызван и активация пользователя есть. У Image, принятого в T7.1, то же самое, поэтому считаю это особенностью инструмента, но причину до конца не установил. В реальном браузере с человеком не проверялось. Надёжнее `setInputFiles` на `input` «Upload file».
- PDF: без данных pdf.js для CJK-шрифтов без встраивания и изображений JPX такие элементы могут не отрисоваться; страница рисуется с большей стороной 1400 px и при сильном приближении теряет чёткость. В диалоге извлечения — номера страниц без миниатюр. Рамка всех страниц — по пропорциям первой, страница другого формата вписывается в рамку.
- Панель плеера и страниц масштабируется вместе с доской, на малом масштабе её элементы становятся меньше 44 px (UI-04 выполняется при масштабе 100 %).
- Сообщения вставки с другой доски по-прежнему говорят «images» (`Copying images…`), хотя копируются и файлы этой задачи: текст оставлен, на него могут опираться приёмочные тесты T7.1.
- Файлы удаляются с окончательным удалением доски — этой операции пока нет (как в T7.1). Квот нет.
