## Handoff (DEV)

Коммит: 63f153a (карточка — следующим коммитом ветки)
Запуск (из корня репозитория):

```sh
docker compose --project-directory deploy/compose -p <проект> down -v
docker compose --project-directory deploy/compose -p <проект> up --build
```

Переменные — из `deploy/compose/.env.example`, новых нет. Сервер, миграции, HTTP-маршруты и сообщения WebSocket не менялись: всё — в документе Yjs (`objects`). Новых зависимостей нет.

Подготовка данных (как в T6.1):
1. Администратор: `POST /api/admin/login`, `POST /api/admin/users {"name","email","password"}`.
2. Владелец: `POST /api/login` (или форма `/login`), доска — `POST /api/boards {"title"}`; открыть `/boards/{id}`.
3. Участник: `GET /api/boards/{id}/share` → `token`; открыть `/b/{token}` и ввести имя.
4. Стикер — инструмент `Sticky note` (клавиша N, закреплён); стопка — инструмент `Sticky stack` (клавиша K, в полном списке `All tools`, по умолчанию не закреплён).

Модель данных стикера (`type: "sticky"`): `text` — `Y.Text` с атрибутами Quill (как у текста T6.1: начертание, ссылки, заголовки, списки); `fill` — цвет; `fontSize` — число или `"auto"` (по умолчанию `"auto"`); `tags` — `Y.Array<string>` без «#» (у нового стикера пустой массив создаётся сразу); `showAuthor` — `false`, если имя автора скрыто (нет поля — показано). Стопка (`type: "stack"`): `fill`, `tags` (`Y.Array<string>`), рамка 200×200, текст пустой.

### Исправления

Коммит: 20afafa (карточка — следующим коммитом ветки). Решения владельца 2026-10-12: BUG-018 и BUG-017 чинятся в T6.2; показ автора по умолчанию и Tab в стикере (STK-04) — без изменений. Сервер: HTTP-маршруты, миграции и сообщения WebSocket не менялись; новых переменных и зависимостей нет.

- **BUG-018 (major, COL-01, TXT-06)** — правки, отправленные браузером перед перезагрузкой, терялись на сервере.
  - Причина (сервер, `realtime`): Uvicorn (`websockets-sansio`) после каждого принятого кадра приостанавливает чтение сокета, пока приложение не заберёт кадр; цикл соединения забирал следующий кадр только после применения и записи предыдущего в базу (одна транзакция на правку). Под нагрузкой запись медленнее набора, и непрочитанные кадры копились в буфере ядра. При перезагрузке вкладки соединение за Caddy рвётся без кадра закрытия, перезагруженная вкладка входит на доску, сервер пишет присутствие в оборванное соединение — ошибка записи закрывает транспорт, и всё непрочитанное из буфера пропадает навсегда (а при мягком закрытии — доходит с опозданием на секунды). Замер на стенде до исправления: браузер отправил 58 кадров, сервер получил 40, закрытие — 1005 (обрыв), ни одной ошибки в журнале.
  - Исправление: сокет вычитывает отдельная задача сразу по приходу кадров в очередь соединения (`app/realtime/inbox.py`, `router._read`); кадры применяются из очереди по порядку. Правки, накопившиеся в очереди подряд, применяются, пишутся в `board_updates` одной транзакцией (`store.append` принимает список) и только потом рассылаются (`BoardRoom.apply`) — порядок «применить → записать → разослать» сохранён. Повреждённое обновление в пачке: принятые до него записываются и рассылаются, соединение отправителя закрывается 1007.
  - Тесты: `test_bug018_edits_sent_before_connection_drop_are_kept_under_load` — настоящий Uvicorn, запись в базу замедлена (нагрузка), 40 правок по одной, обрыв TCP (RST), вход перезагруженной вкладки; до исправления падает (macOS — 27–31 из 40, Linux в контейнере — 34–35 из 40), после — проходит на обеих; `test_edits_before_corrupted_frame_are_kept_and_delivered`.
  - Проверка на стенде `myboard-dev` копией e2e QA (`qa/T6.2` @ 5491514, desktop): «TXT-06 BUG-018 …» и «TXT-06 link to an object that was deleted…» при `--workers=6 --repeat-each=6` — 12 passed (до исправления — 6 из 6 падали), при `--workers=8 --repeat-each=8` — 16 passed; ошибок в журнале api нет.

#### Исправление 2 (BUG-018, «Проверка 2»)

Коммит: 3b1eeb6 (карточка — следующим коммитом ветки). HTTP-маршруты, миграции, сообщения WebSocket, переменные и зависимости не менялись.

- **Корневая причина пустой доски** (0 строк `board_updates`, снимок 2 байта, `updated_at` сдвинут) — сочетание двух дефектов:
  1. Клиент (`realtime/boardConnection.ts`) молча отбрасывал свои правки, сделанные, пока сокет ещё открывается (`readyState` не `OPEN`), рассчитывая, что их дошлёт ответ на вектор сервера (`STEP2`). Под нагрузкой сервер присылает вектор через секунды (загрузка доски под общей блокировкой хаба), вкладку перезагружают раньше — начало правки (создание объекта `Text`) не уходит никогда, а набранное после открытия сокета уходит инкрементами, зависящими от этого начала.
  2. Сервер принимал такие инкременты: Yjs держит их отложенными (в документ они не входят), сервер записывал их в `board_updates` (отсюда сдвиг `updated_at`). При выгрузке доски сжатие писало снимок `get_update()` — без отложенных структур, т. е. пустой документ (2 байта), — и отрезало журнал до последнего номера, удаляя эти строки. Да, снимок пустого документа отрезал журнал с правками: проверено в pycrdt — документ с одним отложенным обновлением отдаёт `b"\x00\x00"`.
  Гипотеза QA о чтении сокета тоже подтвердилась отдельно: до `hub.join` сокет не читался, Uvicorn ставит чтение на паузу после первого кадра, и ответ сервера (`STEP1`) в уже оборванное соединение (RST) стирал непрочитанные кадры из буфера ядра.
- **Исправления:**
  - клиент: правки, сделанные без открытого сокета, копятся (`Y.mergeUpdates`) и уходят кадром `update` сразу после `STEP1` при открытии, не дожидаясь вектора сервера; повтор с последующим `STEP2` Yjs игнорирует;
  - сервер, `router.py`: задача чтения сокета стартует сразу после `accept`, до загрузки доски (`hub.join`); обработка — в `_serve`;
  - сервер, `room.py`/`store.py`: сжатие оставляет в журнале строки, структур которых ещё нет в документе (разница обновления и вектора версии документа не пуста, `_has_unapplied`); когда недостающая правка доезжает, следующее сжатие их отрезает. Если отрезать нечего, новый снимок не пишется.
- **Тесты (падают на коде до исправления):** `test_bug018_edit_waiting_for_missing_earlier_edit_survives_compaction` (отложенная правка переживает сжатие и собирается, когда доезжает начало), `test_bug018_edits_sent_while_board_is_loading_are_kept_after_drop` (настоящий Uvicorn, загрузка доски замедлена на 1 с, 30 правок и RST — до исправления не сохранялось ничего); клиент — «BUG-018: правки, сделанные до открытия соединения, уходят сразу после открытия, без ответа сервера» (`boardConnection.test.ts`).
