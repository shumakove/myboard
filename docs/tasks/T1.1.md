Подготовка данных:

- Администратор создаётся при старте на пустой таблице `admins` из `ADMIN_EMAIL`/`ADMIN_PASSWORD` (почта приводится к нижнему регистру). Смена переменных после этого ни на что не влияет — нужен `down -v`.
- Вход администратора: `POST /api/admin/login {"email","password"}` → `204` + cookie `myboard_admin`.
- Пользователь досок: `POST /api/admin/users {"name","email","password"}` с cookie администратора → `201`.
- Входа пользователя досок (`/login`) ещё нет — это T1.2. Поэтому ADM-04 «новый пароль работает, старый — нет» и ADM-05/06 «не входит / снова входит» наблюдаемы через вход пользователя только после T1.2; сейчас проверяемы: хэш пароля меняется (модульные тесты сверяют его с новым и старым паролем), флаг `disabled` в списке, отзыв сессий пользователя при отключении.

| ADM-04 | реализовано | `PATCH /api/admin/users/{id}` с любыми из `name`, `email`, `password` → `200`; кнопка Edit в строке (поле New password пустое — пароль не меняется). Неизвестный id → `404`, лишние поля → `422` |

| Cookie | реализовано | `myboard_admin`: `HttpOnly; Path=/; SameSite=lax`, без `Secure` при `http://`; `document.cookie` пуст. Значение — 32 случайных байта (base64url), в базе — SHA-256 |
| Частота входа | реализовано | 10 неудачных попыток за 60 с с одного адреса → `429 {"detail":"Too many sign-in attempts, try again later"}`, заголовок `Retry-After` (с), пока окно не освободится, даже с верным паролем |

Smoke (стек `myboard-dev`, `PUBLIC_BASE_URL=http://192.168.0.32:8080`, пустые тома):

- `curl`: анонимный `GET /api/admin/session` → `{"authenticated":false,"email":null}`; `GET /api/admin/users` → 401; вход → 204 и cookie с флагами выше; создание → 201 (почта в нижнем регистре); повтор почты в другом регистре → 409; вход пользователя в панель → 401 с тем же текстом; отключение/включение/переименование → 200; 10 неудачных входов → затем 429 с `Retry-After: 60`; выход → cookie стёрта, старая cookie → 401.
- Браузер: Claude in Chrome по `http://192.168.0.32:8080` — `/admin` → `/admin/users` (приглашение войти), ссылка Sign in → форма входа, консоль и сеть без ошибок. Сценарии с паролем администратора — Playwright (desktop и телефон 390×844 с touch): неверный пароль → Invalid email or password.; вход → `/admin/users`; создание, повтор почты → Email is already in use.; правка имени и пароля; Disable/Enable; `document.cookie` пуст; Sign out → `/admin/login`; горизонтальной прокрутки на телефоне нет; все запросы — на адрес страницы; кроме намеренных 401/409 ошибок в консоли нет.
- OpenAPI-снимок `apps/web/openapi.json` совпадает с `/api/openapi.json` стека; `src/api/schema.d.ts` сгенерирован из него. В сборке `dist` нет `localhost`, `127.0.0.1`, `0.0.0.0`, LAN-адреса.

Решения: `docs/decisions.md`, раздел «T1.1» (argon2-cffi, хэш сессии в базе, cookie `myboard_admin`, нормализация почты, лимит 10/60 с в памяти, `/admin` → `/admin/users`, `GET /api/admin/session` с ответом 200, `@testing-library/user-event`).

Известные ограничения:

- Вход пользователя досок и его сессии — T1.2; ADM-05/ADM-06 через вход пользователя и «новый пароль работает, старый — нет» проверяются вместе с T1.2, сохранность досок отключённого — после T2.1.
- На Docker Desktop (macOS) Caddy видит все подключения из LAN с адреса шлюза VM (`192.168.65.1`), поэтому лимит попыток общий для всех клиентов стенда: после проверки лимита вход в панель с любого клиента закрыт до 60 с. На Linux-хосте адрес клиента настоящий.
- Сессия администратора живёт до выхода или закрытия браузера (cookie без `Max-Age`); срок в требованиях не задан.
- Администратор один; управление администраторами в требования не входит.
