## Handoff (DEV)

Коммит: см. последний коммит ветки `dev/T3.1`
Запуск (из корня репозитория):

```sh
docker compose --project-directory deploy/compose -p <проект> down -v
docker compose --project-directory deploy/compose -p <проект> up --build
```

Переменные — из `deploy/compose/.env.example`. Новая миграция `0005` (столбцы `boards.share_token` (уникальный), `boards.share_token_revoked_at`, `sessions.board_id` → `boards.id`, `sessions.display_name`) применяется при старте API.

Подготовка данных:
1. Администратор: `POST /api/admin/login`, затем `POST /api/admin/users {"name","email","password"}` — пользователь A (и B для проверки изоляции).
2. Пользователь: `POST /api/login` или форма `/login`.
3. Доска: New board на `/` или `POST /api/boards {"title"}`.
4. Ссылка: на странице доски `/boards/{id}` кнопка Share → диалог Share board (поле `Board link`, кнопки Copy link, Reset link, Close) или `GET /api/boards/{id}/share`.
5. Участник: открыть `url` из ссылки в браузере без сессии пользователя (другой профиль/контекст), ввести имя (поле Your name, кнопка Join board) или `POST /api/share/{token}/join {"name"}`.

API: `GET /api/boards/{board_id}/share` → `200 ShareLink {token, url}`; токен выдаётся при первом запросе и не меняется до сброса; чужая/удалённая/несуществующая доска — `404 {"detail":"Board not found"}`, без сессии пользователя — `401` |
| SHR-02 | реализовано | `/b/{token}`: после ввода имени — «You joined as <имя>.» (холст появится в T4.1/T5.*). | SHR-03 | реализовано | `/b/{token}` без сессии этой доски: «Enter your name to join the board.», поле Your name, кнопка Join board; пустое (из пробелов) или длиннее 200 символов имя — `422`. Повторное открытие той же доски тем же браузером имя не спрашивает; повторный `join` заменяет имя |
| SHR-05 | реализовано | Несуществующий, отозванный, слишком длинный токен и токен удалённой доски — одинаково `404 {"detail":"Link is not available"}` на `GET /api/share/{token}` и `POST /api/share/{token}/join`; страница `/b/{token}` — «Board unavailable / This link is not available.». `/boards/{id}` и `/api/boards/{id}` без сессии владельца — `401` / переход на `/login` |
| SHR-06 | реализовано | В диалоге Share: Reset link → подтверждение в диалоге («Reset the link? …», кнопки Reset / Cancel, без `window.confirm`) → новая ссылка в поле и `status` «New link created. The previous link no longer works.». API: `POST /api/boards/{board_id}/share/reset` → `200 ShareLink` с новым токеном; прежний токен — `404 Link is not available`; все гостевые сессии доски удаляются — выданная по старой ссылке cookie на новой ссылке даёт `participant: null`. Сессия владельца и гости других досок не затрагиваются |
| Фрейм | без изменений | `/b/{token}/embed` отдаётся без `X-Frame-Options`/`frame-ancestors` (Caddy, T0.1); остальные страницы — `X-Frame-Options: DENY`, `frame-ancestors 'none'`. Содержимое embed — T7.3 |

Новые эндпоинты: `GET /api/boards/{board_id}/share`, `POST /api/boards/{board_id}/share/reset`, `GET /api/share/{token}`, `POST /api/share/{token}/join`. Smoke (стек `myboard-dev` с нуля, `http://192.168.0.32:8080`):
- `curl`: ссылка из `PUBLIC_BASE_URL`, повторный запрос — тот же токен, без сессии `401`; вход по ссылке без учётки — `participant: null`, после `join` — имя и cookie `HttpOnly; SameSite=lax` без `Secure`; гость на `/api/boards`, `/api/boards/{id}` своей и другой доски — `401`; в списке пользователей администратора гостя нет; неизвестный и отозванный токен — одинаковые `404 {"detail":"Link is not available"}`; после сброса старая cookie на новой ссылке — `participant: null`, новый `join` работает; `/b/{token}` — `X-Frame-Options: DENY`, `/b/{token}/embed` — без запрета фрейма. `apps/web/openapi.json` совпадает с `/api/openapi.json` стека байт в байт; `openapi-typescript` из него даёт `src/api/schema.d.ts` без отличий.
- Браузер (Claude in Chrome): владелец (вход на `http://localhost:8080`) открыл доску → Share — в поле ссылка `http://192.168.0.32:8080/b/…`; Reset link → подтверждение в диалоге → новая ссылка и сообщение. Участник в другом origin (`http://192.168.0.32:8080`, без сессии пользователя): `/b/{token}` → форма имени → «You joined as Guest Dana.», cookie недоступна из JS; `/` уводит на `/login`; после сброса владельцем старая ссылка — «Board unavailable / This link is not available.», несуществующий токен — тот же текст. Ошибок консоли нет, запросы только на origin страницы, горизонтальной прокрутки нет.

Решения: `docs/decisions.md`, раздел «2026-10-01 · T3.1 · Ссылка на доску и вход по ссылке» (токен при первом запросе, отдельная cookie на доску, сброс удаляет гостевые сессии, копирование через `execCommand` по http). Новых библиотек нет.

Известные ограничения:
- Проверка гостевой сессии и отозванной ссылки для WebSocket `/api/ws` — в T4.1: канала в T3.1 ещё нет. По HTTP отзыв проверен (см. SHR-06).
- Холста на `/b/{token}` пока нет (T4.1, T5.*) — страница показывает название и имя участника; права участника на холсте (SHR-04) — T4.1/T11.2.
- Копирование кнопкой Copy link в smoke проверено только синтетическим кликом (без жеста пользователя браузер копирование запрещает, показан запасной текст «Copy failed…»): расширение Claude in Chrome в этом запуске не делало снимков и кликов по координатам. Пути Clipboard API и `execCommand` покрыты модульными тестами `copyText.test.ts`, `ShareDialog.test.tsx`.
- Открытая вкладка участника не узнаёт о сбросе сама — отказ видит при следующем обращении (перезагрузка); мгновенное отключение — с каналом WebSocket (T4.1).
